# 업로드 리플레이 경기 흐름 재생

리플레이 분석실에서 JSON을 선택하고 기존 분석을 실행하면 경기 흐름 재생 패널을 함께 표시한다. 이 패널은 파일의 라운드·처치·폭탄 기록만으로 기기 안에서 작동한다. 전적 검색에서 JSON을 자동 수집하는 기능과는 별개다. 새 API·DB·유료 AI·파일 전송·저장·자동 폴링을 추가하지 않는다. 기존 전력 비교를 위한 넥슨 조회는 기존 정책을 따른다.

## 화면

상단의 `한 경기 상세 분석`/`여러 경기 비교` 탭에서 분석 방법을 선택한다. 선택한 기능의 입력과 결과만 표시하고, 전환해도 각 파일·선수·결과·비교 과제 설정은 페이지 메모리에 유지한다. 비교로 전환하면 한 경기 재생은 현재 위치에서 일시정지한다. 화살표/Home/End 키로 탭을 전환할 수 있다. 숨겨진 한 경기 분석이 완료돼도 비교 화면의 초점·스크롤을 가져가지 않는다.

분석 예시(ANALYSIS PREVIEW)와 파일 받는 방법(HOW TO)은 결과 아래의 보조 안내로 두고 기본은 접힌 상태다. 제목을 눌러 열 수 있으며 예시에는 내 경기 기록이 아님을 표시한다. 정상 JSON을 읽거나 분석 방법을 바꾸면 다시 접고, 한 경기 초기화·파일 오류 시 안내를 펼친다. 접힘/탭 상태를 영구 저장하거나 새 API를 호출하지 않는다.

탭 전환 보완 검증: 전체 단위 1,102개와 브라우저 49개(재생·비교 27개/해설·API 22개) 통과. PC/모바일·라이트/다크 4조합에서 한쪽 패널만 표시, 파일/선수/결과 유지, 숨겨진 재생 일시정지, 늦은 파일 읽기의 초점 유지, 키보드 전환을 추가 확인했다. 실제 두 파일의 공통 선수 5명도 새 화면에서 확인했다. Cloudflare `58e42f0c` 배포 후 실제 도메인 JS/CSS 4개와 탭 HTML·캐시 참조를 대조했다.

- 재생/일시정지, 1·2·4배속, 전체 시간 슬라이더와 그래프 클릭, 이전/다음 라운드 및 라운드 선택.
- 주요 변화 버튼과 그래프 번호: 검증된 사건 묶음 전후 지수가 8점 이상 바뀐 장면 중 라운드별 최대 1개, 경기 전체 최대 3개를 변화 크기로 고른 뒤 시간순으로 표시한다. 동률이면 먼저 발생한 장면을 선택한다. 버튼은 일시정지 후 해당 라운드 안에서 최대 5초 전으로 이동한다. 종료 점수·라운드 초기화·검증 보류 구간은 제외한다. 실제 승부처나 승리 원인으로 단정하지 않는다.
- A팀 기준 한 개의 지수선(50 위 A팀 우세, 아래 B팀 우세), 현재 시점 커서, 기록된 점수·공수, 선수별 생존 상태, 현재 라운드의 처치·폭탄 사건. 사건은 현재 시간까지 최근12건만 DOM에 표시한다. R 유형은 아래 경기 승리 추정치, 그 외 유형은 기존 상황 우세 지수를 사용하며 B팀 숫자는 100에서 뺀 값이다. [표현 변경 기록](home-brand-single-line.md).
- 사건 목록의 선수 필터는 현재 라운드·현재 시점까지의 처치/사망과 확인된 폭탄 사건을 모아 표시한다. 필터 후 최근 12건을 선택하고, 현재 건수/해당 라운드 전체 건수도 선택 선수 기준이다. 전체 선수에서는 식별되지 않은 폭탄 사건도 기존처럼 남긴다. 선택 선수에서는 원본 nexonSN이 참가자와 일치하고 팀 정보가 모순되지 않는 폭탄 사건만 포함한다. 닉네임 일치로 추정하지 않는다.
- 필터 변경은 재생 위치·재생/정지 상태·점수·생존 인원·지수를 바꾸지 않는다. 선수 목록은 경기에서 처음 확인된 이름과 구분 번호를 사용한다. 선수 ID를 기준으로 라운드 이동 시 선택을 유지하고 재분석하면 전체 선수로 초기화한다.
- AI 해설 연결: 기존 로컬 전용 검증 화면에서 현재 근거와 일치하는 저장/API 해설 카드에 `재생에서 보기`를 표시한다. 현재 파일의 검증된 후보 참조로 라운드·시각·선수 ID·초기 인원·전후 인원을 대조한다. 확인이 어려우면 재생 연결만 보류하고 기존 라운드 근거 보기는 남긴다. AI 문장을 읽어 시각을 추측하지 않는다.
- 해설에서 재생으로 이동하면 정확한 근거 시점에서 일시정지하고 패널로 초점을 옮긴다. 전체 선수 사건을 표시해 이전 필터에 근거가 가려지지 않게 한다. 종료 시점이 다음 라운드 시작과 겹치면 근거 라운드를 유지하고, 재생을 이어갈 때 다음 라운드로 진행한다. 운영 유료 AI 활성화와 별개이며 추가 요청·DB·토큰을 사용하지 않는다.
- 옅은 선은 전체 기록, 진한 선은 현재 시점까지의 흐름이다. R 유형은 동등 전력 가정의 경기 승리 추정치(%)이며 실측 승률이 아니다. 다른 유형은 상황 우세 지수(점)다.
- 자동 재생하지 않는다. 사용자가 누르면 시작하고 화면 숨김/페이지 이탈 시 일시정지한다. 파일 초기화·재분석·선수 변경·경기 유형 변경 시 이전 재생과 이벤트 리스너를 해제한다.

## 경기 승리 추정치와 규칙

2026-10-29 사용자에게 확인한 랭크전 규칙을 `matchType: R`에 적용한다. `replay-match-probability.js`는 UI와 독립된 순수 계산이다.

- 전반 먼저 3승하면 공수교대한다. 후반도 한 팀 3승을 상한으로 하며, 뒤진 팀이 후반 남은 승수를 모두 얻어도 합산 동점이 불가능하면 즉시 종료한다.
- 전반 3:0 → 합산 4:0은 종료하지만, 전반 3:2 → 합산 4:2는 계속한다. 후자는 B팀 후반 3승으로 4:5 역전이 가능하다.
- 후반 종료 합산 동점은 골든라운드 한 번으로 결정한다. 3:3뿐 아니라 4:4·5:5도 가능하다.
- 현재 라운드의 가정값은 `50 + 생존 인원 차이/초기 큰 팀 인원×40 + 설치 중 공격팀 방향10`을 5~95로 제한해 사용한다. 점수는 이 보정에 중복 반영하지 않는다. 이 가중치는 실측 승률로 학습·검증하지 않았다.
- 현재 라운드 A 승/패 이후의 경기 승리 가능성을 각각 계산해 위 가정값으로 가중합한다. 이후 모든 라운드·골든라운드는 양 팀 50%를 가정한다. 맵·공수별 실력 차이는 반영하지 않는다.
- 종료 점수 반영 후에는 다음 라운드를 중립으로 계산한다. 전반 3:0·동일 생존 인원 기준 93.8%, 3:2 기준 59.4%이며 공수교대만으로 50%가 되지 않는다. 이는 해당 가정 아래의 값이지 경기 실측 확률이 아니다.
- 기록된 라운드 종료로 규칙상 승리가 확정될 때만 100%·0%다. 진행 중 표시는 반올림 때문에 승리 확정으로 오해하지 않도록 0.1~99.9%로 제한한다.
- 최종 승자·최종 점수·전체 라운드 수에서 과거 확률이나 종료 조건을 역산하지 않는다. 현재까지의 승자만 순차 반영한다. 공수교대 불일치·누락·종료 후 추가 라운드는 해당 시점 이후 계산을 보류한다. 골든라운드의 공격팀은 파일 기록을 사용한다.
- R 이외 또는 유형 미상은 기존 상황 우세 지수와 단위를 명확하게 표시한다. 재접속 복원·인원/폭탄 검증 보류 정책은 유지한다. 새로운 조회·저장·유료 AI 호출은 없다.
- 그래프·현재 수치·주요 변화(%p)·정사각형 공유 PNG가 같은 값을 사용한다. `indexA`는 표시용 필드이며 `metric`으로 두 계산의 의미를 구분한다.

## 기존 상황 우세 지수와 검증

중립50 + 현재 생존 인원 차이/초기 큰 팀 인원×40 + 이미 끝난 라운드 점수 비율 차이×10 + C4 설치 중 공격팀 방향10. 결과는5~95로 제한하고 B팀은100-A팀으로 표시한다. 다음 라운드 승패나 최종 승패를 미리 반영하지 않는다. 종료 시점에만 해당 라운드의 기록된 승리를 점수에 추가한다. 체력·시야·음성·실제 조준·확률 모델은 사용하지 않는다.

기존 analyzeRoundContext의 참가자·초기 상태·사망/처치 합계·시간 검증을 재사용한다. 같은 시각의 사망은 동시 처리한다. 수류탄/지연된 피격으로 사망한 공격자의 처치가 기록될 수 있으므로 공격자 사망 여부만으로 기록을 부정하거나 공격자를 부활시키지 않는다. 사망자는 피해자 기록에 따라 차감한다.

공식 폭탄 코드0설치/1폭파/2해제/3드롭과 0.1초 타임스탬프를 사용한다. 미제공·알 수 없는 코드·모순된 순서·동시 폭탄 상태 등은 상태 계산을 보류한다. 검증이 보류된 구간은 그래프를 이어 그리지 않으며, 생존 인원도 검증되지 않았으면 미확인으로 표시한다. 확인 가능한 사건 목록은 남긴다. 시간·라운드 순서가 유효하지 않으면 재생 패널만 보류하며 기존 분석은 유지한다.

이탈·재입장이 있는 경우에는 재생 전용 `trackReplayParticipants`로 대조한다. 공식 뷰어의 상태 3 이탈/3→1 재참여 표시 방식에 맞춰 상태 1 생존·2 사망·3 이탈을 구분한다. 원본 참가자·팀·처치/사망 합계와 사망 상태 시각(기록 오차 0.1초 이내), 입장·재참여 순서를 검증한다. 살아 있는 선수의 이탈은 해당 시각에만 생존 인원에서 제외하고, 사망 후 이탈은 중복 차감하지 않는다. 이탈 후 상태 1이 기록된 경우에만 생존 인원으로 돌아온다. 사망한 공격자의 지연 처치는 공격자를 부활시키지 않는다.

요약의 이탈 표시만으로 퇴장 시각을 추측하지 않는다. 이탈 표시가 있어도 마지막 상태가 생존이고 기록이 라운드 종료 0.5초 이내까지 확인되면 생존 기록을 따른다. 종료 전 이력이 잘렸거나, 재입장 표시만 있고 시각이 없거나, 죽은 뒤 이탈 없이 생존으로 바뀌거나, 합계/팀/상태가 모순되면 보류한다. 늦은 최초 등장은 일치하는 입장 시각이 있어야 그전에는 미참여로 처리한다. 기존 시작 상태 0.5초 허용 기준을 유지한다. 상태 기록은 라운드당 최대 25,000개, 입장/공격 각 최대 5,000개로 제한한다.

재생 전용 복원에 성공한 라운드만 지수·인원과 이탈/입장 사건을 표시한다. 원래 통계·AI 코칭용 `analyzeRoundContext`는 그대로 유지하므로 그래프의 복원 라운드 수와 해설·비교 통계의 검증 범위가 다를 수 있다. 불완전한 라운드에서 일부 시간만 살리는 구간별 복구·지수 범위 표시는 아직 구현하지 않았다.

재입장 표시와 늦은 명시적 입장 시각이 함께 있으면서 그 전 상태가 생존으로만 채워진 형식은 입장 시각부터 참가로 반영한다. 입장 후 0.5초 이내의 생존 표본이 필요하며, 그전 처치/사망 사건이나 모순된 상태가 있으면 보류한다. 입장 전에는 사망으로 표시하지 않고 `입장 전`으로 구분한다. 같은 시각의 상태 1→2는 일치하는 피해자의 사망 사건이 있는 경우에만 허용하며, 다른 동시 상태 충돌은 그대로 보류한다.

C4 시스템 사망은 공격자 0, 아이템 코드 6104와 해당 폭파미션 사망 이름, 정상적인 설치와 같은 시각의 종료 폭발, 공격팀 승리, 피해자 상태 사망이 모두 대조될 때만 복원한다. 임의의 알 수 없는 공격자는 허용하지 않는다. 이 사망은 게임 요약 데스에 포함되지 않는 형식이므로 일반 처치/사망 합계는 그대로 대조하고, 재생의 생존 인원만 감소시킨다. 사람에게 킬을 부여하지 않고 `C4 폭발 사망`으로 표시하며 피해자 필터와 공유 이미지에도 반영한다. 통계·AI 근거의 검증 범위는 확대하지 않는다.

100라운드·총5000사건·라운드당 최대3600초의 재생 범위를 두고 이름·무기는 길이를 제한해 텍스트로 이스케이프한다. 원본 파일/객체는 수정하지 않는다. 지도 위 연속 이동이나 알려지지 않은 폭탄 카운트다운은 만들어내지 않는다.

## 여러 경기 기본 통계 비교

리플레이 분석실 상단의 `여러 경기 비교` 탭에서 JSON 2~5개(각 최대 2MB)를 한 번에 선택한다. 파일이 1개뿐이면 추가 선택 방법을 안내하며 새 선택은 기존 파일 목록을 대체한다. 기존 한 경기 분석과 별도이며 전력 API·AI·서버 저장을 사용하지 않는다. raw 파일과 계산 결과는 현재 페이지 메모리에만 보관하고 `비교 지우기`·새 파일 선택·페이지 종료 시 해제한다. 로컬 저장소나 DB에 쓰지 않는다.

선수 ID가 두 경기 이상에 있는 경우만 비교 대상으로 제공하고 각 파일의 이름을 함께 표시한다. 닉네임 변경은 같은 ID로 연결하며 동명이인의 다른 ID는 합치지 않는다. 파일 선택 순서대로 표시하고 일시 문자열을 임의로 해석해 추세나 실력 향상으로 판단하지 않는다.

기존 `analyzeRoundContext` 검증을 통과한 라운드에서 처치/사망·라운드당 처치·첫 사망·라운드 생존율·평균 생존을 계산한다. 첫 사망은 동시 사건에 포함될 수 있다. 생존한 라운드는 기록된 종료 시간까지 계산하고 전체 평균·비율은 라운드별 원자료 합계를 사용한다. 검증되지 않은 라운드와 해당 선수가 없는 경기는 0으로 채우지 않는다. 게임별 검증 라운드/제공 라운드와 제외 사유를 표시한다.

문자열이나 안전 정수 경기 ID가 같고 기록이 다르면 추가 파일을 제외한다. ID가 정밀도를 잃은 숫자이면 ID를 신뢰하지 않고 맵·일시·참가자·라운드·처치·초기 상태의 고정 필드 투영을 대조한다. 동일 기록은 중복에서 제외하지만 서로 다른 정확한 경기 ID는 동일 통계라는 이유로 합치지 않는다. 파일명이나 닉네임만으로 같은 경기라고 판단하지 않는다. 제공 라운드 100개·참가자 64명·전체 사건 5,000건·상태 25,000개·라운드 3,600초를 제한하고 불명확한 구조는 사유와 함께 제외한다.

새 단위 7개, 전체 단위 1,078개, 브라우저 37개(비교 6+기존 재생 9+해설/API 22)가 통과했다. 실제 JSON 3개 모두 읽었고 두 경기 이상에 있는 선수 2명에서 각 16/15개 검증 라운드의 유한한 통계를 확인했다. 실제 파일은 업로드하거나 저장소에 넣지 않는다.

## 과제 전후 지표 확인

여러 경기 비교 안의 `과제 전후 확인`을 펼쳐 첫 사망 비율 줄이기·생존율 늘리기·라운드당 처치 늘리기·평균 생존 변화 중 확인할 지표를 고른다. 각 파일은 직접 기준 경기·이후 경기·제외로 구분하며 처음에는 모두 미지정이다. 같은 경기의 중복은 비교 준비 단계에서 제거하므로 한 경기가 두 그룹에 들어가지 않는다. 날짜 문자열이나 AI 문장으로 순서를 추측하지 않는다.

두 그룹 모두 해당 선수의 검증된 라운드가 있어야 결과를 보여준다. 기존 경기 비교와 공용 합산 함수를 사용해 라운드별 원자료 합계로 평균·비율을 계산한다. 그룹마다 집계 가능/지정 경기 수와 검증/제공 라운드 수를 안내한다. 증감은 이후에서 기준을 뺀 값이며 비율 차이는 퍼센트포인트(%p), 시간은 초로 표시하고 각 표시 단위로 반올림한다. 지표의 목표 방향을 안내하지만 실력 향상이나 코칭 효과를 입증하지 않는다. 생존 시간이 길어졌다는 이유만으로 개선으로 평가하지 않는다.

선수 변경 시 그룹과 지표를 유지하고 새 선수의 검증 기록만 다시 계산한다. 과제 설정 지우기는 파일을 유지하면서 그룹·지표를 초기화하고, 파일 교체/전체 비교 지우기/페이지 종료는 이전 설정과 메모리 결과를 정리한다. 기기 저장소나 DB에는 기록하지 않는다. 새로고침 뒤에는 기준 파일과 이후 파일을 다시 선택해야 한다. AI 해설 내용을 자동 저장하거나 실행 여부를 판별하는 기능은 아니다.

새 단위 7개·관련 단위 14개·전체 단위 1,085개·브라우저 41개(비교/과제 10+재생 9+해설/API 22) 통과. 목표 방향·%p·라운드 가중 평균·누락·제외·검증 보류·초점·선수 변경·초기화를 확인했다. 실제 JSON 3개에 공통인 선수 2명을 수동으로 표본 구분해 6/10라운드와 6/9라운드의 차이를 계산했다. 이 로컬 검증은 실제 코칭 전후의 시간순서나 효과를 검증한 것이 아니다.

## 그래프·선택 시점 공유 이미지

재생 조작부의 `이 시점 이미지`를 누르면 재생을 멈추고 그 시점의 표시 전용 모델을 만들어 1080×1080 PNG로 그린다. 상단 `이미지 공유`(기존 표시 이름: 분석 카드 공유)는 1080×675 요약 카드를 유지한다. 정사각형 카드에는 전체 흐름의 옅은 선과 현재 시점까지의 진한 선, 선택 시각·라운드·점수·인원·지수·폭탄 상태, 현재 라운드의 최근 사건 최대 2건을 담는다. 과거·미래 사건을 임의로 보완하지 않으며 검증 보류 구간의 지수선은 생략한다.

최종 점수와 선택 시점 점수를 구분한다. R 유형은 경기 승리 추정치·동등 전력 가정·실측 승률 아님을, 다른 유형은 상황 우세 지수·승리 확률이나 AI 예측 아님을 표시한다. 공유 URL은 일반 분석실 주소이며 같은 장면을 다시 보려면 원본 파일이 필요하다. URL 쿼리/해시, 선수 ID·좌표·원본 파일 정보는 모델에서 제외한다. 닉네임과 사건에 표시된 이름은 이미지에 포함된다. 긴 텍스트는 줄여 표시하지만 최종 점수를 위한 공간은 별도로 확보한다.

Canvas에서 로컬로 PNG를 만들고, 지원하는 기기의 공유창은 사용자가 직접 목적지를 선택한다. 지원하지 않으면 PNG를 내려받는다. 공유 취소 시 다운로드로 전환하지 않는다. 인코딩 중 파일·선수·결과가 바뀌면 이전 이미지의 다운로드/공유를 보류하고, 원본 분석과 현재 재생 컨트롤러를 다시 대조한다. 추가 AI·API·DB·이미지 서버나 원격 이미지·새 폰트 요청을 추가하지 않는다.

공유/재생 관련 단위 28개·전체 단위 1,089개·브라우저 46개(비교/과제 10+재생/공유 14+해설/API 22) 통과. 실제 PNG의 서명·크기, 취소·대기 중 선수 변경·시점 정지·기존 카드, 긴 텍스트와 보류 표기를 확인했다. 마지막 맵 이름/점수 배치 조정 뒤 관련 단위 28개와 공유 브라우저 5개를 다시 확인했다. 실제 JSON 3개의 25라운드에서도 표시 모델의 유한한 지수점과 식별자·좌표 제외를 로컬 확인했다. 실제 파일이나 실명 자료를 테스트 이미지로 생성하거나 업로드하지 않았다.

## 이전 단계 검증 기록

두 번째 이탈/재입장 표본의 후속 보완: 8라운드 중 5라운드에서 4.1초 입장 이전의 생존 표본과 동일 시각 생존/사망 표본, 6라운드에서 161.4초 C4 시스템 사망을 확인했다. 이전 배포 기준 재생 6/8→8/8라운드 복원, 통계/AI 검증은 기존 5/8을 유지한다. 첫 이탈 표본 6/6과 기존 실제 3개 파일 25라운드 결과도 유지한다. 원본 파일은 로컬에서만 검사하며 저장소나 외부 서비스에 올리지 않는다.

새 단위 5개·관련 단위 41개·전체 단위 1,102개·브라우저 49개 통과. 입장 전→생존→사망 표시, C4 피해자 필터와 공유 PNG를 확인했다. 원본 빌드·소스/산출물 검사 후 Cloudflare `124ad372`에 배포하고 실제 도메인의 JS/CSS 6개와 캐시 참조를 확인했다.

이탈 후속 보완: 사용자 파일의 6라운드에서 이탈한 선수의 상태 3이 미지원 코드로 처리되고 요약 이탈 표시 때문에 전체 보류되던 원인을 확인했다. 재생은 5/6→6/6으로 복원했고 통계·AI 근거는 기존 5/6 검증 범위를 유지한다. 사망 후 14.7초/60.6초 이탈은 추가 인원 감소가 없고, 생존 중 56.3초/65.4초 이탈은 해당 시각에 반영한다. 이 파일에는 중간 입장·재입장 기록이 없어 재입장은 합성 사례로 검증했다. 기존 실제 JSON 3개 25라운드 결과 유지, 새 단위 8개/관련 36개/전체 1,097개/브라우저 48개 통과. 원본 파일·이름·ID는 테스트 저장소나 외부에 올리지 않는다. 공식 뷰어 참조는 [공개 번들](https://barracks.sa.nexon.com/js/chunk-common.fafec01e.js)의 기존 확보본을 확인했으며 최신 웹 조회는 불가했다. 원문 코드를 복제하지 않고 동작 의미만 대조했다.

해설 연결 추가 시 관련 단위 39개·전체 단위 1,071개·브라우저 31개(해설/로컬 API 22개+재생 9개) 통과. 정확한 근거 이동·일시정지·전체 사건 표시·초점·키보드·라운드 경계·기존 이동·인증/중복 생성 방지·구매 비활성 상태를 확인했다. 기존 구매 안내 브라우저 검사 2개는 오래된 미확정 가격/환불 문구 기대를 현재의 20회·3,300원·365일·정상 제공 1회당 165원 기준으로 갱신했다. 실제 판매 조건이나 구매 코드는 수정하지 않았다. 실제 JSON 3개의 첫 선택 선수별 후보 18개도 로컬 재생과 일치했다.

선수 필터 추가 시 단위 19개·브라우저 9개 통과. 동명이인·위장 닉네임과 ID 구분, 폭탄 사건 ID/팀 검증, 필터 후 최근 12건 제한, 미래 사건 제외, 재생 상태 유지·라운드 이동·재분석 초기화를 확인했다. 실제 JSON 3개의 총 25라운드·폭탄 사건 17개에서도 식별 연결을 로컬로 확인했다. 파일은 업로드하지 않는다.

주요 변화 추가 시 단위 16개·브라우저 8개를 통과했다. 동시 사건의 순변화, 변화 크기 우선 선정·동률 처리·최대 3개, 검증 보류 구간 제외, 종료 점수 제외, 라운드 안의 5초 전 이동과 일시정지·키보드 재생을 확인한다. PC/모바일×라이트/다크 레이아웃과 새 API 호출이 없는지도 확인한다.

단위13개: 동시 처치, 뒤로 탐색, 공수 전환, 미래 결과 미반영, 폭탄 상태, 사후 처치, 재입장·누락·중복 사망, 시간·크기 경계, 지수 대칭/범위, 불완전 구간 보류. 브라우저7개: 모바일/PC×라이트/다크, 동기화, 배속/정지/이탈/초기화, 보류 구간, 이름/무기 문자열 주입과 선수 전환. 기존 해설 브라우저2개와 전체 단위1063개도 통과했다.

사용자가 제공한 실제 JSON3개에서 총25라운드(6+10+9)를 로컬로 재구성해 확인했다. 실제 파일은 저장소나 제3자 서버에 올리지 않는다. 합성 테스트와 실제 파일 로컬 검증을 구분한다.

화면 배치: PC에서는 그래프·시간 이동·조작부를 왼쪽, 선수와 사건 기록을 오른쪽에 배치한다. 화면 높이에 따라 그래프 높이를 조절하고 긴 사건 목록과 선수 목록은 해당 영역 안에서 스크롤한다. 작은 화면에서는 한 열로 전환하며 계산 설명은 필요할 때 펼친다. 계산·데이터·재생 동작은 동일하다.
