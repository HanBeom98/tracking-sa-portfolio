# 관리자 운영 대시보드

2026-10-29 구현. 운영 반영 여부는 배포 커밋과 `/build.txt`로 별도 확인한다.

## 진입과 권한

`/admin/`은 사이트 관리자 전용 화면이다. 공통 헤더의 **관리자** 링크는 인증이 완료된 사이트 관리자에게만 나타난다. 일반 회원·비회원·리그 전용 운영자는 이 화면의 목록 조회를 시작하지 않는다.

기존 `auth/domain/access-policy.js`의 사이트 관리자 이메일 또는 현재 사용자의 `users/{uid}.role == "admin"`을 사용한다. 리그 운영 권한을 사이트 전체 권한으로 확대하지 않는다. 화면의 링크·진입 검사는 사용 편의를 위한 것이며, 실제 읽기·쓰기 허용 여부는 기존 Firestore 보안 규칙이 결정한다. 정적 HTML이나 JS의 URL 자체는 비밀이 아니다. 이 작업에서 권한 부여·보안 규칙 변경은 하지 않는다.

배포 후 기존 방문 브라우저가 이전 로그인 메뉴를 재사용하는 문제를 확인해, 공통 런타임 → 로그인 UI → 로그인 메뉴까지 자산 버전을 전달한다. 메뉴 코드 변경도 빌드 지문에 포함하므로 새 버전에서 관리자 링크가 갱신된다.

로그아웃·다른 계정 전환·관리자 역할 상실 시 목록과 확인창 내용을 지운다. 이전 인증 상태에서 시작한 조회 응답도 화면에 다시 표시하지 않는다. 기존 `users` 프로필은 기존 인증 흐름이 읽으며 대시보드가 회원 전체를 조회하지 않는다.

## 제공 기능

| 메뉴 | 동작 |
| --- | --- |
| 관리자 홈 | 대기 신청 수(목록 범위), 홈 표시 공지 수, 최근 공지·신청 요약 |
| 공지 관리 | 최근 20개 공지, 작성 시각·홈 표시 기한·표시 상태, 기존 작성·수정·본문 화면 연결 |
| 리그 신청 | 대기 신청 20개, 개별 전적 확인 링크, 확인창을 통한 승인·반려 |
| 운영 바로가기 | 기존 Google Analytics·Firebase·Cloudflare 콘솔 링크, 수동 배포 정보 확인 |

홈 공지는 기존 정책인 작성일부터 14일·최신 5개 기준이다. 삭제 기능·새 공지 편집기는 중복 구현하지 않는다. 전체 리그 관리 기능은 기존 리그 화면 링크로 연결한다. 배포 정보는 정적 `/build.txt`의 커밋과 빌드 시각을 보여주며 서버 상태·배포 성공 여부를 대신 판단하지 않는다.

## 읽기와 비용

목록은 관리자 진입 시 필요한 것만 조회한다. 각 쿼리는 **최대 21건**을 요청해 20건과 추가 목록 존재 여부를 표시한다. 홈의 두 목록은 최대 42개 문서를 반환하는 범위이며, 이는 인증·규칙 평가·인덱스 등 모든 비용을 포함한 과금 상한이라는 뜻은 아니다. 조회 실패는 0건으로 표시하지 않는다.

같은 화면 안의 메뉴 이동은 메모리 결과를 재사용한다. **새로고침·재시도·신청 처리 후 목록 갱신·페이지 재진입**에는 다시 읽기가 발생한다. 자동 폴링·실시간 구독·전체 회원/경기 스캔·분석 이벤트 이중 저장·새 컬렉션·새 함수는 추가하지 않는다. 배포 정보도 버튼을 누를 때만 정적 파일을 읽는다. 외부 콘솔은 링크만 제공한다.

## 신청 처리 안전장치

승인·반려는 기존 `CrewRepository` 메서드를 공유한다. 트랜잭션 안에서 신청의 존재·PENDING 상태·UID 일치 여부를 다시 확인한다. 승인 대상 닉네임과 OUID는 화면 인자가 아니라 저장된 신청에서 읽는다.

- 이미 같은 OUID의 멤버가 있으면 **닉네임 이력·점수·승패·기존 필드를 그대로 유지**하고 신청만 처리한다.
- 새 멤버만 기존 초기 점수·0승 0패로 생성한다.
- 멤버 생성과 신청 상태 변경은 함께 성공하거나 함께 취소된다.
- 여러 운영자가 동시에 처리하면 먼저 완료한 한 번만 적용되고, 뒤의 시도는 이미 처리됐음을 알리고 목록을 갱신한다.
- 기존 리그 화면도 같은 안전장치를 사용한다. 리그 전용 운영자의 기존 리그 권한은 유지한다.

결제·환불·이용권 수동 지급·사용자 권한 변경·탈퇴/삭제·시즌 초기화는 이 대시보드에 넣지 않는다.

## 검증

단위 검사는 권한 범위·조회 상한·메모리 재사용·로그아웃 경쟁·확인 후 처리·기존 전적 보존·동시 처리·쓰기 실패 취소를 확인한다. 브라우저 검사는 로컬 DB 대역으로 비회원·일반/리그 회원 차단, 관리자 화면, PC/모바일·밝은/어두운 테마, 확인창과 로그아웃을 확인한다. 실제 SDK·Firestore 규칙 검사는 로컬 Emulator에서 수행하며, 실제 Auth SDK로 관리자 프로필을 복원하고 대시보드에서 신청을 승인하는 브라우저 검사도 포함한다. 운영 데이터를 수정하지 않는다.

관리자 페이지는 `noindex, nofollow`이며 사이트맵·사이트 검색에 넣지 않는다. 광고를 삽입하지 않고 로그인 런타임을 즉시 준비한다. 이 검색 설정은 접근 제어를 대신하지 않는다.
