# 리플레이 AI 단일 호출·정산·결과 복구

2026-10-26 현재 생성 응답은 [사실·질문·연습 ID 선택 계약 v2](replay-coaching-facts.md)로 변경했다. 모델의 자유 문장을 저장하는 대신 서버가 카드를 조립하고 선택 정보도 함께 보관한다. 아래 초기 요청의 실제 토큰·품질 측정은 이전 계약의 기록이다.

2026-10-25. **서버 내부 모듈을 구현하고 모의 공급자·로컬 Firestore Emulator에서 검증했다.** 후속 [실제 품질 시험](replay-coaching-pilot.md)에서는 Luna 생성과 로컬 장부 정산도 확인했지만 의미 품질 기준을 통과하지 못했다. 운영 HTTP 연결·운영 DB 쓰기·배포는 실행하지 않았으며 기존 무료 분석과 `mock` HTTP 동작을 유지한다.

## 초기 프롬프트 입력 측정

사용자가 제공한 공식 JSON 한 경기에서 선택 선수 1명의 검증된 9개 라운드를 사용했다. 원본·닉네임·계정 ID 대신 정규화된 수치 요약·한국어 지시문·전체 출력 스키마를 공식 토큰 계산 API에 전달했다. 아래는 교환킬 필드 설명을 보완하기 전 초기 요청의 기록이며, 보완 후 같은 표본은 1,642토큰이다.

| 항목 | 측정값 또는 설정 |
| --- | ---: |
| 전체 생성 요청 UTF-8 바이트 | 6,376 |
| 전체 입력 토큰 | **1,450** |
| 정책 입력 상한 | 6,000 |
| 출력 상한 | 2,000 |
| 입력 단가 | 100만 토큰당 $0.10 |
| 출력 단가 | 100만 토큰당 $0.50 |
| 입력 비용 계산 | $0.000145 |
| 출력 상한까지 사용한 합계 | **$0.001145 (1,145 µUSD)** |
| 실제 토큰 계산 / 해설 생성 호출 | 1 / **0** |

합계는 현재 Standard·캐시 없음 단가로 산출한 이 요청의 상한 추정이다. 실제 생성 usage·품질·속도·청구 결과가 아니며, 다른 선수·경기·프롬프트에는 다른 수가 나온다. 세금·환율·호스팅 비용을 포함하지 않는다. 토큰 계산 엔드포인트의 무료 제공이나 영구적인 가격을 보증하지 않는다.

## 구현한 경로

| 파일 | 역할 |
| --- | --- |
| `cloud-functions/replay-coaching-openai.js` | 명시적으로 켠 단일 Responses 호출, 응답/usage 해석, 근거 참조 검증 |
| `cloud-functions/replay-coaching-result.js` | 보관할 짧은 결과의 정확한 필드·분량·크기 검사 |
| `cloud-functions/replay-coaching-runner.js` | 예산 준비 → 영속 전송 승인 → 생성 1회 → 결과와 비용의 원자적 정산 |
| `cloud-functions/replay-coaching-quota.js` | 기존 개인 종료 기록에 결과를 함께 저장하고 동일 요청에서 재조회 |

키 자동 검색·SDK·새 서비스·예약 작업·자동 재시도·대체 모델·추가 로그 저장소는 없다. 네트워크 호출은 고정된 공식 `/v1/responses`만 허용하며 리디렉션을 거절한다. 기본 제한은 30초, 설정 상한은 45초이며 본문 읽기도 같은 기한에 포함한다. 응답은 최대 64KiB만 읽고 공급자 오류 본문·키·원문을 오류에 싣지 않는다. 기한 종료가 공급자 처리나 청구의 취소를 보장하지 않는다.

모델·처리 티어·입력/출력/합계·캐시 읽기/쓰기·숨은 추론 토큰의 범위를 확인한다. 검토하지 않은 모델 별칭/스냅샷, 변경된 단가/티어, 누락된 usage, 입력 수 불일치는 비용을 0으로 추정하지 않고 미확정 예약으로 남긴다. 실제 소액 시험에서 반환된 모델 ID와 usage는 현재 계약과 일치했다. 향후 요청도 같은 검사를 통과해야 한다.

## 장애 시 결과

| 상황 | 사용자 성공 | 비용·결과 처리 |
| --- | --- | --- |
| 정상 JSON·근거·분량·usage | +1 | 확인한 비용과 검증한 결과를 **같은 트랜잭션**으로 저장 |
| 거절·출력 잘림·잘못된 JSON/근거, usage는 확인됨 | +0 | 발생 비용은 정산, 남은 최대 예약액 해제, 결과 미보관 |
| 통신·타임아웃·HTTP 오류·알 수 없는 usage | 미확정 | 최대 예약 유지, 재시도 없음, 명시적 복구 필요 |
| 전송 승인 저장의 응답 유실 | 미확정 | 생성 호출하지 않음, 저장됐을 수 있는 전송 상태 유지 |
| 정산 커밋 후 응답 유실 | 이미 +1 | 동일 요청 ID로 저장된 결과 반환, 재생성/추가 차감 없음 |
| 정산 자체 실패 | 미확정 | 결과를 완료로 반환하지 않음, 예약 유지, 자동 재생성 없음 |
| 명시적 최대 비용 종료 뒤 늦은 결과 | +0 | 오래된 lease의 정산 거절, 비용 중복 반영 없음 |

이미 완료됐지만 결과가 없는 이전 형식 기록은 `COACHING_RESULT_UNAVAILABLE`로 거절한다. 고객 성공 횟수가 남아 있다는 이유로 새 유료 호출을 만들지 않는다. 같은 입력을 다른 요청 ID로 제출하면 별개 작업이며, 동일 ID 중복 방지와 전체 콘텐츠 캐시는 다르다.

## 보관 범위와 비용

원래 비용 기록 `recent` 안에 공급자 응답 ID와 검증된 카드 JSON만 함께 넣는다. 입력 요약·원본 JSON·닉네임·선수 ID·공급자 전체 본문·API 키를 저장하지 않는다. 모델 문장의 사실성/개인정보 무포함을 이 구조 검사만으로 보장하지 않는다.

- 결과 1개는 최대 **3,072바이트**, 카드 1~3개다. 제목/관찰/연습/한계 상한은 30/100/80/60자다.
- 현재 이용 기간과 이전 2개 기간에만 남긴다. 기간당 성공 50개·시도 70개이므로 결과 최대 **150개**, 종료 기록 최대 **210개**다. 사용자 문서 전체 JSON은 **700,000바이트**를 넘으면 거절해 Firestore 문서 한도 여유를 둔다.
- 새 이용 기간을 만들 때 가장 오래된 기간을 제외한다. 시간이 지났다고 즉시 물리 삭제하거나 24시간 TTL을 실행하지 않는다. 오래된 자료의 별도 백업·삭제 스케줄은 없다.
- 기존 정상 흐름의 **4트랜잭션·10읽기·5쓰기**에서 결과를 함께 보관하므로 결과 전용 문서/추가 쓰기를 만들지 않는다. 문서 크기와 전송량은 늘며 충돌 재시도 시 읽기는 늘 수 있다. 완료 재조회는 읽기 2회이고 토큰 계산·생성·쓰기는 없다.
- 최신 결과 1개만 덮어쓰는 초기 제안 대신 종료 기록과 함께 보관한다. 그래야 이후 작업이 생겨도 보관 중인 기존 요청의 응답 유실을 재생성 없이 복구할 수 있다. 운영 도입 전 개인정보 처리방침과 보관/삭제·조회 안내를 이 동작에 맞춰야 한다.

## 검증과 남은 단계

새 단위 검사 15개에서 단일 호출·토큰/티어 불일치·거절·본문 크기·시간 제한·중복 경합·커밋 전후 응답 유실·명시적 복구와 늦은 정산·최대 210개 기록을 확인했다. 전체 단위 **807/807**, Emulator **61/61**, 빌드가 통과했다. 공급자 응답은 테스트 대역이며 실제 생성 품질/속도/청구를 검증한 결과가 아니다.

후속 소액 시험에서 실제 Luna의 모델 ID·usage·분량은 확인했지만 수치 해석 오류와 약한 조언을 발견했다. 사실 문장의 서버 확정과 상황별 선택 계약을 내부 구현했으며 다음은 새 계약의 제한된 실제 선택 시험과 유용성 평가다. 운영 HTTP·화면 연결, 실제 구독 권한·PG·환불, 고객 보관/삭제 정책은 별도다. 구현한 내부 함수를 등록했다고 운영 기능이나 판매가 활성화되지는 않는다.
