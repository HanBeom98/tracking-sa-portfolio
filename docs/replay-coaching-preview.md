# 해설 미리보기와 응답 계약 v1

근거 요약 준비에 이은 **2단계 모의 화면**이다. 브라우저에서 정해진 문장에 기록을 넣어 응답을 만들고 검증한 뒤 표시한다. 생성형 AI·API endpoint·유료 토큰·서버 저장·구독·사용량 차감은 연결하지 않았다. 기존 전력 비교 조회는 그대로다.

## 화면

- 분석 결과의 `해설` 바로가기에서 **해설 미리보기** 패널로 이동한다.
- `AI 미연결 · 예시`를 표시한다. 모의 결과를 실제 AI 평가로 표시하지 않는다.
- 최대 3개 카드에 `유지할 점 찾기`, `복기할 장면`, `다음 경기 과제`를 담는다. 뒷받침할 장면이 없으면 강점/복기 카드를 억지로 만들지 않는다.
- 각 카드는 **관찰한 사실 / 연습 제안 / 해석 한계**를 구분한다. 연습 제안을 실제 효과가 검증된 처방이나 패배 원인으로 표현하지 않는다.
- `N라운드 근거 보기`는 기존 라운드 이동 기능을 재사용한다. 라운드 필터와 접힘을 풀고 대상 카드에 키보드 포커스를 옮긴다. `verified-rounds`는 검증된 전체 집계로 별도 표시한다.
- 전체·검증·제외 라운드 범위를 함께 표시한다. 검증 표본이 없으면 카드 없이 해설 보류 안내와 기존 타임라인을 제공한다.
- 잘못된 응답은 해설 패널에서만 보류한다. 나머지 기존 분석을 중단하거나 자동 재요청하지 않는다.

## 모듈과 연결

| 모듈 | 역할 |
| --- | --- |
| `domain/replay-coaching-response.js` | 응답 형식·길이·종류·근거 참조 검증과 안전한 객체 재구성 |
| `application/replay-coaching-preview.js` | 검증된 근거 요약에 기반한 결정적 모의 문장 생성. 네트워크·저장 없음 |
| `ui/replay-coaching-panel.js` | 검증 후 HTML 이스케이프, 상태 안내 및 근거 버튼 렌더링 |
| `main.js` | 기존 분석 결과에 패널 추가. 공유·상세 분석·파일 선택 흐름 유지 |

## 응답 형식

아래는 합성 기록의 한 카드 예시다. 루트에는 `schemaVersion`과 `cards`만 허용한다. 검증 표본이 있으면 1~3개, 표본이 없으면 빈 배열이다.

```json
{
  "schemaVersion": 1,
  "cards": [{
    "kind": "review",
    "title": "첫 사망 장면을 먼저 복기하기",
    "observation": "2라운드 2.0초, 본인 포함 3대3에서 첫 사망했습니다.",
    "practice": "첫 교전 직전의 엄폐 위치와 팀원 합류 가능 여부를 확인하는 질문으로 해당 장면을 다시 보세요.",
    "limitation": "첫 사망이라는 사실만으로 무리한 진입이나 라운드 패배의 책임을 판단할 수는 없습니다.",
    "evidenceRefs": ["round-2"]
  }]
}
```

| 항목 | 제한 |
| --- | --- |
| `schemaVersion` | `1` |
| `kind` | `strength`, `review`, `practice`. 같은 종류 중복 금지 |
| `title` | 공백 아닌 문자열, 최대 80 UTF-16 코드 유닛 |
| `observation` | 최대 400, 공백 문자열 금지 |
| `practice`, `limitation` | 각각 최대 300, 공백 문자열 금지 |
| `evidenceRefs` | 1~2개, 중복 금지. 현재 입력에 실제 포함된 상세 장면 ID 또는 `verified-rounds`만 허용 |
| 기타 필드 | 루트·카드 모두 허용하지 않음 |

한 카드라도 잘못되면 응답 전체를 표시 보류한다. 제외되거나 상세 선택에서 빠진 라운드는 전체 집계에 값이 있더라도 개별 장면으로 인용하지 못한다. 참조와 숫자의 원천은 [근거 요약 계약](replay-coaching-evidence.md)이다. 예시/AI 여부와 표본 범위는 모델이 작성할 필드가 아니라 화면에서 결정한다.

이 검증기는 **서술 내용의 진실성이나 제안의 효과를 입증하지 않는다**. 유효한 근거 ID를 붙인 잘못된 문장까지 검출하는 기능이 아니다. 실제 모델 연결 단계에서는 서버의 입력 재검증·인증/할당량·요금 상한 정책과 함께 사실-문장 일치 평가를 추가해야 한다. 현재 모의 응답 검증을 유료 API 보안이나 품질 보증으로 간주하지 않는다.

## 검증과 다음 단계

- 단위 테스트: 모의 분기, 동시 처치·사망 후 처치의 표현, 일부/전체 판정 보류, 응답 버전·알 수 없는 필드·길이·참조 검사, HTML 이스케이프와 오류 격리.
- 로컬 Chromium: 390px·1280px, 밝은/어두운 테마, 라운드 필터 후 근거 이동, 파일 교체·초기화, 보류된 라운드 제외, 새 네트워크 요청이 없는 흐름. 오래된 합성 기록으로 기존 OpenAPI 예측도 제외하고 외부 서비스를 차단한다.
- 실제 생성형 AI와 휴대폰 OS를 검증했다는 뜻은 아니다. 스크린샷은 합성 기록을 사용한다.

```sh
node --test tests/unit/replay-coaching-preview.test.js tests/unit/replay-coaching-evidence.test.js
npm run build
npm run test:e2e:ci -- --grep "coaching preview|replay context|local replay entry"
```

[테스트 전용 서버 기반](replay-coaching-server.md)을 구현하고 로컬에서 검증했다. 브라우저는 아직 이 API를 호출하지 않는다. 실제 모델·구독 연결과 실제 요금에 따른 한도 설정은 후속 단계다.
