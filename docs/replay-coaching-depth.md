# 구독자용 복기 흐름과 다음 경기 확인 목표

2026-10-26. 구독자용 내부 AI 후보에 장면 흐름·확인 이유·다음 3라운드 목표를 추가하고, 이전 규칙에서 실제 3경기의 생성·검증·로컬 저장·재조회를 확인했다. 이후 **새 생성에만 주제 중복 축소와 행동 목표 v2를 적용**하고, 별도로 제한한 새 시험에서 같은 두 경기의 AI 선택을 비교했다. 두 응답 모두 처음부터 서로 다른 주제 3개를 선택했으며 저장·추가 호출 없는 재조회도 통과했다. 작은 표본의 기술 검증이며 유료 가치는 아직 확인되지 않았다. 기존 무료 분석·무료 모의 해설·저장 결과·화면 응답 형식은 유지한다. 실제 구독 권한·유료 HTTP 연결과 배포는 별도 단계다.

## 후보와 상황 검사

- 현재 후보는 기존 전체 검증 집계와 최대 6개 상세 라운드에서 최대 24개로 제한한다. 라운드마다 우선 후보를 번갈아 넣어 한 라운드만 목록을 채우지 않도록 한다. 생략 수를 함께 전달한다.
- 심화 사망·단독·첫 사건·교환킬 수행/수혜·개인/팀 종료 결과를 추가했다. 교환킬은 후보로 표현하며 수행자와 수혜자를 구분한다. 동시 사건의 내부 순서는 정하지 않는다.
- 사망 직전에 본인 외 생존 팀원이 있어야 팀원 대응 질문/목표를 제공한다. 처음부터 혼자인 경우에는 이전 팀원 사망을 전제하지 않는다.
- 새 연습 슬롯은 다음 3라운드 확인 목표를 가진 심화 후보만 선택할 수 있다. 기존 단일 사실은 강점/복기 후보로 남는다. 이전에 저장한 일반 연습 카드의 재조회는 유지한다.
- `reviewReason`은 서버가 만든 확인 이유다. UI는 기존 카드 형식을 쓰고 제목과 관찰 흐름으로 상황을 보여준다. 모델 입력에 원본 JSON·계정 식별자·닉네임·클라이언트 지시를 추가하지 않는다.
- 모델 출력의 고정 슬롯 v3·최대 3장·종류별 한 장을 유지한다. 같은 사실의 이전/심화 표현을 서로 다른 카드에 중복 배치하면 서버가 거절한다.

## 새 생성: 주제 중복 축소와 행동 목표 v2

- 후보마다 서버가 작성한 `topic`을 전달한다. 다른 라운드의 교환킬 수행/수혜는 모두 `trade`로 묶고, 이전/심화 표현에도 같은 주제를 부여한다. 단독 생존(`solo`)과 일반 인원 점검(`survival`)은 다른 행동 맥락이므로 구분한다.
- 모델에는 서로 다른 주제를 선택하고 부족한 슬롯은 `null`로 두도록 지시한다. 승리·높은 킬 수를 좋은 판단의 원인으로 해석하지 않도록 명시한다.
- 서버는 먼저 **모든 선택의 사실·종류·질문·연습 조합을 검사**한다. 잘못된 조합을 중복 제거로 숨겨 성공 처리하지 않는다.
- 유효한 선택에만 `연습 → 복기 → 강점` 순으로 주제 중복을 줄인다. 남긴 항목은 모델이 실제 선택한 부분집합이며 다른 사실을 대신 넣지 않는다. 같은 주제를 반복하면 1~2장만 남을 수 있다. 같은 주제라는 이유로 생성 전체를 실패시키거나 재호출하지 않는다.
- 주제가 다른 카드의 순서·역할은 유지한다. 카드 수와 무관하게 성공 응답 1개가 기존 분석 이용 횟수 1회이며, 공급자 사용량·비용 정산 방식은 유지한다.
- 새 심화 후보는 `dp2_` 목표를 사용한다. 사망 시각을 적는 과제 대신 **교전 전 생존 인원 확인, 불리할 때 교전 지속 여부 재판단, 첫 교전 전 엄폐 확인, 아군 사망 시 합류 여지 확인** 같은 행동을 제안한다. 사용자가 실제로 그 행동을 하지 않았다고 단정하지 않는다.
- 단독 생존·아군 사망 같은 조건부 목표는 다음 3라운드에 해당 상황이 없으면 제외하도록 표시한다. 사망 직전에 생존 팀원이 없는 경우 해당 사망 후보에는 팀원 대응 질문/목표를 새로 허용하지 않는다. 제안의 실행·효과는 자동 수집하거나 채점하지 않는다.

이전 실제 AI 선택을 새 목표 ID에 대입한 **로컬 시뮬레이션**에서는 두 경기의 세 카드는 유지되고, 후속 처치가 반복된 한 경기는 복기 카드가 빠져 세 장에서 두 장으로 줄었다. 새 모델 호출 결과나 유료 가치 향상을 증명하는 결과는 아니다.

별도 승인된 시험에서 **새 규칙으로 실제 두 경기**를 생성한 결과는 다음과 같다. 동일한 두 경기·선수에 규칙별 한 번씩 요청한 비교이며, 원본 경기 수가 추가된 것은 아니다.

| 표본 | 이전 실제 선택의 주제 | 새 실제 선택의 주제 |
| --- | --- | --- |
| A | 후속 처치 / 단독 생존 / 인원 변화 | 후속 처치 / 단독 생존 / 인원 변화 |
| B | 첫 교전 / 후속 처치 / 후속 처치 | 첫 교전 / 후속 처치 / 인원 변화 |

두 응답 모두 서버가 중복 카드를 제거하기 전부터 서로 다른 주제를 선택했고, 새 `dp2_` 목표로 카드 3개를 제공했다. 저장 결과 두 건은 읽기 2회·쓰기 0회·추가 카운트/생성 0회로 재조회됐다. 무료 해설 및 이전 저장 문구도 유지됐다.

실행할 행동은 더 분명해졌으나 개인화에는 한계가 있다. 표본 B의 새 연습 장면은 사망 직전 3대2로 유리했고 팀도 승리했다. 이때의 ‘불리하면 교전 지속 여부를 다시 판단’은 다음 경기의 조건부 목표이며, 해당 장면의 실제 실수나 패배 원인을 찾아낸 설명이 아니다. 주제 수가 늘었다는 사실만으로 더 좋은 코칭이나 구독 가치를 입증하지 않는다.

## 이전 결과와 무료 기능의 호환성

이전 `replay-coaching-facts.js`와 `depth1_` 사실·`dq1_` 질문·`dp1_` 목표의 문구와 의미는 바꾸지 않았다. 새 행동 목표만 `dp2_` ID를 사용한다. 저장 선택은 기존 schemaVersion2, 화면 결과는 schemaVersion1을 유지한다. 향후 이미 저장된 `dp2_` 문구를 수정할 때도 새 버전 ID가 필요하다.

신규 생성은 현재 실제로 제공한 후보인지 검사한다. 이전 `dp1_` 목표는 새 생성 후보에 넣지 않고 역사적 결과 복구에 사용한다. 기존 저장 결과는 원래 ID와 문장으로 재조립해서 검증하므로 새 목록의 상위 24개에서 빠진 이전 사실도 복구된다. **과거 저장 카드에는 새 주제 중복 규칙을 소급 적용하지 않는다.** 잘못된 기록·조합·변조 문장은 계속 거절하며 이전 비용/성공 횟수를 초기화하거나 새로 생성하지 않는다.

실제 3경기 시험의 저장 장부를 로컬로 읽어, 주제가 반복되는 이전 카드까지 동일하게 추가 카운트·생성 없이 반환되는 것을 확인했다. 각 재조회는 읽기 2회·쓰기 0회였으며 3경기의 무료 해설도 이전 기록과 일치했다. 무료 분석 코드를 수정하지 않았으며 구독 전용 기능을 공개 활성화한 변경도 아니다.

## 비용과 검증 범위

추가 API 제품·로그·DB 컬렉션·예약 작업·별도 저장소를 도입하지 않았다. 요청 32KiB·입력 6,000토큰·출력 2,000토큰·결과 3,072바이트·사용자 문서 JSON 700,000바이트와 기존 호출/비용 제한을 유지한다. 새 지시와 주제 필드가 포함된 실제 두 요청도 각각 새로 토큰을 조회한 뒤 제한 내에서 생성했다. 실제 토큰 수·지연·사용량 기반 비용의 비공개 시험 기록은 저장소 밖에 보관한다. 이전 요청의 견적을 재사용하지 않으며, 예산 초과 시 생성은 중단하는 기존 경로를 따른다. 두 응답으로 일반적인 선택 품질·속도·비용을 보장하지 않는다.

첫 경기의 이전 실제 선택은 6라운드 첫 사건과 개인/팀 결과, 8라운드 본인 사망과 팀원 후속 처치 후보, 2라운드 시작·사망 직전 인원차와 결과였다. 이후 두 경기에서도 생성 경로가 동작했으나, 한 경기는 세 카드 중 두 카드가 후속 처치 주제였다. 이 관찰을 바탕으로 현재의 주제 중복 축소와 행동 목표 v2를 구현했다.

첫 경기에서는 무료 해설과 두 장면이 겹쳤고, 이후 두 경기에서는 각각 0개·2개 장면이 겹쳤다. 다른 장면을 고르는 것 자체가 더 좋은 해설이라는 뜻은 아니다. 장면 연결·목표 표현·주제 중복 처리는 확장됐지만 실전 행동 변화와 유료 가치는 아직 확인되지 않았다. 실제 플레이어의 수동 평가가 필요하다.

```text
node scripts/replay-coaching-depth-audit.mjs --replay <local.json> --report <new-report.json>
```

원본 사건을 직접 조회하는 기존 독립 오라클과 새 관찰 문장의 수치·주체·동시성·결과를 대조하고 모든 제공된 항목 및 서로 다른 사실의 최대 길이 세 카드 조합을 검사한다. 요약의 일관성과 원본의 진위 인증은 구분한다. 한 경기의 여러 플레이어는 여러 독립 경기 표본이 아니다. 유료 가치·실제 목표 실행·기량 향상을 검증한 결과도 아니다.
