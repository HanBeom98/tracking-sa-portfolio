# 매치 목록 조회와 캐시

2026-11-07 유지보수 체크리스트 3·4번 구현 기준.

## 공급자 조회 범위

NEXON `/suddenattack/v1/match`는 `ouid`, `match_mode`, 선택적인 `match_type`으로 최근 최대 1,000경기를 제공한다. 날짜·이전 페이지 커서는 지원하지 않는다. 날짜를 바꾸어 같은 목록을 반복 요청해도 조회 범위를 확장할 수 없다.

- 최근 경기: 유형별 목록을 합치고 경기 ID로 중복 제거한 뒤 최신순으로 선택한다.
- 활동 달력: 유형별 목록에서 한국 시간 기준 오늘을 제외한 직전 30일을 선택한다. 상세 기록은 날짜를 선택했을 때 기존 방식으로 조회한다.
- 더 보기: 같은 목록에서 현재 마지막 경기 시각 이전 기록을 선택한다. 공급자 범위를 벗어난 과거 기록은 추가로 얻을 수 없으며 화면에 이 한계를 안내한다.
- 리플레이 전력 비교: 같은 목록 중 리플레이 시작 시각 이전 경기만 선택한다. 당시 기록이 공급자 범위에 없으면 현재 경기로 대체하지 않는다.

## 메모리 캐시

`NexonApiClient` 인스턴스에서 OUID·유형·모드별 요청을 공유한다. 진행 중인 동일 요청은 합치고, 정상 목록은 완료 시점부터 30초간 최대 32개 키까지 보관한다. 최근 사용한 키를 유지하며 실패·잘못된 응답은 저장하지 않는다. 원본 목록을 브라우저 영구 저장소나 DB에 새로 저장하지 않는다.

명시적 프로필 새로고침은 목록 캐시를 비운다. 무효화 전에 시작한 요청이 늦게 끝나도 새 캐시를 덮어쓰지 않는다. 완료된 날짜의 활동 요약 캐시는 기존 일 단위 정책을 유지한다. 활동 요약 키는 v4로 바꾸었으며 해당 사용자·모드의 구형 v1/v2/v3 캐시는 활동 조회 시 제거한다. 프로필 저장 키도 v2로 이전해 이전의 정상처럼 저장된 불완전한 결과를 읽지 않고, 조회한 사용자의 이전 키만 정리한다.

## 유지한 동작과 남은 일

리그의 퀵매치 클랜전·클랜전, 경기 상세 조회, 정산 MMR/HSR 연결, OUID를 기준으로 하는 임시 닉네임 발견·이력 갱신은 유지한다. 새 외부 서비스·DB·유료 의존성은 추가하지 않는다.

## 조회 결과와 재시도

- 모든 요청이 정상이고 `match: []`인 경우만 정상적인 빈 기록으로 처리하고 캐시한다. 목록 배열이 없는 응답은 정상 빈 결과가 아니다.
- 한 유형이라도 실패하면 `MatchQueryError`로 전체 실패(`MATCH_QUERY_FAILED`)·부분 실패(`MATCH_QUERY_PARTIAL`)를 구분한다. 불완전한 유형 집합으로 최종 경기 수·승률·활동 집계를 확정하지 않는다. 화면에서는 별도 안내와 수동 재시도를 제공한다.
- 정상 목록의 30초 메모리 캐시는 유지한다. 재시도 시 실패한 유형만 다시 요청할 수 있으며 자동 반복 요청은 추가하지 않는다. 불완전한 결과는 프로필·경기 유형·활동의 정상 캐시에 쓰지 않는다.
- 경기 유형 전환·더 보기 실패 때 기존 정상 기록은 유지한다. 이전 프로필의 완료/실패가 다음 검색 화면을 덮어쓰지 않는 기존 보호도 유지한다.
- 날짜별 상세 조회의 일부/전체 실패는 0딜·0헤드샷으로 일 단위 상세 캐시에 확정하지 않는다. 실패 안내와 상세 재시도를 표시하고, 경기 유형 탭을 바꾸어도 실패 상태가 기록 없음으로 바뀌지 않는다.
- 활동 무효화 전에 시작한 요청이 늦게 끝나도 새 활동/날짜 캐시를 덮어쓰거나 새 진행 요청을 제거하지 않는다.
- 리플레이 전력은 정상 빈 기록·일부 유형 실패·조회 실패를 선수별로 구분한다. 불완전한 클랜 유형 목록을 전력 점수로 사용하거나 성공한 전력 프로필로 캐시하지 않는다. JSON 기반 무료 분석은 계속 독립적으로 동작한다.

목록이 정상인 최근 경기의 개별 상세 실패 시에는 기존 목록 요약 대체 동작을 유지한다. 모든 선택적 외부 정보의 장애를 다루는 전면 오류 처리 개편은 이 작업 범위가 아니다.

## 검증 근거

로컬 모의로 전체/부분/잘못된 응답의 실패 전파, 빈 결과만 캐시, 실패 후 복구, 활동 무효화 경합, 구형 캐시 이전, 리플레이 상태 문구를 검증한다. PC·모바일 양쪽 테마에서 실제 서비스·캐시·활동 컴포넌트를 연결해 실패 후 재시도와 상세 오류의 0값 방지를 확인한다. 외부 API·운영 DB·유료 AI 호출 없이 수행한다.

모의 공급자 목록으로 중복 요청 병합·30초 만료·키 분리·용량 제한·무효화 경합을 검증한다. 최근 경기→활동→더 보기의 같은 유형 목록 재사용, 한국 날짜 경계, 무승부, 리그 정산과 Tracking→임시 닉네임→Tracking 복귀를 단위 검사한다.

31일 활동의 5개 유형을 기준으로 기존 최대 150회(완료 날짜 30개 × 유형 5개)였던 목록 요청을 캐시가 없을 때 5회로 줄인다. 이 수치는 모의 검사에서 확인한 목록 요청 수이며 전체 API 호출 수·실사용 속도·과금 절감률을 뜻하지 않는다. 프로필·상세 조회는 별도다.
