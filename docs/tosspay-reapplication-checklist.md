심사 결과가 나올 때까지 일반 상품 페이지에서 비회원도 동의 후 토스 TEST 결제창을 확인한다. 회원 구매·운영 결제는 로그인 정책을 유지한다. 공개 페이지는 TEST이며 서버의 `TOSSPAY_REVIEW_ENABLED=true`와 `TOSSPAY_REVIEW_GUEST_ENABLED=true`가 모두 필요하다. 종료 시 비회원 플래그를 false로 바꾸면 새 비회원 요청이 차단된다.

`/api/replay-pass-guest-test`는 start/session으로 24시간 서버 서명 Secure·HttpOnly·SameSite=Lax 호스트 쿠키를 발급·검증한다. 쿠키 왕복을 먼저 검증하므로 차단된 브라우저에서는 주문/Firestore/토스 호출을 시작하지 않는다. 회원가입·Firebase 익명 사용자·추가 비밀값·별도 DB 없이 기존 TEST 전용 원장을 재사용한다. 키는 기존 TEST 서버 값으로 용도별 HMAC을 계산하며 브라우저에 노출하지 않는다. 주문번호나 클라이언트 세션 선택으로 다른 방문자의 주문을 처리할 수 없다. 쿠키·복구 사본이 만료/삭제됐을 때 기존 주문을 새 세션으로 자동 교체하지 않는다.

전체 신규10건/한국 날짜·유효 요청100회/한국 날짜로 제한하며, 기존 누적 카운터는 기록으로 보존하되 한도로 사용하지 않는다. 회원·운영 도구·비회원이 이 일일 한도를 공유한다. 일일 한도 소진 시 당일 신규 주문은 막히며 다음 한국 날짜 요청에서 일일 카운터가 갱신된다. 새 방문이나 새로고침만으로 거래를 만들지 않고, 동의 후 명시적인 구매 클릭에만 생성한다. 같은 브라우저의 진행 중 주문은 중복 클릭·복귀 시 재사용하고 자동 폴링/재시도는 하지 않는다. 이 논리적 한도는 인터넷 요청 전체 또는 클라우드 요금을 강제로 차단하는 보장은 아니다.

다음으로 개발 미리보기 조건의 문구·버전·서버 확인 시각을 기존 주문에 함께 저장하고 재시도 시 보존하는 [확인 기록](replay-coaching-purchase-acknowledgement.md)을 구현했다. 검증은 단위1,029/브라우저11/Emulator9다. 실제 판매 약관 동의나 미확정 환불 조건 승인이 아니며 제공·환불 확정과 운영 연결은 계속 남아 있다.

## 심사 담당자에게 안내할 TEST 순서

1. [상품 안내](https://trackingsa.com/ai-replay-pass/)에서 상품·제공·환불 안내와 푸터 사업자 정보를 확인한다. 무료 기본 분석은 [기존 분석실](https://trackingsa.com/stats/sudden-attack/replay/)에서 계속 사용할 수 있다.
2. 사업자가 승인된 제출 채널로 별도 전달한 접근코드를 입력하고 TEST 확인 항목을 선택한다. **코드/브라우저 비밀값을 공개 문서·URL·스크린샷에 넣지 않는다.**
3. TEST 주문 준비 → TEST 결제창 준비 → 토스 TEST 결제창으로 이동한다.
4. 심사 담당자 본인이 토스 앱 구매자 인증을 완료하고 공식 중간 페이지의 이동 버튼으로 사이트에 돌아온다. 비밀번호/인증번호를 사업자에게 보내지 않는다.
5. 같은 코드를 다시 입력해 기존 TEST 주문을 확인하고, 구매자 인증 후 TEST 승인 확인을 누른다. 새 탭으로 돌아왔으면 보관된 TEST 주문 복구부터 누른다.
6. 승인 확인 완료·실제 이용권 지급 없음 표시를 확인한다. TEST에는 실제 대금·운영 이용권·유료 AI 실행이 없다.
