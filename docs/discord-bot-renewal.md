# Discord 봇 개편

2026-11-07 업데이트. 무료 운영을 위해 **봇은 경기·선수 요약, 웹사이트는 상세 분석**을 담당한다. 구현·배포·실서버 CPU 검증·전체 서버 공개는 별도 단계다.

## 현재 상태

- 선택한 `AimBug님의 서버`에서 검증한 뒤 11월 4일 운영자의 전체 서버 전환 승인을 받았다. 기존 글로벌 `대내모집`·`전적검색`·`라이벌`·`대내전적검색` 정의를 백업하고 `/전적`·`/리플레이`·`/도움말`로 교체했다. 글로벌 등록은 새 서버 초대나 자동 메시지 발송이 아니다.
- 운영 배포 설정은 `DISCORD_REPLAY_ENABLED=true`, `DISCORD_BOT_VERSION=2`다. 새 배포에서 전체 서버 리플레이를 허용하고, 남아 있는 구버전 명령·버튼에는 새 사용법을 비공개로 안내한다. 배포의 플래그와 글로벌 등록 성공을 확인한 후 테스트 서버의 중복 명령 세 개를 제거한다. Discord 클라이언트의 목록 반영에는 시간이 걸릴 수 있다.
- 파일 앞부분 요약과 상세 분석 링크를 구현했다. 11월 4일 기존 카드의 선수 선택 CPU **6ms·3ms**, 실제 첨부 명령의 **21ms**를 관측한 뒤 중복 라우팅을 줄였다. 개선 배포 후 실제 첨부 명령 두 건은 **9ms·3ms**, 정상 비공개 목록 응답이었다. 전체 서버 전환은 같은 분석 코드와 제한을 사용하며, 이 두 CPU 값을 전체 서버의 성능 보장으로 확대하지 않는다.
- 기존 내전 모집용 Cloud Function·세션 데이터·사이트 정산 웹훅은 삭제하지 않는다. 회원·리그·구매 데이터도 정리 대상이 아니다.

## 사용자 흐름

| 명령 | 동작 | 공개 범위 |
| --- | --- | --- |
| `/전적 닉네임` | 기존 넥슨 프록시·캐시로 최근 전적·티어 조회, 상세 전적 링크 제공 | 채널 공개 |
| `/리플레이 파일` | 공식 JSON 하나 첨부 → 선수 선택 → 맵·스코어·K/D/A·피해량 요약 | 결과와 원본 JSON 링크를 기본으로 채널 공개 |
| `/리플레이 파일 공개:거짓` | 같은 요약과 원본 JSON 링크를 요청자에게만 표시 | 명시적으로 나만 보기 선택 |
| `/도움말` | 사용법·JSON 받는 방법·상세 분석 링크 제공 | 요청자만 보기 |

**상세 분석 열기**를 누르면 기존 웹 분석실로 이동한다. 같은 JSON을 다시 선택하면 무료 규칙 기반 핵심 장면·라운드 기록·경기 그래프를 기기 안에서 확인할 수 있다. 링크만으로 파일이나 선수 선택을 자동 이전하지 않는다. 닉네임만으로 리플레이 원본을 수집하지 않는다.

11월 7일 운영자 요청으로 새 리플레이 명령의 기본 응답을 채널 공개로 변경했다. `공개:참`도 계속 지원하며 `공개:거짓`일 때만 요청자 전용으로 응답한다. 선수 선택은 공개 여부와 관계없이 요청자만 15분 동안 가능하다. 공개 카드의 선수를 바꾸면 같은 카드가 갱신되어 모두에게 반영된다. 권한·만료·연속 요청 오류 안내와 도움말은 요청자에게만 표시한다. 기존 메시지의 공개 범위를 소급 변경하지 않는다. 공개 결과를 읽기만 하는 사람을 위한 분석 요청이나 새 DB 저장·AI 호출은 추가하지 않았다.

평균 생존·전술 해설은 라운드 기록이 필요하므로 봇 요약에서 제외한다. 없는 피해량·스코어·승패 정보는 `정보 없음`으로 표시한다. 오래된 상세 보기 버튼 요청도 요청자·만료 시각을 검증하고 새 요약과 웹 안내로 갱신한다. 새 결과에는 상세 보기 버튼을 만들지 않는다.

## 앞부분 읽기와 정확성 경계

- 실제 제공 파일 세 개(약 478KB·881KB·761KB)에서 경기·선수 요약은 라운드 기록 앞에 있었다. 선수 30명의 식별자·닉네임·K/D/A·피해량을 원본 전체 파싱 결과와 로컬에서 대조했다. 개인 파일은 테스트 서버나 저장소로 복사하지 않는다.
- 원본 Discord CDN에 `Range: bytes=0-16383`을 요청한다. 처리·보관하는 접두부는 최대 **16KiB**, 스트림 읽기는 최대 **32회**다. 서버가 범위 요청을 무시해도 접두부만 복사한 뒤 남은 스트림을 취소한다. 이미 전달된 한 청크까지 16KiB 이하였다는 네트워크 수신량 보장은 아니다.
- JSON 루트 `replay_info`의 `replayMatchSummaryInfo`와 `replayCharacterSummaryInfo`만 추출한다. 문자열이나 다른 중첩 객체의 동명 키를 요약으로 오인하지 않는다. 이스케이프·속성 순서·BOM을 처리하고 선수는 1~25명·고유한 안전 식별자로 제한한다. 깊이·멤버 수도 제한한다.
- 두 요약을 찾으면 뒤의 라운드·좌표 기록을 파싱하지 않는다. **전체 JSON의 유효성·사망/재접속 일관성을 검증한 결과가 아니다.** 파일 앞부분에 기록된 요약임을 표시하고 상세 검증은 웹 분석실에서 수행한다.
- 앞부분이 부족하거나 큰 기록이 먼저 나와 요약을 못 찾으면 추가 다운로드 없이 웹 분석을 안내한다. 잘못된 JSON 접두부·유효하지 않은 선수 정보는 오류로 안내한다.
- 첨부 메타데이터의 파일 상한은 2MiB다. 응답의 전체 `Content-Length` 또는 206의 전체 파일 크기가 확인되면 같은 상한을 적용한다. 끝까지 읽지 않으므로 과거의 실제 전체 수신 바이트 검사·32라운드/16,000상태 검사를 수행한다고 표현하지 않는다.

## 데이터·비용 경계

- 파일은 Discord에 업로드되고 봇 서버가 앞부분을 읽는다. 웹사이트의 기기 내 처리와 다르다. 비공개 응답도 Discord에 원본이 남지 않는다는 뜻은 아니다.
- 원본·요약·결과를 Firestore·Storage·Cache API에 저장하지 않는다. 요청자·세션별로 투영한 요약만 Worker 메모리에서 최대 2분간 재사용한다. 최대 4개 항목·읽은 접두부 합계 64KiB이며 라운드 원본·선수별 분석 캐시는 없다. 세션 만료보다 오래 재사용하지 않는다. 만료 항목은 다음 접근에 제거하며 별도 삭제 타이머는 없다. 인스턴스 간 적중은 보장하지 않는다.
- 선수 선택은 요청자만 15분 동안 사용한다. 원본 링크가 먼저 만료되면 재첨부를 안내한다. 명령 5초·선수 선택 2초 간격 제한은 인스턴스 메모리 최대 1,024개 항목으로 적용한다. 전역 사용자 한도나 과금 차단 기능은 아니다.
- 생성형 AI 호출·결제·이용권 조회/차감·새 DB·큐·상시 실행 서버·유료 플랜을 추가하지 않는다. 웹 분석의 기존 무료/유료 경계도 바꾸지 않는다.
- 서명된 요청과 Discord 원본 CDN의 일반/임시 첨부 경로만 허용한다. 임의 URL·리디렉션은 거절한다. 다운로드·결과 갱신은 각각 최대 5초이며 자동 재전송하지 않는다. 토큰·원본 JSON·서명된 첨부 URL을 로그로 남기지 않는다.
- Discord에는 먼저 대기 응답을 보내고 비동기로 갱신한다. 후속 응답 토큰 15분과 Cloudflare CPU/`waitUntil` 기한은 구분한다.

위 CPU는 Cloudflare 실시간 로그의 CPU 필드이며 경과 시간(각 180ms·687ms)과 다르다. 카드 생성은 로컬에서 수행하여 Worker 캐시를 미리 채우지 않았다. 첫 선수 선택에서 파일 접두부 읽기와 요약 추출이 함께 발생했다. 화면 조작 도구의 좌표/캡처 오류로 선택은 사용자가 수행했고 결과는 앱 접근성·Bot API·실시간 로그로 확인했다. 원본·토큰·서명된 첨부 URL을 로그 파일에 보관하지 않았다.

앞선 두 선수 선택 요청은 무료 CPU 기준 아래였지만, 뒤이어 실제 첨부 명령에서는 21ms를 관측했다. 어느 값도 p95나 모든 트래픽의 보장으로 사용하지 않는다. 실제 첨부의 비공개 응답은 확인됐으나 첫 실행 비용인지 반복되는 비용인지 원인을 확정하지 못했다. 이 관측 하나만으로 검증된 분석 규칙을 바꾸거나 유료 서비스를 추가하지 않는다.

## 첫 실행·반복 실행 분석과 라우팅 개선

- 운영 코드 변경 전 재실행 구간의 전체 로그는 **13ms·4ms·3ms·3ms·4ms**, 모두 성공·예외 없음이었다. 초기 값이 상대적으로 높지만 요청별 인스턴스와 슬래시/선수 선택을 로그에 저장하지 않아 21ms의 원인을 확정한 것으로 해석하지 않는다. 배포도 이전 관측과 다르므로 단순 개선율로 사용하지 않는다.
- 로컬 workerd에서 실제 파일 세 개를 사용해 같은 서명 검증·같은 접두부·같은 응답 코드를 대조했다. 기존 Pages 경유 요청마다 경로 매칭 함수가 **20회** 생성됨을 계수했다. Pages 어댑터를 뺀 로컬 대조군도 만들었으며, 이 대조군은 운영에 배포하지 않는다.
- `functions/_middleware.js`에서 고정된 디스코드 URL만 기존 서명 검증 핸들러로 먼저 전달해 매칭 생성을 **2회**로 줄였다. 서명·시각·본문 크기·앱 ID 검증은 그대로 같은 핸들러가 수행한다. 다른 요청은 `context.next()`로 기존 Pages 처리를 이어 간다.
- 루트 미들웨어 때문에 정적 트래픽이 Functions로 유입되지 않도록 원본 `_routes.json`과 빌드 복사 규칙을 추가했다. 호출 범위는 `/api/*`이며 홈·가이드·리플레이 HTML·JS·이미지는 정적으로 제공한다. 산출물 검사와 회귀 검사에서 이 범위를 강제한다.
- 로컬 기존/수정 번들의 API·정적 경로 13개를 대조해 응답이 같음을 확인했다. 외부 통신은 모의하고 ASSETS는 로컬 스텁이므로 실제 외부 서비스까지 검증한 결과는 아니다. 서명 검증·비공개 첨부·선수 선택도 workerd에서 다시 확인했다.
- 로컬 경과 시간이나 프로파일의 샘플 간격 합계는 운영 CPU 시간이 아니다. 로컬 샘플에는 대기·스케줄링 지연이 섞일 수 있어, 이를 원인별 CPU 밀리초로 더하지 않는다. 확인된 중복 작업만 줄인 변경이며 **21ms가 완전히 해결됐다는 주장은 운영 재측정 전까지 하지 않는다.**

개선 커밋 `e34faf61` 배포에서 실제 첨부 명령을 두 번 다시 실행했다. 비공개 목록은 사용자가 확인했고 Cloudflare 로그의 CPU는 **9ms·3ms**였다. 첫 결과의 4,476ms는 네트워크 대기를 포함한 경과 시간으로, CPU 9ms와 구분한다. 사이트·분석실과 API의 비변경 GET 점검도 기존 예상 상태와 일치했다. 이번 두 요청은 무료 기준 안이지만, 서로 다른 배포의 적은 표본을 일정한 개선율이나 모든 최초 요청의 보장으로 사용하지 않는다. 21ms를 만든 비용을 전부 특정한 것은 아니며, 확인한 중복을 줄인 뒤 실제 요청을 재검증한 결과다.

실제 슬래시 시험의 첨부는 사용자가 직접 선택했으며 앞서 에이전트가 준비한 6명 가상 파일과 같다고 가정하지 않는다. 원본·파일명·선수 정보·서명된 첨부 URL을 검증 기록에 저장하지 않았으며, 응답 성공·비공개 여부·선수 수·CPU/경과 시간만 기록했다.

10월 30일 이전 전체 분석 방식에서는 약 472KB 가상 파일 첫 처리가 CPU 38~42ms, 이후 보기는 3~21ms였다. 숫자 포맷 초기화·거리/투척물/코칭 근거 계산을 줄여도 무료 실행 범위를 검증하지 못해 전체 파싱을 없애는 현재 구조로 변경했다. 이전 봇 전용 `analyzeReplaySummary`와 전용 검사는 정리했으며 웹사이트 전체 분석 엔진은 유지한다. 과거 CPU 수치를 현재 성능으로 표기하지 않는다.

에이전트가 업로드하는 실서버 검증 파일은 개인 정보 없는 가상 JSON만 사용한다. 실제 슬래시 첨부·선수 선택·요약·웹 링크·만료/권한 오류를 확인하고, 기존 계정의 무료 범위와 첫 요청/재다운로드 CPU를 확인한 뒤 전체 공개를 결정한다. 무료 범위에 맞지 않으면 유료 자원을 기본 해결책으로 추가하지 않는다.

## 등록·전환 절차

이번 전환에서는 글로벌·테스트 서버의 원래 명령 정의를 저장소 밖 로컬 파일로 각각 백업했다. Cloudflare 운영 설정의 기존 환경 변수 14개를 보존하면서 전환용 플래그 두 개만 추가했다. 서명 검증·기본 비공개 응답·구버전 저장 작업 차단·등록 백업을 포함한 관련 단위 테스트 28개를 다시 통과했다. 전체 단위 1,177개와 실서버 CPU 값은 위 검증 시점의 결과이며, 새 배포의 첫 실행 CPU를 다시 측정한 값은 아니다.

운영 배포가 성공하고 실제 배포에 두 플래그가 포함되었는지 확인한 후 글로벌 세 명령과 테스트 서버 중복 제거 결과를 다시 조회한다. 이 과정은 다른 서버의 개별 명령 설정·세션 데이터·Cloud Function·웹 결제 설정을 변경하지 않는다. 원복이 필요하면 백업 정의로 글로벌 명령을 복구하고 두 플래그를 이전 상태로 되돌린 새 배포가 필요하다.

1. `node scripts/register-discord-commands.js`는 네트워크 없는 미리보기다.
2. 코드 검증·배포 후 선택한 서버에만 `--guild TEST_SERVER_ID --apply --backup C:\path\commands-before.json`으로 등록한다. 조회·새 파일 백업 성공 후 교체하며 실패 시 중단한다. `.env` 토큰은 출력하지 않는다.
3. 무료 실행 범위와 사용자 흐름을 검증한다. 기존 글로벌 명령은 유지한다.
4. 전체 공개 결정 후 운영 명령을 백업하고 `--global --apply --backup ...`으로 교체한다. 기존 글로벌 목록 전체를 교체하는 명령이다. 구버전 종료·리플레이 활성화 플래그와 중복 테스트 서버 명령을 함께 점검한다.
5. 실제 사용이 끝난 구버전 핸들러·브리지·함수·보존 데이터의 정리 범위를 별도로 결정한다. 등록 도구는 Cloud Function·DB를 삭제하지 않는다.

## 구형 경로 분리 (2026-11-07)

운영의 `DISCORD_BOT_VERSION=2`에서는 과거 내전 모집·전적 명령, 오래된 버튼·모달에 비공개 전환 안내를 반환한다. 이 분기는 구형 어댑터를 import하기 전에 끝나므로 구형 세션 RPC·Firestore 조회·팀 나누기 처리로 넘어가지 않는다. `/전적`, `/리플레이`, `/도움말`과 `rp2:` 선수 선택은 기존 v2 경로를 유지한다.

`functions/api/discord-interaction.js`는 64KiB 본문 제한·원본 본문 Ed25519 서명·5분 시각·앱 ID 검증과 라우팅을 담당한다. 검증을 통과한 구형 요청만 `functions/discord/legacy-handler.js`를 지연 로딩한다. 어댑터에는 원래 Request와 서명된 본문 문자열을 그대로 넘기며, 기존 모집 세션 서비스에 재전달할 서명을 재생성하지 않는다.

구형 어댑터는 기존 원복 절차를 위해 보존했다. 이전과 같이 v2 플래그를 해제한 배포에서는 구형 경로가 동작할 수 있다. 명령 등록·환경 플래그·Cloud Function·기존 세션/정산 데이터는 이 정리로 변경하거나 삭제하지 않는다. 원복은 기존 명령 백업 복구와 플래그 변경을 포함한 별도 운영 작업이다. 코드를 분리한 것만으로 CPU 시간이나 무료 실행 한도 개선을 보장하지 않는다.

`tests/unit/discord-ingress-routing.test.js`는 v2에서 구형 모듈을 로딩하지 않음, Ping/새 도움말, 원복 시 검증된 원본 전달, 서명·시각·크기·앱 ID 거부 순서를 확인한다. 기존 native 서명·빠른 디스패치·구형 세션 브리지·v2 봇 검사도 함께 유지한다. 외부 Discord 메시지나 실제 세션 기록을 생성하지 않는 모의 검사다.

- `functions/discord/bot.js`, `messages.js`, `commands.js`: 응답·권한·도움말·명령 정의
- `functions/discord/profile.js`: 기존 넥슨 프록시 기반 전적 조회

- `scripts/discord-command-registration.js`: 미리보기·백업 후 명령 등록
