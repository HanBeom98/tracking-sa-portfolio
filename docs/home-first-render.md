# 홈 첫 화면 표시 개선

2026-10-24. 홈에서 `runtime-config.js`, `translations.js`, `common.js`를 동기 스크립트로 실행해 HTML 파싱이 멈추던 구간을 제거했다. 빌드할 때 홈에만 `defer`를 붙인다. 다른 페이지는 기존 실행 방식을 유지한다.

세 스크립트의 문서 순서를 유지해 런타임 설정과 공통 전역 함수가 홈 모듈보다 먼저 준비되도록 했다. 기존 인증 로더는 그대로 연결되며, 로그인 복원을 사용자 클릭까지 미루지 않는다. 이 첫 단계에서는 광고 SDK, CSS, 공지 표시 정책과 화면 디자인을 바꾸지 않았다. 이후 홈 CSS의 전달 방식은 별도 [비교 실험과 후속 변경](home-css-delivery.md)으로 기록한다.

## 통제된 로컬 비교

Chromium, 390×844 CSS px, CPU 4배 감속, 네트워크 지연 150ms·다운로드 200,000 bytes/s·업로드 100,000 bytes/s, 캐시·서비스 워커 비활성. 외부 Firebase·광고·분석 서비스는 차단했다. 변경 전 HTML과 새 빌드 HTML을 같은 로컬 서버·브라우저에서 각각 새 컨텍스트로 3회 측정했다. 변경 전 세 번을 먼저 측정했으므로 실행 순서에 따른 변동 가능성이 있다.

| 지표 | 변경 전 중앙값 (범위) | 변경 후 중앙값 (범위) | 중앙값 차이 |
| --- | --- | --- | --- |
| FCP | 1,204ms (1,176–1,228) | 828ms (828–880) | −376ms, 약 31% |
| LCP | 1,204ms (1,176–1,228) | 828ms (828–880) | −376ms, 약 31% |
| DOMContentLoaded 종료 | 1,443ms (1,398–1,468) | 1,082ms (1,063–1,149) | −361ms, 약 25% |

LCP 관찰기의 요소 태그는 양쪽 모두 `::after`였다. 홈에는 장식용 `SA` 가상 요소가 있으나 이 결과만으로 본문 제목을 LCP 대상이라고 단정하지 않는다. 로컬 FCP/LCP가 같은 시각에 기록됐다는 점도 해석에 포함한다. 이 표는 실제 사용자 데이터나 운영 PageSpeed 점수가 아니며, 과거 PSI 60점에서 얼마나 상승했는지는 새 운영 측정 전까지 미확인이다. 외부 서비스의 실행 비용과 실제 모바일 기기 편차는 이 비교에 포함하지 않는다.

## 회귀 확인

- 브라우저에서 위 스크립트 세 개를 각각 응답 대기 상태로 두어도 홈 제목과 검색 입력창이 먼저 표시된다.
- 응답 재개 후 SOOP는 설정된 페이지 모드로 요청하며, 로그인 버튼과 테마 전환이 초기화된다.
- 홈에만 적용되는 빌드 분기, 공통 스크립트 순서와 기존 인증 로더 보존을 Python 테스트로 확인한다.
- `npm run test:e2e:auth:local`의 실제 로컬 Firebase SDK·에뮬레이터 검증으로 로그인·공지 흐름을 확인한다.

별도 분석 SDK, 서버 요청, 저장소나 유료 자원은 추가하지 않았다.
