# 일반 구매 화면과 운영 구매 모듈 연결 준비

2026-10-27. 내부 결제·지급·구매 내역 모듈을 운영용 조합 경로와 일반 상품 화면에 연결했다. **현재 공개 화면은 계속 TEST이며, 이 변경으로 실제 판매·운영 결제·유료 AI를 활성화하지 않는다.** 운영 함수 배포나 LIVE 키 조회도 실행하지 않는다.

## 연결한 흐름

일반 상품 화면 → 고정된 `/api/replay-coaching-purchase` 전송 → `replayPurchase` 조합 경로 → 인증·조건 확인·기존 주문/결제 바인딩 → 공급자 상태 검증 →20회 지급 → 본인 구매 내역 조회다. 브라우저의 UID·금액·성공 파라미터나 임의 콜백을 지급 근거로 사용하지 않는다. 브라우저 인증 토큰은 요청에만 사용하고 복구 정보에는 주문번호와24시간 기한만 보관한다.

운영 UI는 배포 소스의 `data-purchase-mode="LIVE"`에서만 선택한다. 현재 HTML은 `TEST`다. URL의 mode/query를 바꿔 운영 경로를 켤 수 없다. 브라우저에서 DOM을 바꾸더라도 운영 API의 독립된 서버 차단을 해제하지 못한다. 기존 loopback 전용 개발 전송도 호환 유지한다.

## 기본 차단과 활성화 조건

| 항목 | 현재 상태 |
|---|---|
| 공개 상품 모드 | TEST 유지 |
| Cloudflare 운영 브리지 | 소스 준비, 기본 차단; 실제 배포 미실행 |
| Firebase `replayPurchase` | 소스의 명시적 미배포 함수, 정기 배포 대상에서 제외 |
| `REPLAY_PURCHASE_ENABLED` | 기본 비활성 |
| `REPLAY_MERCHANT_APPROVED` | 기본 비활성, 토스 승인으로 자동 설정하지 않음 |
| `REPLAY_SALES_ENABLED` | 기본 비활성; 신규 주문·결제 시작만 별도 중단 가능 |
| 정식 판매 조건 문서 | 실제 문서를 배포 진입점에 주입하지 않음 |
| 실제 LIVE 결제 제공자 | 배포 진입점에 주입하지 않음. 토스 실거래 어댑터·키는 승인 후 별도 연결 필요 |

플래그만 true로 바꿔도 실제 문서와 LIVE 제공자가 없으면 서버가 인증/DB/공급자 호출 전에 차단한다. TEST 제공자를 LIVE처럼 바꿔 주입하거나 공용 TEST 거래를 실제 지급 원장에 반영하지 않는다. 새 운영 함수·비밀값·콜백 서비스·유료 업그레이드를 만들지 않았다.

신규 판매만 일시 중단하는 `REPLAY_SALES_ENABLED=false` 상태에서는 이전에 시작한 동일 소유자 결제의 확인·지급 완료와 구매 내역 조회를 유지한다. 전체 구매 경로를 끄는 전역 플래그와 구분하며, 이미 돈이 이동했을 가능성이 있는 주문을 새 결제로 재시도하지 않는다.

## 구매 조건 확인 기록

기존 개발 문구는 `purpose: preview`로 유지한다. 운영 경로는 신뢰한 서버 문서의 `purpose: sale`과 상품 조건을 함께 해시하고 문구·버전·최초 서버 확인 시각을 기존 주문 문서에 기록한다. 클라이언트는 accepted/version/digest만 제출하고 본문·가격·시각을 만들 수 없다. 예전 개발 확인만 있는 미결제 주문은 운영 결제를 시작하지 못한다. 이미 지급한 과거 주문의 조회나 구매 당시 단가는 소급 변경하지 않는다.

현재 공급자 포트의 계약은 `mode: LIVE`, 생성/상태 조회/승인 메서드와 서버가 검증한 결제 완료 시각이다. 브라우저나 콜백의 시간으로365일을 계산하지 않는다. 이 연결 준비가 실제 판매 약관의 법적 적합성이나 심사 승인을 보장하지 않는다.

## 검증 범위

로컬 합성 LIVE 포트와 demo Firestore에서 소유자 검증, 정상20회 지급, 구매일부터365일 만료, 동시/중복 요청, 승인 응답 유실 복구, 본인 내역, 신규 판매 중단 중 기존 결제 완료, TEST/미리보기 확인 기록의 운영 지급 차단을 검사한다. 합성 포트의 LIVE 표시는 프로토콜 시험값이며 실제 토스 실거래를 실행한 것이 아니다.

기존 TEST 구매 화면과 운영용 모의 화면을 같은 상품 HTML에서 각각 검증한다. 새 운영 모드는 테스트에서만 HTML 응답을 전환하며 공개 소스의 TEST 설정은 유지한다. 추가 실제 결제나 유료 AI로 원가/품질 시험을 반복하지 않는다.

## 승인 후 남은 작업

토스 결과와 실제 가맹점 키/약정 확인, 정식 판매 조건·개인정보/결과 보관 기준 확정, LIVE 상태/결제 시각을 엄격히 정규화하는 실제 제공자 연결, 운영 함수·브리지 배포와 제한된 최종 검증이 필요하다. 환불 접수·운영 처리 화면과 유료 AI 활성화는 이 단계에서 켜지 않는다. 승인 전에 가짜 판매 완료나 실제 지급 완료를 공개하지 않는다.
