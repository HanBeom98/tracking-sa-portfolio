공식 API 최근 지표, 선택한 경쟁 모드 분석 구간, 31일 활동의 기준은 각각 기존 로직을 유지한다. 경기 유형을 바꾸면 기존대로 해당 유형의 분석과 기록을 표시한다. 전체 최근/이전 비교와 최신 흐름 평가도 기존 범위를 유지한다. 흐름 평가의 근거는 접었다 펼칠 수 있으며 제목과 변화 수치는 바로 보인다.

`public-result-tabs.js`는 표시·키보드 이동만 조정한다. `player-card.js`가 활동 패널·선택 날짜·요청 캐시·재시도를 소유한다. 활동 패널은 외부 탭 영역에 붙이되 컴포넌트가 같은 노드를 계속 참조한다. 같은 프로필의 분석 구간/경기 유형 전환은 프로필 컴포넌트를 재사용해 활동을 다시 조회하지 않는다. 활동을 처음 열기 전에는 상세 활동 API를 호출하지 않는다.

새 검색·초기화·VS 비교 진입 시 탭과 외부 활동 영역을 정리한다. VS 및 리그는 탭 분할을 적용하지 않고 기존 프로필/비교 흐름을 사용한다. 공유 카드와 즐겨찾기·새로고침도 기존 동작을 유지한다. 새 패키지·서버·DB 저장·측정 이벤트는 추가하지 않는다.

검증은 로컬 fixture로 실제 뷰와 컴포넌트를 실행한다. 공식/자체 지표 보존, 탭/방향키, 활동 지연 조회 및 재사용, 구간 변경 후 선택 날짜 유지, 유형 전환·더보기·초기화·VS를 확인한다.

단위 1,255개와 관련 브라우저 44개 검사를 통과했다. 결과 탭 흐름은 320·390·1,280px의 밝은/어두운 테마에서 확인했다. 외부 서비스 요청을 차단한 로컬 fixture 검사이며 실제 사용자의 성능 향상이나 운영 배포 완료를 의미하지 않는다. 기존 검사 안에 탭·캐시 보존 시나리오를 확장했으며 같은 구현을 확인하는 별도 단위 검사를 중복 추가하지 않았다.

## 경기 목록 가독성 정리

공개 검색의 요약을 PC에서는 정렬된 행으로, 800px 이하에서는 두 줄로 표시한다. 기존 리그 카드·정산 표시는 유지한다.

| 화면 | 접힌 요약 | 펼친 기록 |
| --- | --- | --- |
| PC | 승패·작은 맵 이미지/이름·유형·K/D/A와 KD·헤드샷·딜량·경기 일시 | 기존 팀별 선수 상세 |
| 모바일 | 승패·맵·일시 / 유형·K/D/A | 내 KD·헤드샷·딜량과 기존 팀별 선수 상세 |

워터마크는 공개 요약에서 제거한다. 이미 조회한 데이터만 사용하고, 상세를 여는 동작에도 새 요청을 추가하지 않는다. 날짜·시간은 한국 시간으로 표시하고, 유효하지 않은 일시는 `시간 미확인`으로 표시한다. 값이 없는 요약 지표는 `—`, 확인된 0은 0으로 구분한다. 승리·패배·무승부·탈주·결과 미확인은 색과 문구를 함께 사용한다. 긴 맵명·유형의 전체 텍스트는 접근성 이름과 title에 유지한다.

공개 요약은 native button을 사용하며 기존 펼치기·접기, `aria-expanded`, 키보드 Enter/Space, 상세 선수 이름 클릭, 로컬/원격 더보기를 유지한다. 빈 목록·로딩은 기존 처리를 따른다.

후속 검증: 전체 단위 1,255개, 관련 브라우저 27개 통과. 이 중 새 목록 검사는 320·390·1,280px × 두 테마 6개와 페이지네이션·리그 보존 1개이다. 정상/미확인·0값·탈주 표시·문자열 이스케이프·상세 12명 보존·요약 높이와 넘침·API 호출 없음도 포함한다. 테스트는 loopback의 가상 데이터이며 운영 조회·DB·실결제·유료 AI를 사용하지 않는다.

## 최근 흐름 비교 그래프

기존 승률·킬뎃 차이 카드에 이전/최근 구간의 실제 비율을 막대로 함께 표시한다. 두 지표 모두 0~100%의 동일한 눈금을 사용하며 시간별 추세나 경기별 기록을 만들어내지 않는다. 회색은 이전, 강조색은 최근이며 각 행에 기간과 수치를 적어 색 없이도 구분한다. 구간별 경기 수, 변화량(%p), 기존 평가 문구와 펼칠 수 있는 근거·집계 기준을 유지한다.

이전 구간이 7경기 미만이거나 없으면 그래프를 그리지 않고 비교 표본 부족을 표시한다. 이전 구간이 없는 경우 최근 구간을 복사해 비교하던 presenter의 fallback도 제거했다. 확인된 0%는 빈 막대와 0.0% 숫자, 100%는 전체 막대로 표시한다. 작은 화면은 두 지표를 세로로 배치한다. 기존 집계·API·저장·의존성에는 변경이 없다.

전체 단위 1,258개 및 기존 전적 결과 브라우저 검사 6개(320·390·1,280px × 두 테마)가 통과했다. 기존 검사를 확장해 실제 막대 길이, 표본 부족, 제목·수치 일치, 근거 열기, 탭·경기 유형·이전 구간 전환 보존을 확인했다. 이후 CI 브라우저 217개와 운영 파일 확인을 완료했다. 데이터 검증에는 가상 통계만 사용했다.

## 공개 경기 상세 디자인

공개 경기 상세는 `public-match-scoreboard.js`가 렌더링한다. 기존 리그 정산·MMR/HSR·경고와 선수 이름 클릭 검색은 유지한다. 공개 요약 행의 크기와 펼치기·접기 동작도 유지한다.

- 기존 맵 사진과 경기 결과를 배너로 표시한다. 사진은 상세를 처음 펼칠 때만 src를 설정하며 실패하면 기본 배경으로 표시한다. 공통 사이트 메뉴의 전역 header 스타일이 간섭하지 않도록 일반 컨테이너를 사용한다.
- 조회 선수 K/D/A·킬뎃·헤드샷 횟수·딜량을 먼저 보여준다. 원래 반올림된 값을 그대로 사용하며 새 스코어·MVP·평가를 계산하지 않는다.
- 전체/팀 필터는 현재 상세 안에서만 동작한다. 무승부는 팀 ID로 구분하고 ID가 불충분하면 전체 참가자로 표시한다. 팀·결과 미확인 행도 삭제하지 않는다.
- 딜량 막대는 제공된 전체 참가자 목록의 최다 딜량에 대한 상대 길이다. 팀 필터를 바꿔도 기준은 유지한다. 숫자도 함께 표시하며 없는 값은 `—`, 확인된 0은 0으로 구분한다.
- 모바일은 선수·K/D/A·딜량을 먼저 표시하고 native details에서 선수별 킬뎃·헤드샷 비율을 펼친다. 선수 이름은 기존대로 전적 검색 버튼이다. 손가락 입력 환경에서는 두 동작의 높이를 44px 이상으로 확보한다.
- 상세 참가자가 없어도 기존에 제공된 조회 선수 요약을 남긴다. 날짜는 한국 시간이며 미확인 맵에는 다른 맵 사진을 붙이지 않는다.

새 API·DB·분석 이벤트·패키지는 추가하지 않는다. 로컬 가상 데이터로 단위 1,262개, 관련 브라우저 20개를 검증했다. 두 테마의 PC·모바일, 12명 무승부·팀 미확인·승리·문자열 이스케이프·이미지 실패·0 딜량·상세 없음·리그 보존·전적 검색/탭 흐름을 포함한다.
