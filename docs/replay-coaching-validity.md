# AI 이용권: 결제 완료일부터 365일

2026-10-27. **판매가 꺼진 내부 구매 경로의 로컬 구현·검증 기록**이다. 공개 심사용 TEST와 운영 이용권은 계속 분리한다. LIVE 연결·실제 판매·재접수·미확정 환불 조건 승인은 이번 작업에 포함하지 않는다.

## 변경 이유와 동작

기존 상품은 고정 만료일(`expiresAt`) 또는 만료 미지정(`null`)을 받았다. 고정 날짜만으로는 구매자마다 다른 결제일부터 365일을 제공할 수 없다. 지급 복구 시각부터 계산하면 복구 때 이용 기간이 늘어나는 문제도 생긴다.

새 상품 설정은 `validDays: 365`를 지원한다. 초기 가격 3,300원·50회·자동 갱신 없음은 유지한다.

| 단계 | 기준 |
|---|---|
| 상품·미결제 주문 | 구매 당시 `validDays` 보관. `paidAt`·`expiresAt`은 null. 화면은 ‘결제 완료일부터 365일’ 표시 |
| 검증된 결제 완료 | 서버 결제 조회가 확인한 `paidAt`부터 `365 × 24시간` 계산. 주문과 지갑 lot에 같은 만료일 저장 |
| 지연 지급·장애 복구 | 최초 결제 완료 시각 유지. 복구일 기준으로 기간을 연장하지 않음 |
| 중복·동시 완료 | 같은 결제는 한 번만 지급. 만료일도 유지 |
| 만료 정각 | `현재 시각 >= expiresAt`이면 새 분석 잔액에서 제외. 기존 기록을 자동 삭제/환불하지 않음 |
| 상품 변경 | 새 주문에만 새 가격·횟수·버전·기간 적용. 기존 지급·환불은 구매 당시 조건 유지 |

기존 고정 만료일·만료 미지정 주문은 그대로 지원한다. 기간은 정수 1~365일만 허용하고, 상대 기간과 고정 만료일을 동시에 지정하면 거절한다.

## 검증 경계

- 상대 기간 지급은 명시적 LIVE 증빙과 서버가 확인한 결제 완료 시각이 모두 필요하다. 누락·잘못된 형식·주문 이전·현재보다 미래·계산 범위 초과 시 지급을 보류한다. 현재 시각으로 대체하지 않는다.
- HTTP 요청은 가격·기간·결제 시각을 받지 않는다. 검증 포트는 요청자가 추가한 시각을 증빙으로 복사하지 않는다.
- 비공개 결제 바인딩에 구매 당시 기간을 보관한다. 지급 후 계산되는 만료일과 변경 불가능한 구매 조건을 구분한다.
- 만료 검사는 기존 분석 요청 경로에서 수행한다. 새 DB 컬렉션·예약 작업·추가 주기 조회·유료 의존성은 없다.
- 기존 50회/3,300원 주문의 49회 금액이 `49 × 66 = 3,234원`으로 보존됨을 검증했다. 실제 환불 실행이나 추가 환불 정책 확정은 아니다.

| 검증 | 결과 |
|---|---|
| 전체 단위 테스트 | 1,008개 통과 |
| 구매 화면 브라우저 | 8개 통과, 390px·1280px 표시/복귀/복구 포함 |
| 로컬 Firestore Emulator | 10개 통과, 트랜잭션 경쟁·지연 복구·서버 전용 접근 포함 |
| 빌드·생성물 | build, source-of-truth, public-edit-policy, build-artifacts 통과 |

결제·지급 지연, 승인 응답 유실, 중복 지급, TEST 증빙 거부, 만료 직전/정각/직후, 상품 변경 후 기존 주문 보존, 손상된 기간·만료일을 검사했다. 외부 결제나 유료 AI 호출 없이 합성 제공자 응답과 demo Emulator를 사용했다.

## 남은 연결

LIVE 어댑터는 아직 주입형 인터페이스이며 운영 키를 연결하지 않았다. [토스 상태 조회 문서](https://docs-pay.toss.im/reference/common/status)의 결제 완료 시각 `paidTs`를 서버에서 밀리초 `paidAt`으로 정규화하는 작업과 실제 가맹점 환경 검증이 필요하다. TEST 어댑터를 운영 증빙으로 재사용하지 않는다.

후속으로 [회원 구매 내역·잔여 횟수 조회](replay-coaching-purchase-history.md)를 로컬 구현했다. 운영 HTTP 경로·약관 동의 기록·실제 계정/AI 연결·환불 운영 절차는 판매 전에 남아 있다. [조건 제안](replay-coaching-sales-conditions.md)과 [재심사 체크리스트](tosspay-reapplication-checklist.md)를 따른다. 이번 작업은 원본 코드 반영까지이며 Cloudflare/Firebase 배포·판매·재접수는 수행하지 않았다.
