# 상품 페이지의 해설 결과 구성 예시

2026-10-29. 7번 상품 결과 예시의 구현·검증 기록이다. 실제 공개 버전은 [현재 상태](current-status.md)의 배포 확인 방법으로 대조한다. [문서 목차](README.md).

## 공개 화면 구성

`/ai-replay-pass/#result-example`에서 비회원도 예시를 확인한다. 페이지 첫 안내의 ‘결과 예시’ 링크로 이동하며, 기존 TEST 구매·무료 비교 영역 뒤와 제공·환불 조건 앞에 배치한다. 실제 주문을 만들거나 로그인해야 예시를 볼 수 있는 구조가 아니다.

- 첫 문장에 **가상 경기에서 수동 선택한 구성 예시이며 실제 AI 생성 결과가 아님**을 표시한다.
- 분석실의 첫 번째 가상 샘플(체험 플레이어·6라운드)을 그대로 사용한다. 실제 회원·다운로드 경기의 닉네임이나 식별자를 넣지 않는다.
- 현재 해설의 사실·질문·행동 목표를 카드 3개로 보여준다. 첫 사건과 개인/팀 결과, 사망 전 인원 변화, 다음 경기 과제를 각각 확인할 수 있다.
- 각 카드에 사실·복기 질문·다음 경기 연습 목표·확인 한계를 표시한다. 실제 분석은 카드 수와 내용이 달라지고 항상 3장을 제공하는 것은 아니라고 안내한다.
- 무료 분석실로 연결하고 ‘샘플로 한 경기 체험’ 버튼을 안내한다. 이 체험에 유료 AI 선택이 포함되지 않음을 구분한다.

예시의 1라운드 첫 처치는 8.0초지만 팀은 패배한다. 2라운드는 시작 5대5에서 18.0초 본인 사망 직전 본인 포함 5대4이고 팀은 승리한다. 이 수치는 시작 인원·사망 직전 인원·개인 결과·팀 결과를 혼동하지 않도록 현재 계약으로 조립한 것이다. 좋은 판단이나 사망 원인을 입증하는 문구로 바꾸지 않는다.

## 생성과 유지보수

브라우저에는 정적 HTML·CSS만 추가한다. 생성 도구 `scripts/replay-product-example.mjs`는 개발 환경에서 가상 JSON → 기존 분석 근거 → 현재 사실/목표 선택 검사·주제 중복 정리 → 해설 카드 조립을 실행한다. 공급자·운영 DB·비밀 키를 읽거나 AI를 호출하지 않는다. 예시에 사용한 선택은 편집자가 고정한 값이며 모델 응답이라고 기록하지 않는다.

```powershell
node scripts/replay-product-example.mjs --check
node scripts/replay-product-example.mjs --write
```

`--check`는 현재 계약으로 만든 예시와 원본 HTML이 일치하는지 확인한다. 계약이 바뀌면 새 문구를 검토한 뒤 `--write`로 한 쌍의 전용 마커 안만 갱신하고 빌드한다. 제공·환불·TEST 주문 코드는 생성 대상이 아니다. 기본 단위 검사에도 예시와 현재 계약의 일치 검사를 포함한다.

현재 화면은 실제 모델의 선택 품질이나 유료 코칭 효과를 검증한 결과가 아니다. 기존 제한된 실제 시험 기록은 [심화 해설 검증](replay-coaching-depth.md), 상품 조건은 [확정안](replay-coaching-sales-conditions.md)을 따른다.

## 검증과 비용 범위

단위 검사는 현재 근거·질문·행동 목표 일치, 예시 원본의 갱신 여부, HTML 이스케이프와 마커 밖 보존을 확인한다. 브라우저 검사는 390/1280px×밝은/어두운 테마, 비회원 공개·예시 고지·카드 배치·넘침·무료 샘플 연결을 확인한다. 예시 조회와 샘플 체험에서 API 요청 0건·페이지 오류 0건을 확인했다.

예시를 위해 브라우저 JS·API·DB·분석 이벤트·유료 AI 호출을 추가하지 않는다. 기존 결제 동의·20회/3,300원/365일·환불 안내·비회원 TEST 경로는 유지한다. 이 문서는 실제 판매 활성화나 토스 승인 완료를 뜻하지 않는다. 정적 페이지 전송량까지 0바이트이거나 호스팅 비용이 언제나 0원이라는 의미는 아니다.
