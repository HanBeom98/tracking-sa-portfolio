# 제품 측정 보고서와 기준 데이터

작성일·무료 운영 범위 조정일: 2026-10-23. 성장 체크리스트 6번 **진행 중**. GA 맞춤 정의와 탐색 7개 탭을 저장·재진입 확인했다. 이후 재확인에서 production/v1 행과 점검 분리 조회를 확인했다. 다만 등록일 부분일·배포 전후가 섞인 자료이며 완료일 기준 구간은 아직 확보하지 못했다. 사용자의 필수 조건인 [추가 과금 없는 운영](free-operation-policy.md)에 따라 BigQuery 연결안을 철회했다. 정확한 p50/p95·순서 있는 세션 비율은 현재 범위에서 미산출로 남기며 완료 필수 조건에서 제외한다.

## 등록한 분석 항목

아래 14개는 모두 이벤트 범위의 낮은 종류 수를 가진 분류다. 기기·날짜·운영체제·브라우저·이벤트 이름은 GA 기본 차원을 사용한다. 닉네임·OUID·시도 ID·세션 ID·시간값을 새 맞춤 측정기준으로 등록하지 않는다.

| 보고서 표시 이름 | 원본 매개변수 |
| --- | --- |
| SA 트래픽 구분 | traffic_scope |
| SA 측정 버전 | measurement_version |
| SA 검색 진입점 | entry_point |
| SA 결과 상태 | outcome |
| SA 검색 결과 표시 | result_shown |
| SA 결과 출처 | result_source |
| SA 백그라운드 갱신 | revalidation |
| SA 오류 코드 | error_code |
| SA 즐겨찾기 동작 | action |
| SA 즐겨찾기 진입점 | action_source |
| SA 즐겨찾기 저장 범위 | persistence |
| SA 비교 진입점 | vs_source |
| SA 공유 진입점 | share_source |
| SA 공유 방식 | method |

`SA 경과 시간`은 `duration_ms`의 이벤트 범위 맞춤 측정항목이며 단위는 **밀리초**다. 범주형 차원으로 만들지 않았다. 맞춤 지표의 합계·평균·건수는 분위수와 다르다. SDK와 기존 사이트 동작은 이번 설정에서 바꾸지 않았다.

## 저장한 GA 탐색

이름: **Tracking SA v1 일반 이용 기준**. 본인 GA 속성의 탐색에서 연다. 공유 권한을 변경하지 않았다. 2026-10-23 재진입 후 7개 탭의 실제 저장된 행·열·값·필터를 대조했다. 보고 시간대는 속성 설정에서 GMT+09:00 대한민국 시간을 읽어 확인했으며 변경하지 않았다.

| 탭 | 행 | 값 | 이벤트 조건 |
| --- | --- | --- | --- |
| 01 이벤트·기기 | 이벤트 이름 | 이벤트 수 | 정의한 9종만 정확히 일치하는 정규식 |
| 02 검색 결과 | 결과 상태·검색 결과 표시 | 이벤트 수 | sa_search_finish |
| 03 첫 결과 시간 합계·표본 | 결과 출처 | 이벤트 수·경과 시간 합계 | sa_search_first_result |
| 04 즐겨찾기 상태 변경 | 동작·저장 범위 | 이벤트 수 | sa_favorite_change |
| 05 VS 완료 결과 | 결과 상태·결과 출처 | 이벤트 수 | sa_vs_finish |
| 06 공유 완료·취소·대체 | 공유 방식·결과 상태 | 이벤트 수 | sa_share_finish |
| 07 집계 확인·점검 포함 | 트래픽 구분·이벤트 이름 | 이벤트 수 | 정의한 9종. production 제한 없음 |

모든 탭의 열은 **기기 카테고리**다. 1~6번에는 `traffic_scope=production`, `measurement_version=v1`을 정확히 일치 조건으로 적용했다. 7번은 집계 상태 확인용이며 verification도 포함하므로 일반 이용 성과에 합산하지 않는다. 여기서 쓰는 조건은 탐색의 조회 필터이며 수집 데이터를 영구 삭제하는 GA 데이터 필터를 활성화한 것이 아니다.

9종 정규식:

```text
^sa_(search_start|search_first_result|search_finish|summary_view|favorite_change|vs_start|vs_finish|share_start|share_finish)$
```

최초 설정 확인 당시 기간은 **오늘, 2026-10-23**으로 등록일 점검에 사용했다. 이는 부분일이며 개선 전 기준 기간을 확보했다는 뜻이 아니다. 새 맞춤 정의의 보고서 반영에는 24~48시간이 걸릴 수 있다. 모든 탭에서 조회 가능한 행이 없었고 QA 탭도 같은 상태였다. 화면의 합계 0을 이용자가 0명이라는 결론으로 바꾸지 않는다. 등록 전 매개변수의 소급 보고 가능성도 가정하지 않는다.

## 기준 기록과 분모

실제 비공개 운영 수치와 현재 미산출 상태는 저장소 밖 로컬 기준 기록에 보관한다. 공개 저장소에는 수집·분석 절차와 확인 한계를 남긴다.

- 과거 28일 서비스 규모와 새 제품 지표를 구분한다. 과거에 없던 제품 이벤트는 **미측정**이며 0이 아니다.
- 기준 분석은 같은 완료 날짜 구간·기기·버전·production 조건을 쓴다. 등록일 부분일과 5번 점검 시간을 일반 이용 성과로 해석하지 않는다.
- 종료 관측 비율은 finish/start다. 결과 표시율은 finish 중 result_shown=1/finish 전체다. success/partial/failure 구성의 분모에서는 대체·취소를 빼고 별도 표시한다. 건수가 일치하지 않아도 강제로 보정하지 않는다.
- 시간 탭은 경과 시간 합계와 이벤트 수를 기록한다. 이벤트 수를 유효 duration 표본 수와 같다고 가정하지 않는다. 유효 duration 표본 수가 확인된 경우에만 합계/유효 표본 수로 평균을 계산하며, 평균을 p50/p95로 부르지 않는다. 분위수는 현재 범위에서 미산출이다.
- 즐겨찾기/VS/공유 원시 건수를 검색 건수로 나누면 반복 사용 때문에 100%를 넘을 수 있다. 이를 고유 전환율로 표시하지 않는다.
- 일반 GA 사용자 퍼널을 같은 세션의 검색별 전환율로 대체하지 않는다. 같은 세션에서 첫 결과 이후 후속 행동이 발생한 비율은 원자료의 순서와 세션 범위를 검증한 뒤 산출한다. 여러 검색이 있는 세션의 행동을 개별 검색에 귀속하지 않는다.
- GA 기준 구간은 맞춤 정의의 보고 가능 상태·마지막 동작 변경 이후 첫 완료일부터 잡는다. 확인한 날짜·시간대·집계 처리 상태와 N을 함께 남긴다. 등록일 부분일은 기준 기간에 섞지 않는다. 기간만 채워도 표본이 부족하면 효과는 미판정으로 둔다. 원자료 내보내기 시작을 기다리는 계획은 철회했다.

## 무료 측정 방식과 철회한 연결안

2026-10-23 사용자가 모든 변경을 추가 과금 없는 방식으로 진행하도록 지정했다. BigQuery 연결안은 **철회**했으며 제출하지 않았다. GA의 새 연결 작성 화면을 닫고 연결 목록이 비어 있는 것을 다시 확인했다. 이 작업으로 내보내기용 IAM 권한·데이터셋·새 수집 서버·결제 계정을 만들지 않았다. 기존 서비스의 결제 상태가 모두 무료라는 의미는 아니다.

기존 GA 탐색 7개 탭을 그대로 사용한다. 데이터가 처리되면 같은 완료 기간·기기·production/v1 조건으로 화면에서 읽거나 수동 CSV 내보내기를 로컬에 저장한다. 연결형 대시보드·예약 내보내기·새 로그 저장소는 추가하지 않는다. 수동 집계 결과에는 기간·필터·이벤트 건수·분모·누락/처리 상태를 함께 기록하고 운영 원자료는 공개 저장소에 올리지 않는다.

| 지표 | 현재 무료 방식 | 해석 한계 |
| --- | --- | --- |
| 검색 시작·종료 관측 | GA 이벤트 수와 finish/start | 연결되지 않은 관측 건수의 비율이며 고유 시도별 성공률이 아님 |
| 결과 표시율 | sa_search_finish 중 result_shown=1 / 같은 조건의 finish 전체 | 종료 이벤트가 관측된 검색 범위. start만 남은 작업은 별도 |
| 결과·갱신 상태 | outcome·revalidation별 건수와 구성비 | 대체/취소를 성공·실패로 채우지 않음 |
| 첫 결과 시간 | 결과 출처·기기별 duration 합계와 이벤트 수 | 유효 duration N 확인 전 평균 미산출. p50/p95 미산출 |
| 즐겨찾기·VS·공유 | 종류·상태별 이벤트 수 | 반복 동작 포함. 사용자/세션 전환율로 표현하지 않음 |
| p50/p95·순서 있는 세션 비율 | 현재 범위에서 미산출 | 요금제나 원자료 서비스 추가를 이유로 삼지 않음 |

## 남은 완료 조건 — 무료 범위

1. 처리된 실제 production 표본과 점검 분리가 조회되는지 확인한다. 비어 있으면 집계 대기 상태를 유지하고 0명/0건으로 단정하지 않는다.
2. 같은 완료 기간의 기기별 이벤트 건수·결과 표시율·결과/갱신 상태·후속 행동 건수를 실제 N·분모와 함께 로컬 기준 기록에 남긴다. 수동 내보내기와 로컬 계산만 사용하며 시간 평균은 유효 duration N이 확인된 경우에만 기록한다.
3. p50/p95·순서 있는 세션 비율은 미산출·현재 범위 제외라고 명시한다. 이 범위 조정으로 과거 요구 지표를 측정했다고 간주하지 않는다. 완료일 기준 표본이 없으므로 아직 6번을 완료로 바꾸지 않는다.

## 배포 후 재확인 — 2026-10-23

- 저장된 7개 탭을 재조회해 production/v1의 검색 이벤트·종료 상태·결과 출처/시간 합계와 QA 탭의 production/verification 분리 표시를 확인했다. 최초 설정 시 모든 행이 비어 있던 상태에서 집계가 조회되는 상태로 바뀌었다.
- 조회 기간은 여전히 오늘 부분일이다. 실제 비공개 건수와 화면은 저장소 밖 로컬 재확인 기록에 보관하며, 조회되지 않는 후속 행동을 실제 이용 0건으로 단정하지 않는다. 시간 합계와 이벤트 수만으로 유효 duration N·평균·분위수를 계산하지 않았다.
- Site Deploy #704의 모바일 개선이 같은 날 반영돼 일별 자료에는 변경 전후가 섞일 수 있다. 동일 v1이라는 사실만으로 배포 전후 코드를 구분할 수 없다. 이 자료를 확정 개선 전 기준이나 변경 효과로 쓰지 않는다.
- 마지막 관련 배포 다음 날인 2026-10-24가 첫 완료일 후보이며, 달력상 2026-10-25 이후 처리된 해당 날짜 자료를 확인할 수 있다. 그때까지 집계 완료나 충분한 표본을 보장하는 일정은 아니다. 다른 동작 변경이 있으면 후보 구간도 다시 정한다.
- 앞으로 확보하는 완료일 구간은 현재 배치의 운영 기준이다. 확보하지 못한 과거 제품 기준을 소급 복원하거나 개선 전후 효과를 입증하지 않는다. 10번에는 비교 가능 여부·표본 부족·피드백 한계를 함께 기록한다.
- 6번은 production/점검 분리 확인을 완료했지만 완료 기간·기기별 N/분모·상태와 후속 행동 기준 기록은 남아 있다. 완료로 표시하지 않는다. 기존 보고서 조회만 수행했고 새 정의·필터·BigQuery·자동 내보내기·서비스/결제 설정 변경과 추가 제품 시험 전송은 없다.
