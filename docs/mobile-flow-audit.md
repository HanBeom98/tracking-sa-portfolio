# 모바일 검색·비교·공유 흐름 점검

작성일: 2026-10-23. 성장 체크리스트 7번의 **로컬 점검·문제 목록 작성 완료** 기록이다. 코드 수정·운영 배포·실제 iPhone Safari/Android 검증·개선 효과 확인을 완료했다는 뜻은 아니다. 6번 일반 이용 기준 표본은 별도로 대기 중이다.

## 범위와 비용

- 기존 빌드의 Chromium 로컬 화면을 사용했다. 390×844, 402×844, 1280×844에서 밝은/어두운 테마를 확인했다. 소스/배포본 146개 일치 검사를 먼저 통과했다.
- 외부 요청은 로컬 라우트에서 차단하고 검색 API·GA SDK·clipboard/share·다운로드는 fixture로 응답했다. 운영 GA 전송·API 호출·DB 쓰기·실제 클립보드 쓰기·외부 수신자 공유·실제 파일 다운로드를 하지 않았다. 사진은 로컬 생성 PNG다.
- 정상 결과는 캐시에 주입한 합성 20경기 데이터다. 긴 이름은 경계 점검용 합성 값으로 실제 게임의 닉네임 허용 길이를 뜻하지 않는다. 별도 0경기 결과도 확인했다. 실제 게임 기록·운영자 분석 수치·사용자 데이터는 포함하지 않는다.
- 기존 source JS/CSS, 생성 public, 결제/GA 설정은 변경하지 않았다. 유료 도구·새 수집 서버·BigQuery·추가 저장소를 도입하지 않았다.

## 관찰한 19개 시나리오

| 분류 | 수 | 확인 내용 |
| --- | ---: | --- |
| 화면·비교 | 6 | 390/402/1280px × 밝은/어두운 테마. 결과·공유 패널·프로필·첫 KPI 위치, 가로 넘침, VS 모달과 비교 결과 |
| 경계 데이터 | 2 | 긴 합성 이름, 0경기 결과 |
| 조회 오류 | 2 | 504 timeout·429 호출 제한에서 다른 안내, 입력 유지·재검색 버튼 복구 |
| 공유 | 6 | clipboard 성공/거부, native 성공/취소/오류, clipboard 완료 응답 보류 후 해제 |
| 입력·즐겨찾기·모달 | 1 | 빈 Enter·정상 Enter, 추가/해제, Escape 닫기·포커스·dialog 속성 |

19개는 **관찰 시나리오 수**이며 모두 이상 없었다는 테스트 통과 수가 아니다. 이 관찰에서 처리되지 않은 pageerror는 없었다. 화면 비교는 DOM 및 로컬 PNG 캡처로 확인했다. 기존 브라우저 회귀 검사의 실행 결과는 별도로 기록한다.

## 확인한 개선 항목

| 우선순위 | 항목 | 증상과 근거 | 원인·다음 수정 방향 |
| --- | --- | --- | --- |
| 1 | 공유 완료 응답 대기 중 복구 | clipboard.write를 보류한 fixture에서 1.2초 후에도 버튼 비활성·생성 중 안내·start만 관측. 해제하면 success finish·버튼 복구 | share()가 해당 Promise를 그대로 기다리며 진행 단계 안내·장기 대기 복구 경로가 없음. 이미지 생성/클립보드/공유 창 단계를 구분하고 대기 안내·명시적 대체 저장을 설계. 늦은 응답·중복 클릭·중복 종료를 함께 검증해야 함 |
| 2 | 취소 후 진행 안내 잔류 | 모의 native share가 AbortError를 반환하면 cancelled finish와 버튼 복구는 정상인데 안내는 생성 중 그대로 | AbortError 분기에서 status를 갱신하지 않고 return. 사용자 취소 안내로 갱신할 필요 |
| 3 | PNG 요청을 저장 완료로 안내 | clipboard 거부 또는 native 오류 뒤 fixture anchor 요청 1회, 이벤트는 download_requested지만 UI는 PNG로 저장했다고 안내 | 브라우저의 실제 저장 완료를 확인하지 않는 경로. 저장 요청 의미로 문구를 맞추고 원래 공유 실패 경로도 구분 |
| 4 | 모바일 핵심 통계까지 긴 이동 | 390px에서 결과 영역 시작→첫 승률 KPI 2,326px, 402px에서 2,314px. 공유 패널과 프로필이 KPI보다 먼저 배치 | 공유 패널만의 문제가 아니라 프로필 포함 전체 정보 순서 검토 필요. 핵심 지표·최근 변화 우선, 공유/사진 편집은 후순위 또는 접기. 실제 이탈 원인이라고 단정하지 않음 |
| 5 | 즐겨찾기 보조 버튼의 작은 영역 | fixture의 칩 VS 버튼 약 25×22px, 삭제 버튼 18×18px | 실제 휴대폰 오조작률은 미측정. 가까운 버튼 간 간격·터치 영역 확대를 검토. 숨긴 1px 파일 입력과 의도한 말줄임은 결함 집계에서 제외 |
| 6 | 폭 변경 후 공유 이름 불일치 | 390→844px에서 prefersNativeShare 조건은 false로 바뀌지만 버튼은 공유하기 유지 | updateActionLabel이 초기화 때만 호출됨. 크기/매체 조건 변화와 안내를 동기화할 필요 |
| 7 | VS 모달 접근성 정보·포커스 복귀 | 열 때 입력 포커스·Escape 닫기는 정상. role/aria-modal 없음, closeVsModal에 열기 버튼으로 복귀 처리 없음 | 화면 안에 들어오는 크기는 정상. dialog 이름·의미·포커스 이동/복귀를 별도 개선하고 키보드·보조기기 검증 필요 |

이 순서는 다음 구현의 후보 우선순위다. 네이티브 공유 창은 사용자가 열어 놓을 수 있으므로 일괄 시간 제한으로 강제로 취소하지 않는다. 실제로 취소할 수 없는 clipboard 작업을 중복 재시도하거나, 완료를 모르는 상태를 성공/실패로 단정해 이벤트를 맞추지 않는다.

## 배치 측정값

합성 20경기 결과, CSS px, 문서 좌표에서 측정했다. 밝은/어두운 테마의 위치는 해당 폭에서 같았다. 런타임 속도·네트워크 성능·사용자 스크롤 횟수 측정값은 아니다.

| 화면 폭 | 결과 영역 시작 Y | 첫 승률 KPI Y | 결과 시작부터 거리 | 공유 패널 높이 | 문서 가로 폭 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 390 | 511 | 2,837 | 2,326 | 651 | 390 |
| 402 | 511 | 2,825 | 2,314 | 639 | 402 |
| 1280 | 386 | 1,432 | 1,046 | 480 | 1280 |

검사한 화면과 긴 이름·0경기·오류 상태에서 문서 수준 가로 넘침은 없었다. 모바일 VS 모달은 약 371/382px 폭으로 화면 안에 들어왔고, 입력 유지·재검색·즐겨찾기 상태 변경·사진 초기화·정상 공유 응답 처리는 관찰 범위에서 정상이다.

## 이전 첫 이미지 복사 미종료의 해석

[5번 운영 기록](product-measurement-verification.md)의 첫 복사에서 PNG는 생겼지만 UI와 finish가 끝나지 않았던 사실을 유지한다. 이번 clipboard 응답 보류 fixture는 유사한 UI/이벤트 양상을 재현하고, 응답을 해제하면 복구됨을 보였다. 운영 첫 시도에서 실제로 어떤 Promise가 왜 지연됐는지는 확정하지 못했다. 정상 로컬 호출 1회가 성공했다고 운영 문제가 해결됐다고 판단하지 않는다.

createShareCardBlob은 폰트·이미지 로딩·canvas.toBlob도 기다린다. 이번 합성 프로필에는 외부 계급 이미지가 없으며, 외부 프록시/디코딩·운영 브라우저 포커스/권한·OS 클립보드의 조합을 검증하지 않았다. 따라서 해당 경로를 원인에서 제외하지 않는다.

## 다음 단계와 남은 한계

8번은 위 공유 상태 문제를 먼저 수정하고, 핵심 지표와 공유/사진 편집의 배치를 개선한다. 변경 전 캡처와 좌표는 저장소 밖 로컬 점검 산출물에 보관했다. 작은 화면·데스크톱·테마·경계 데이터·늦은 응답·취소/대체 저장을 다시 검증한다. 새 기능 효과 비교 전에는 6번의 가용 기준 표본과 한계를 남긴다.

실제 iPhone Safari·Android 공유 창/키보드/터치·실제 clipboard·실제 저장 완료는 미확인이다. 390px Chromium의 API fixture와 실제 휴대폰 검증을 합치지 않는다. 이 미확인 항목을 기록한 상태로 7번의 로컬 감사는 종료하며 9번 실기기 확인 항목에 계속 남긴다.

검증 명령: npm run check:source-of-truth — 146개 일치 통과. npm run test:e2e:ci — 기존 로컬 브라우저 회귀 25개 통과(41.3초). 이 회귀 검사는 취소 시 status 잔류나 무응답 복구까지 검증하지 않으므로, 통과 결과가 위 결함을 부정하지 않는다. 코드/빌드 변경이 없는 점검 문서 작업이어서 전체 단위 검사·새 빌드·운영 배포는 실행하지 않았다.

## 8번 후속 구현

위 7개 개선 항목에 대한 [구현·로컬 검증 기록](mobile-flow-improvements.md)을 추가했다. 공유 지연 안내/명시적 PNG 저장, 취소/다운로드 문구, 접힌 공유 패널·통계/최근 변화 우선 배치, 버튼 크기·폭 변경 이름·VS 모달 의미/포커스 처리를 반영했다. 이는 운영 첫 복사 문제의 근본 원인 확정이 아니며 원래 점검 기록과 미확인 한계를 보존한다. 운영 배포·실기기 검증은 별도다.
