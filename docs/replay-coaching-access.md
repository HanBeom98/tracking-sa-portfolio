# 모의 이용 기간·50회 성공·70회 시도 구조

> 2026-10-26 후속: 이 문서는 이전 월간 모의/품질 시험의 구조 기록이다. 현재 판매 방향은 월 구독이 아닌 [구매 횟수권](replay-coaching-credits.md)이며, 운영 해설 API도 별도 횟수권 잔액을 사용한다. 기존 시험 장부/기간 경계는 보존하고 새 잔액으로 자동 이관하지 않는다.

2026-10-25. [정산 분리](replay-coaching-settlement.md)의 후속 로컬 개발이다. **실제 결제·구독 권한·유료 AI·운영 배포는 연결하지 않았다.** 월 3,300원/50회는 여전히 품질·결제 조건 확인 전의 상품 제안이다.

## 두 종류의 기간

| 기준 | 현재 구현 |
| --- | --- |
| 사용자 이용 기간 | 서버가 명시한 ID·시작 시각·종료 시각. 시작 포함/종료 제외 |
| 전역 생성·비용 예산 | 기존 한국 시간 달력 월(`YYYYMM`). 사용자 기간과 별도 |
| 신규 요청 번호 | 생성 시점 한국 월 접두사를 요구 |
| 이미 알려진 요청 | 보관 중인 현재/이전 기간의 번호라면 지난달·만료 후에도 중복 상태 확인 가능. 재생성 없음 |

예를 들어 10월 25일~11월 25일을 하나의 테스트 기간으로 두면 11월 1일에도 성공 횟수와 시도 수는 그대로다. 비용은 각 요청이 예약된 10월/11월의 전역 장부에 남긴다. 사용자가 보낸 기간·성공 여부·비용 값으로 권한을 바꾸지 않는다.

지금은 허용 UID들이 서버 환경에 지정한 **하나의 테스트 기간을 공유**한다. 실제 결제일·갱신 웹훅·개별 회원의 구독 정보에서 기간을 가져오는 기능은 아직 없다. 결제 증명이나 고객별 유료 권한이 구현됐다는 뜻이 아니다.

## 한도와 보관 범위

| 항목 | 구현 상한 | 비고 |
| --- | ---: | --- |
| 기간당 정상 해설 | 50회 | 서버 테스트 설정으로 더 작게 설정 가능 |
| 기간당 전체 시도 | 70회 | 정상·실패·취소·미확정 시도를 포함. 성공 한도 이상이어야 함 |
| 기간별 중복 기록 | 70개 | 초과 시 새 시도를 거절하며 같은 기간의 오래된 기록을 먼저 버리지 않음 |
| 서버 보관 기간 수 | 현재 + 이전 2개 | 사용자 문서에 최대 210개 종료 기록. 원본/요약/해설 본문 저장 없음 |
| 브라우저 페이지 메모리 | 전체 최대 210개 | 계정·근거별 ID/응답. 미확정 항목을 지워 공간을 만들지 않음 |
| 동시에 처리할 작업 | 계정당 1개 | 이전 기간의 작업도 포함 |

50회 성공만 시험하는 경우 51번째 새 요청은 `USER_LIMIT`으로 거절한다. 실패 20회 뒤 성공 50회가 쌓인 경우에는 70개 기록을 모두 보존하고 다음 요청을 `ATTEMPT_LIMIT`으로 거절한다. 실패 비용이 있는 경우 기존처럼 비용 장부에도 남긴다. 전역 예산이 먼저 소진되면 개인 잔여 횟수가 있어도 요청을 막는다.

페이지 메모리 상한은 모든 계정을 합친 값이며 새로고침하면 사라진다. 기록이 꽉 찼을 때 자동으로 새 ID를 만들어 재시도하지 않는다. 이미 보관한 요청의 확인은 계속 가능하다. 영구 결과 보관·복원이나 성공 결과를 새 기간에 다시 생성하는 기능은 아니다.

## 명시적 서버 설정

`REPLAY_COACHING_MODE=mock`와 테스트 UID/전역 제한 설정 외에 다음 값이 전부 필요하다. 운영 환경에는 추가하지 않았다.

| 변수 | 의미 |
| --- | --- |
| `REPLAY_COACHING_TEST_PERIOD_ID` | 영문·숫자·`_`·`-`의 1~64자 ID |
| `REPLAY_COACHING_TEST_PERIOD_START` | UTC ISO 시각. 예: `2026-10-25T00:00:00.000Z` |
| `REPLAY_COACHING_TEST_PERIOD_END` | UTC ISO 종료 시각. 예: `2026-11-25T00:00:00.000Z` |
| `REPLAY_COACHING_USER_LIMIT` | 정상 성공 1~50회 |
| `REPLAY_COACHING_ATTEMPT_LIMIT` | 전체 시도 수. 성공 한도 이상, 최대 70회 |

기존 `REPLAY_COACHING_USER_MONTHLY`만으로 동작하는 묵시적 달력 월 모드는 제거했다. 기간 값이 빠지거나 일수·시각·한도가 잘못되면 `COACHING_NOT_CONFIGURED`로 비활성 처리한다. 날짜는 밀리초와 `Z`를 포함한 정규 UTC 문자열이어야 한다.

현재는 월간 상품을 가정해 **28~32일 길이**만 지원한다. 월말에 임의로 날짜를 더해 갱신일을 계산하지 않는다. 월간 외 기간·일시 정지·환불·중도 변경은 후속 결제 정책과 함께 설계해야 한다.

## 갱신과 만료

- 한 번 적용한 ID의 시작/종료 시각·성공 한도·시도 한도를 중간에 바꾸면 충돌로 거절한다.
- 새 기간은 이전 기간이 끝난 후, 이전 종료 시각과 겹치지 않아야 한다. 같은 ID 재적용으로 횟수를 초기화하지 않는다.
- 보관 중인 이전 ID의 재사용, 과거 기간 설정의 재적용과 겹친 기간은 `ACCESS_PERIOD_CONFLICT`로 거절한다.
- 시작 전 새 요청은 `ACCESS_NOT_STARTED`, 종료 시각부터의 새 요청은 `ACCESS_EXPIRED`로 거절한다. 알려진 완료 요청은 기존 결과의 중복 상태만 반환할 수 있다.
- 갱신 시 현재 집계를 직전 기간으로 옮기고 새 집계를 한 번 만든다. 동시에 갱신 요청이 와도 트랜잭션에서 하나의 활성 예약만 생긴다.
- 이전 작업이 미확정이면 새 기간을 적용해 우회할 수 없다. 먼저 기존 정산/명시적 복구를 완료해야 한다.
- 예약 후 전송 시작 직전에 기간이 만료됐다면, 아직 전송하지 않은 작업을 트랜잭션에서 비용 0으로 취소하고 생성을 시작하지 않는다. 기간 내 전송 시작한 작업의 정상 정산은 만료 뒤에도 가능하다.

날짜를 바꾸면 비용이 없어지는 구조가 아니다. 복구는 활성 작업의 원래 비용 월을 사용하고, 종료 기록과 지출을 보존한 뒤 새 기간을 적용한다. 전역 월 예산 리셋이 사용자 이용권을 한 번 더 지급하지도 않는다.

## 이전 두 기간을 보관하는 이유

28일짜리 월간 기간이 이어지면 같은 달 안에서 두 번 갱신될 수 있다. 예를 들어 3월 1일에 만든 요청이 3월 2일·3월 30일의 갱신을 거친 후에도 같은 `202603` 접두사를 가질 수 있다. 직전 기간 하나만 보관하면 이 요청을 새 요청으로 오해할 수 있다.

현재와 이전 두 기간을 보관하면 중복 기록을 버린 가장 오래된 작업은 적어도 두 월간 기간(최소 56일) 이전에 시작한 작업이다. 신규 요청의 현재 월 검사와 함께 사용해, 보관에서 빠진 오래된 번호가 새 생성으로 들어오지 않게 한다. 이 보장은 현재의 28~32일·비중첩 기간 조건에 의존한다. 짧은 주기 상품을 추가할 때는 기록 정책도 다시 설계해야 한다.

## 데이터와 검증

사용자 장부는 `schemaVersion: 3`, `access`, `used/held/attempts/recent`, `previous`(최대 2개)와 `active`다. 활성 예약은 비용 월 `period`와 별도의 이용 기간 ID `accessId`를 가진다. 전역 비용 장부는 v2를 유지한다. v1/v2 사용자 장부를 자동 초기화/이전하지 않으며 불일치 시 거절한다. 신규 함수는 운영 미배포여서 이번에 운영 데이터 이전을 수행하지 않았다.

신규 정상 요청은 여전히 기본 트랜잭션 3회·문서 읽기 6회·쓰기 5회다. 새 컬렉션·스케줄·유료 TTL 작업·분석 수집을 추가하지 않았다. 사용자 문서의 제한된 메타데이터 보관량은 늘어난다. 실제 활성화 전 무료 할당량·운영 사용량 확인은 별도로 필요하다.

검증은 최대 50회, 실패 포함 70회, 첫 요청 중복 기록 보존, 페이지 메모리 210개, 시작·만료 경계, 달력 월 경계, 갱신 중복·충돌·동시 예약, 이전 기간 미확정 작업, 전송 직전 만료, 연속 28일 기간의 늦은 요청과 보관 만료를 포함한다. Firestore Emulator에서도 월 경계와 갱신 경합을 확인하며 브라우저에는 이용 기간·만료·설정 충돌 안내를 표시한다.

후속 [입력·비용 상한 준비](replay-coaching-budget.md)는 별도 통화 문서 키에서 일별 5회/10시도·개인/전체 마이크로달러 예산과 중단 검사를 로컬 구현했다. [단일 생성·결과 복구](replay-coaching-provider.md)와 [소액 실제 품질 시험](replay-coaching-pilot.md)도 진행했으며 의미 품질 기준 미달로 유료 출시를 보류했다. 이 문서의 기존 모의 HTTP 경로에는 연결하지 않았다. 운영 구독 권한·결제는 미구현이다.
