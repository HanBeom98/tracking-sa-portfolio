# 리플레이 화면과 모의 API 로컬 연결

2026-10-25. 운영 활성화 전의 테스트 단계다. 유료 AI·구독 결제·운영 API 호출은 추가하지 않았다.

## 동작 범위

- 정확히 `http://127.0.0.1:4173/stats/sudden-attack/replay/?coaching=mock`에서만 요청 UI가 열린다. 운영 도메인에서는 같은 쿼리를 붙여도 열리지 않는다.
- 리플레이를 분석한 뒤 로그인한 사용자가 버튼을 직접 눌러야 전송한다. 자동 호출·자동 재시도는 없다. 검증된 라운드가 없으면 요청을 막는다.
- 고정된 같은 출처의 `/api/replay-coaching`로 `{ requestId, evidence }`만 보낸다. Firebase ID 토큰은 Authorization 헤더에 넣는다. UID·사용량·요금은 클라이언트가 결정하지 않는다.
- 원본 파일·닉네임·좌표는 보내지 않는다. 요약 전송 안내를 버튼 위에 표시한다. 서버 응답도 여전히 정해진 문장으로 만든 모의 해설이며 `AI 미연결 · 예시` 표시를 유지한다.
- 로그인·요청 중·완료·사용 한도·권한 거부·비활성·미확정·잘못된 응답을 구분한다. 기존 라운드 분석과 근거 이동은 계속 사용할 수 있다.

## 중복과 화면 전환

계정과 요약이 같은 요청은 페이지 메모리에서 같은 요청 ID를 사용한다. 서버 응답을 잃거나 파일을 다시 선택해도 새로운 ID로 우회하지 않는다. 타임아웃(15초)은 서버 작업 취소를 의미하지 않으며, 명시적으로 **같은 요청 상태 확인**만 할 수 있다.

이전 응답이 있으면 중복 완료 확인 후에도 그대로 표시한다. 응답을 받지 못한 채 서버에서만 완료됐다면 서버에 문장을 저장하지 않으므로 재표시할 수 없다고 안내한다. 이때 기기 내 해설 예시를 유지한다. 원래 페이지를 새로 열면 메모리 ID가 사라지므로 새 요청은 별도 사용량을 쓸 수 있다. 영구적인 결과 보관·복원 기능은 아니다.

파일·플레이어·경기 유형 변경과 초기화 때 요청 대기를 중단하고 오래된 응답을 화면에 적용하지 않는다. 로그아웃·계정 변경 때도 기존 계정의 서버 응답을 숨긴다. 중단한 요청은 확인 전까지 결과 미확정으로 유지한다. 메모리 보관은 페이지 전체 최대 210개이며 브라우저 저장소에 토큰·요약·응답을 쓰지 않는다. 한도에 도달하면 기존 번호를 버리는 대신 새 요청을 막는다.

## 검증 실행

```sh
npm run build
npm run test:e2e:coaching:local
```

기존 Auth/Firestore/Storage Emulator 실행 환경(Node·Java·테스트 의존성)이 필요하다. 테스트는 데모 프로젝트 `demo-trackingsa-ownership`과 고정된 loopback 포트만 사용한다. 외부 브라우저 요청은 차단한다. 이 명령은 검증 후 서버와 에뮬레이터를 종료한다.

브라우저는 실제 Firebase SDK로 Auth Emulator에 로그인한다. 테스트 HTTP 어댑터는 Auth Emulator의 토큰 조회로 계정을 검증하고 기존 `createReplayCoachingHandler`에 요청을 넘긴다. 실제 Firestore Emulator 트랜잭션으로 사용량을 확인한다. 배포된 Functions 런타임이나 운영 JWT 서명 검증까지 시험한 것은 아니다.

운영 CORS는 변경하지 않았다. loopback 전용 테스트 어댑터에서만 요청 출처를 변환한다. 어댑터·데모 계정·테스트 한도는 `tests/`에만 있으며 공개 빌드에 포함하지 않는다. 테스트 중 미허용 계정은 실제 서버가 거절하고, 비활성·미확정·잘못된 응답 화면 일부는 의도적으로 응답을 주입해 확인한다.

단위 검증은 로그인/근거 없음의 미전송, 한국 월 기준 ID, 요약 스냅샷, 동일 ID 재시도, 중복 클릭, 지연 토큰, 오래된 응답 격리, 계정 분리, 응답 계약 검증을 확인한다. 브라우저 검증은 정상·중복·응답 유실 후 복구·월 한도·권한·파일 교체 및 모바일/데스크톱 배치를 다룬다.
