# 구독 AI용 전 라운드 복기 후보 v2

> 2026-10-26 후속: 현재 유료 상품 방향은 월 구독이 아닌 [AI 분석 횟수권](replay-coaching-credits.md)이다. 복기 근거/모델 선택/카드 표시 계약은 유지하고 유료 API의 권한·잔액 경계를 변경했다. 실제 판매/유료 AI 활성화는 아직 하지 않았다.

2026-10-26. 중요한 장면이 기존 상세 후보 선정 전에 빠지는 문제를 보완하기 위한 로컬 준비 경로다. **전 라운드 후보 검사·사건 전후 흐름·복기 우선순위, 버전별 서버 입력 검증·질문/목표, 로컬 사건 강조 화면**을 구현했다. 새 입력으로 실제 2경기에서 모델 선택을 각 1회 검증했다. 운영 DB 저장·구독 권한 부여·공개 배포는 하지 않았다. 기존 무료 분석, 근거 요약 v1과 저장 해설을 유지한다. 내부 비용 통제 runner는 새 v2 입력도 지원하지만 운영 HTTP는 기존 모의 경로다.

## 진입점과 기존 기능의 경계

`replay-analyzer.js`의 별도 비동기 함수 `analyzeReplayForCoaching(parsed, playerId)`를 명시적으로 호출하면 기존 분석을 실행한 뒤 `replay-coaching-review.js`를 지연 로드한다. 기존 `analyzeReplay()`는 새 후보를 자동 계산하거나 새 모듈을 로드하지 않으며 반환값도 유지한다.

순수 함수 `buildReplayCoachingReview(analysis)`는 신뢰된 로컬 분석 결과를 입력으로 받는다. **HTTP의 임의 클라이언트 입력을 검증하는 함수가 아니다.** 새 객체는 schemaVersion2이며 현재 `normalizeCoachingEvidence` 및 AI API의 v1 입력과 구분한다. 별도 서버 검증 `normalizeReviewEvidence`와 내부 요청/응답 경로를 추가했다. 새 AI 결과의 서버 표시용 응답·브라우저 검증·카드/사건 이동을 로컬 저장 응답 불러오기로 연결했다. [비활성 운영 API](replay-coaching-paid-api.md)에 인증·AI 전용 이용권·사용량·결과 소유자 검증을 연결했다. 운영 배포·결제 확인/이용권 발급·브라우저 자동 호출은 아직 하지 않았다. 이 함수를 호출해도 구독 권한은 생기지 않는다.

## 후보 선정

불완전한 상황 기록, 유효하지 않거나 중복된 라운드 번호, 지원하지 않는 인원 전환은 제외한다. 제외한 기록은 사건이 없었던 것으로 세지 않는다. 유효한 모든 라운드에서 기준을 계산하고, 한 라운드당 대표 후보 하나를 만든다.

| 우선순위 기준 | 뜻 |
|---|---|
| 인원 우세 중 사망 후 팀 패배 | 사망 직전 아군이 상대보다 많았던 기록과 이후 패배를 구분해 복기 |
| 첫 사망 사건 | 첫 처치 사건 시각에 본인 사망이 포함됨 |
| 단독 생존 | 혼자 남은 시점과 이후 인원 변화 |
| 후속 처치 수혜/수행 후보 | 기존 검증된 교환킬 후보의 주체와 이후 흐름 |
| 첫 처치 | 첫 사건 이후 개인 생존과 팀 결과 |
| 인원 우세 중 사망·기타 사망 | 사망 전후 변화. 승리한 경우도 실수로 단정하지 않음 |
| 처치 기록·종료 결과 | 위 상황이 적은 라운드의 보완 후보 |

위 순서는 검토용 제품 규칙이며 승률 손실·실력·책임을 계산한 점수가 아니다. 같은 대표 기준 안에서는 함께 나타난 반복 기준 수, 동시 사건 여부, 라운드 번호로 순서를 안정적으로 정한다. 각 기준에 해당한 라운드 수는 **선택된 일부가 아닌 전체 검증 라운드**에서 계산한다. 반복이 확인된 것은 이 경기 안의 기록이며 장기 습관을 입증하지 않는다.

대표 기준이 다른 후보를 먼저 넣은 뒤 남은 자리를 채워 최대 6개를 반환한다. 최종 후보는 다시 우선순위 순으로 정렬한다. 전 라운드를 검사했다는 사실이 모든 장면을 상세 결과로 반환한다는 뜻은 아니다. 생략된 검증 라운드 수를 표시한다.

## 사건 전후 근거

각 후보는 다음 정보를 갖는다.

- 시작 인원과 기준 시각 직전/직후 인원
- 기준 사건 전 최대 2개·기준 사건 1개·이후 최대 4개의 처치/사망 전환
- 각 시각의 본인 처치 수·본인 사망 여부·본인 생존 여부
- 직전 인원 상태가 시작된 시각, 이전/다음 처치·사망 사건까지의 간격
- 팀 종료 결과, 마지막 기록 인원, 창에서 생략된 앞/뒤 사건 수

같은 시각의 사망은 한 그룹으로 반영한다. 중간 순서나 실제로 없었던 인원 상태를 만들지 않는다. ‘다음 사건까지의 간격’은 교전·시야 확보·대응 가능 시간을 뜻하지 않는다. 본인 사망 뒤 남아 있는 아군 수에는 본인이 포함되지 않는다. 사망 후 처치는 기록하되 살아 있는 플레이어의 교환킬로 해석하지 않는다.

단독 생존이 처음부터 시작되거나 사건 없는 라운드는 이전 사망을 만들어내지 않는다. 마지막 기록과 팀 승패는 별개 필드다. 폭탄 동작·거리·시야·엄폐·음성·의도·판단 실수·패배 원인을 추가로 추정하지 않는다.

## 실제 파일에서 확인한 변화

한 실제 경기에서 기존 v1 상세 후보는 1·3·4·7·8·9라운드였다. 새 v2는 그 전에 빠졌던 **2라운드를 1순위**로 선정했다.

| 시각 | 사건 직전 → 반영 후 |
|---|---|
| 62.4초 | 3대2 → 3대1 |
| 64.6초 | 본인 사망, 3대1 → 2대1 |
| 79.9초 | 2대1 → 1대1 |
| 83.8초 | 1대1 → 0대1 |

3대1이 된 뒤 2.2초 후 본인이 사망했고, 이후 다음 처치/사망 사건까지 15.3초가 지났다. 팀 결과는 패배다. 선정 이유는 이 흐름을 확인할 필요가 있다는 뜻이며 본인에게 패배 책임이 있다는 판정이 아니다. 실제 새 AI가 이 근거를 보고 선택한 결과도 아니다.

- 신규 단위 검사 14개: 기존 후보에서 누락된 우세 후 패배, 전후 흐름·간격, 우세 사망 후 승리, 동시 사건, 시작부터 단독, 사망 후 처치, 팀 전환·비대칭 인원, 불완전/중복 기록, 반복 집계, 창 생략, 개인정보 제거·무료 불변, 원본 독립 대조와 의도적 거짓 수치 탐지.
- 전체 단위 검사 880개 통과(새 입력/선택/복구 10개와 표시용 응답·불러오기 8개 포함).

오프라인 대조 실행:

```text

```

원본 파일·선수 이름·계정 식별자는 저장소에 넣지 않는다. 새 후보 객체에는 고정된 선정 기준과 수치만 포함하며 원문·좌표·이름·무기·자유 지시문을 넣지 않는다. 추가 유료 의존성·로그·DB 컬렉션·예약 작업은 없다.

비활성 서버 API의 인증·이용권·사용량·소유자 경계는 로컬/Emulator로 검증했다. 다음은 결제 확인과 이용권 발급/회수 경계, 브라우저 자동 호출의 연결 및 실제 이용자의 유용성 피드백이다. 운영 활성화·유료 공개는 아직 하지 않았다. AI는 구독자 전용이라는 범위를 유지하며 무료 기본 분석을 구독으로 옮기지 않는다. 위치·동선은 좌표와 지도 지원을 검증한 뒤 별도로 다룬다.

## 서버 계약과 질문·행동 목표

`cloud-functions/replay-coaching-review-input.js`는 v2의 정확한 키·64라운드/후보 6개/사건 7개 상한·인원 전환·본인 생존·사망·처치·동시 사건·시간 간격·생략 범위·집계 간 일관성을 검사한다. 클라이언트의 설명과 한계 문장은 서버 고정 문장으로 교체한다. **원본 재생 파일의 진위나 해당 계정 소유권을 인증하는 검사는 아니다.** 요약만으로 빠진 라운드의 실제 중요도를 다시 검증할 수도 없다.

교환킬 가해자/피해자 연결은 이 요약에 없다. 해당 후보를 서버에서 검증된 교환킬로 단정하지 않고, 확인 가능한 본인 사망/처치와 인원 변화로만 표현한다. 반복 집계도 장기 습관·실력 지표로 사용하지 않는다.

`replay-coaching-review-catalog.js`는 후보별 고정 `rflow3_*` 사실과 `rq3_*` 질문·`rp3_*` 목표를 제공한다. 우세/열세/동수 사망, 첫 사건, 단독 생존, 일반 흐름에 따라 질문과 다음 3라운드 행동 목표를 제한한다. 과거에 엄폐나 합류를 하지 않았다고 추정하거나 목표 실행을 자동 채점하지 않는다. 강점 판단 근거는 부족하므로 새 계약의 strength 슬롯은 null만 허용한다. 주제가 겹치면 선택한 카드만 줄이며 다른 장면 대체·자동 재호출은 없다.

모델은 기존 schemaVersion3 고정 슬롯에서 ID만 고른다. 서버가 선택 조합을 검증하고 한국어 문장을 렌더링한다. 저장 형식은 기존 selection v2/response v1·최대 3,072바이트를 유지한다. 새 ID의 문구/의미 변경은 ID 버전을 올려야 하며 저장 해설 복구 시 새 중복 제거를 적용하지 않는다. v1 입력은 기존 요청과 렌더러로 분기한다.

실제 3경기 모든 30명/후보 180개가 새 정규화·요청 구성·결과 재현에 통과했다. 최대 요청은 12,617바이트, 단일 카드 저장 결과는 최대 728바이트였다. **바이트는 토큰 수가 아니며** 당시에는 실제 계수를 수행하지 않았다. 이후 아래 실제 2경기 시험에서 각각 계수 후 상한 안에서 생성했다. 정상/중복 요청·비용 정산은 메모리 DB와 모의 제공자로 검사했고 운영 DB에 쓰지 않았다.

## 로컬 사건 강조 확인

새 UI는 `http://127.0.0.1:4173/stats/sudden-attack/replay/?coaching=review`에서만 명시적으로 열린다. AI 생성 카드가 아닌 규칙 기반 후보/사건 창이다. 기본 무료 경로에서는 새 엔진/UI 모듈을 요청하지 않는다.

기준 시점 버튼은 해당 후보의 전후 사건 목록을 펼치고 정확한 시각의 인원 전환에 포커스/테두리를 표시한다. 같은 시각은 하나의 그룹이며 내부 순서를 만들지 않는다. 시작부터 단독이거나 사건 없는 종료 기준은 처치/사망 사건이 아니라고 표시한다. 앞뒤 생략·본인 사망 후 인원 포함 범위·팀 결과·간격 해석 한계를 함께 표시한다. 기존 라운드 이동 버튼도 제공한다. 선수/경기 유형/파일/초기화 변경은 이전 미리보기를 제거하며 지연 로드 응답도 무효화한다. 이 로컬 조건은 구독자 권한 검사와 별개다.

```text
node --test --experimental-test-isolation=none tests/unit/replay-coaching-review-contract.test.js
node node_modules/@playwright/test/cli.js test --config tests/e2e/playwright.review.config.js
```

요청 JSON의 strict 키/필수 필드/null 슬롯 형식은 [OpenAI 공식 Structured Outputs 문서](https://developers.openai.com/api/docs/guides/structured-outputs)를 확인했다. 형식 준수와 사실·선택 품질은 별개의 검사다. 이번 작업에서 모델/가격/계정 설정을 변경하지 않았다.

## 새 근거의 실제 모델 선택 검증

2026-10-26, 기존에 확인했던 서로 다른 두 경기에서 한 선수씩, 새 v2 요청으로 각 1회만 실제 생성했다. 정확한 요청을 먼저 계수하고 고정 요청 해시·가격 버전의 견적을 검증했다. 이전 시험의 호출 한도를 다시 사용하거나 실패 재시도하지 않았다. 두 요청 모두 정상 완료 후 로컬 제어를 닫았다. 호출/비용 상세와 선수 식별 정보는 저장소 밖 로컬 검증 기록에만 둔다.

| 확인 항목 | 관측 결과 | 해석 범위 |
|---|---|---|
| 기존 상세 목록에서 빠졌던 장면 | 한 경기에서 2라운드 64.6초의 3대1 → 본인 사망 → 2대1, 이후 팀 패배를 AI가 복기 대상으로 선택 | 누락 보완 사례이며 패배 책임 판정이 아님 |
| 상황별 목표 | 다른 경기의 1라운드 99.4초, 2대4 사망 장면에 열세 교전 전 이탈·합류 여지 확인 목표가 연결됨 | 해당 조건에 맞는 고정 목표이며 실제 위치/실수를 관찰한 것은 아님 |
| 카드 구성 | 두 경기 모두 복기·연습 2개, 서로 다른 주제를 모델이 직접 선택; 서버가 지운 카드 없음 | 강점 슬롯은 새 계약에서 의도적으로 null이며 이전 3카드와 구성 차이가 있음 |
| 원본 대조 | 두 경기 모든 플레이어의 후보/사건 창을 원본 사건으로 대조하고 선택 장면도 추가 대조 | 사실 일관성 검사이며 전술 코칭 정확도 평가가 아님 |
| 저장 결과 복구 | 각 시험의 로컬 장부로 이미 완료된 요청을 복구, 2읽기·0쓰기·0추가 계수/생성 | 운영 DB를 사용하지 않은 검증 |
| 이전 결과 | 무료 기본 해설과 이전 실제 저장 해설 그대로 재현 | 무료/기존 저장 형식 호환 유지 |

입력 후보 범위·고정 문구·질문/목표·카드 수를 함께 바꾼 시험이다. 같은 파일에서 버전별 한 번씩 얻은 결과이므로 개선 원인을 특정 프롬프트나 모델 능력 하나로 돌리거나 일반적인 정확도·성능 향상을 주장하지 않는다. 새 구조는 교환킬 주체 연결과 검증되지 않은 강점 해석을 일부 생략하는 대가도 있다.

AI는 제공된 장면/질문/목표의 ID를 선택하고 문장은 서버가 작성한다. 모든 전후 흐름을 이해했는지, 목표가 실제로 실행됐는지, 실력이 향상됐는지, 구독할 가치가 있는지는 이번 시험으로 입증하지 않았다. 같은 파일의 반복 유료 호출보다 저장 응답 카드 화면을 통한 이용자 피드백을 우선한다.

## 저장된 실제 응답의 카드·사건 연결

`cloud-functions/replay-coaching-review-response.js`의 내부 함수 `buildReviewClientResult`는 저장 결과를 기존 서버 검증/재렌더링으로 확인한 뒤 표시용 응답만 만든다. 저장 장부·선택/응답 형식·비용 정산은 바꾸지 않는다. 모델 호출·토큰 계수·DB 읽기/쓰기·HTTP/권한 검사를 수행하지 않는 어댑터다. 향후 운영 API는 먼저 인증·구독/소유권 검사를 통과한 결과에만 이 함수를 적용해야 한다.

표시용 JSON은 schemaVersion1, mode=saved_ai, evidenceHash, response만 포함한다. 공급자 ID·선택 ID·사용량·장부·원본 파일·닉네임은 포함하지 않는다. 공유 도메인 `replay-review-response.js`를 빌드로 서버 ESM 미러에 동기화해 브라우저와 서버가 같은 계약을 사용한다.

근거 해시는 v2의 수치·선정/범위·사건 흐름을 키 순서와 무관하게 정규 직렬화한 SHA-256이다. 서버가 대체하는 고정 설명/한계 문구는 제외한다. **이는 현재 근거와의 일치 검사이며 원본 진위·선수/계정 신원·AI 생성 여부의 인증이나 구독 권한 증명이 아니다.** 같은 수치 구조라면 같은 해시가 될 수 있다. 운영 응답의 진위는 인증된 서버 경계에서 확보해야 한다.

로컬 미리보기의 ‘저장된 AI 해설 확인’에서 최대 8KB의 표시용 JSON을 선택하면 브라우저 메모리에서만 읽는다. 카드 1~2개, 복기/연습별 한 개, 서버 표시 길이 상한, 현재 후보에 속한 단일 라운드 근거를 검사한다. 다른 근거·누락 참조·중복 장면·지원하지 않는 버전·초과 크기·잘못된 JSON은 카드를 보류한다. 파일 내용/파일명을 HTML로 실행하지 않으며 질문과 목표의 줄바꿈은 보존한다.

카드의 근거 버튼은 현재 분석의 후보에서 시각을 조회해 해당 사건 창을 펼치고 정확한 전환에 포커스/강조한다. 응답이 임의의 좌표나 사건 시각을 지정하도록 허용하지 않는다. 잘못된 불러오기는 앞선 카드도 제거한다. 파일 읽기/해시 확인 중 새 파일을 선택하거나 지우기·선수/유형/원본 변경·초기화/재분석을 하면 이전 작업의 결과는 표시하지 않는다. 서버 전송·저장·자동 재시도는 없다.

검증: 새 단위 검사 8개, 로컬 미리보기 브라우저 검사 9개, 기존 무료 리플레이/해설 검사 5개 통과. 밝은/어두운 테마와 390px/1280px에서 카드 표시·정확한 사건 이동·잘못된 응답 보류·문자열 표시를 확인했다. 저장된 실제 두 경기의 응답도 별도 브라우저 검사로 원문 4카드/4사건과 대조했다. 새 AI/계수 호출 및 운영 DB 쓰기는 하지 않았다. 기존 무료 분석과 이전 저장 해설 경로는 그대로다.

이 화면은 정해진 로컬 origin/query에서만 열리는 개발 검증 화면이다. 구독자 권한을 부여하거나 운영 화면에서 유료 AI 버튼을 공개하지 않는다. 서버의 인증·AI 이용권/사용량/소유자 검증은 [비활성 운영 API](replay-coaching-paid-api.md)에 연결했다. 브라우저의 자동 HTTP 수신·실제 결제/이용권 발급·운영 활성화는 아직 하지 않았다.
