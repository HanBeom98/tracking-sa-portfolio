## 리플레이 그래프와 분석 범위

- `matchType: R`은 전후반 3선승·조기 종료·골든라운드 규칙과 이후 라운드의 동등 전력 가정으로 **경기 승리 추정치(%)**를 계산한다. 전반 점수를 다음 라운드에 반영하며 공수교대만으로 50%로 초기화하지 않는다.
- 다른 유형은 생존 인원·기록된 점수·폭탄 상태를 이용하는 **상황 우세 지수(점)**다. 두 지표 모두 실측 데이터로 보정한 승률이나 생성형 AI의 판단이 아니다.
- 현재까지의 기록만 사용하며 최종 승패를 과거 시점의 계산에 미리 반영하지 않는다. 재접속을 복원하더라도 규칙·참가자·인원·폭탄 기록을 검증하지 못한 구간은 계산을 보류한다.
- 이미지 공유와 인쇄/PDF는 기기 안에서 생성한다. 공유 미리보기의 이미지 복사·PNG 저장과 브라우저의 인쇄/PDF 저장은 별도 동작이다.

계산식·지원 조건·보류 사유는 [경기 흐름 재생](replay-playback.md), 홈 가상 경기와 한 선 표시는 [홈·그래프 설명](home-brand-single-line.md)을 따른다.

## Discord 봇

11월 4일 글로벌 명령을 `/전적`·`/리플레이`·`/도움말`로 전환했다. 11월 7일 운영 배포에서 `DISCORD_BOT_VERSION=2`, `DISCORD_REPLAY_ENABLED=true`를 확인했다. 봇은 파일 앞부분의 경기·선수 요약과 웹 상세 분석 링크를 제공하며, 웹의 전체 라운드 분석을 봇에서 실행하지 않는다.

| 요청 | 표시 범위 |
| --- | --- |
| `/전적 닉네임` | 채널 공개 |
| `/리플레이 파일`, `공개:참` | 결과와 원본 JSON 링크를 채널 공개 |
| `/리플레이 파일 공개:거짓` | 요청자만 보기 |
| `/도움말`, 권한·만료·연속 요청 오류, 구형 명령 전환 안내 | 요청자만 보기 |

선수 선택은 공개 범위와 관계없이 요청자만 15분 동안 가능하다. 공개 카드에서 선수를 바꾸면 같은 카드가 갱신된다. 구형 내전 모집·전적 처리 코드는 원복용 어댑터로 분리했고, v2는 구형 요청에 안내를 반환한 뒤 해당 어댑터를 로딩하지 않는다. 기존 세션 함수·데이터·사이트 정산 웹훅은 보존했다.

과거 전체 분석의 38ms와 후속 실제 첨부 두 건의 9ms·3ms는 서로 다른 시점·처리 방식의 관측이다. 현재 성능이나 모든 요청의 무료 실행 한도 보장으로 사용하지 않는다. 읽기 상한·메모리 보관·공개 범위·CPU 검증 이력은 [봇 개편 명세](discord-bot-renewal.md)를 따른다.

## 배포와 검증 기록

main push는 [Site Deploy](../.github/workflows/site-deploy.yml)가 [공통 검증](../.github/workflows/validate.yml)을 호출하고, 전체 검증 성공 후 정적 사이트·Pages Functions를 배포한다. Cloudflare의 main Git 직접 자동 배포는 비활성 상태를 확인했다. 자동 push에서 Firebase 규칙/인덱스·Storage 배포나 게시판 데이터 정리를 실행하지 않는다. 수동 실행 범위는 [개발·검증](development.md#현재-ci와-검사-한계)을 따른다.

11월 7일 코드 변경 최종 스냅샷은 로컬 단위 1,260개·Python 44개, 원격 기본 브라우저 200개와 인증/권한 작업 통과다. [해당 실행](https://github.com/HanBeom98/tracking-sa/actions/runs/42357052186)의 결과이며, 이후 변경이나 모든 입력의 정상 동작을 보장하는 고정 수치가 아니다. 별도 workerd 검사는 외부 통신을 모의한 로컬 검사다. 개선별 근거와 확인 한계는 [유지보수 결과](maintenance-2026-11-07.md)에 정리했다.

최신 운영 버전은 [build.txt](https://trackingsa.com/build.txt)와 해당 배포 실행을 대조한다. 문서 정리 자체를 토스·애드센스 승인, 실결제·유료 AI 활성화, 성능 측정으로 취급하지 않는다.
