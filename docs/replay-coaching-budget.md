# AI 해설 입력·비용 상한과 중단 준비

2026-10-26 후속 [사실·조언 선택 계약](replay-coaching-facts.md)을 내부 구현했다. 현재 모델 입력은 서버의 사실·질문·연습 목록이며 출력은 ID 선택이다. 아래 실제 토큰/품질 측정은 이전 자유 문장 계약의 기록이고 새 계약의 실제 토큰·비용은 미측정이다. 예산·요청 크기·출력 상한과 정산 경계는 유지한다.

2026-10-25. **서버 내부 준비 모듈을 로컬에서 구현·검증했다.** 운영 HTTP 경로와 생성 공급자는 연결하지 않았다. 후속 [소액 품질 시험](replay-coaching-pilot.md)은 로컬 장부로 실제 생성까지 확인했지만 의미 품질 기준은 미달이다. 운영 DB 쓰기는 실행하지 않았다. 기존 `mock` 핸들러와 무료 분석 흐름은 유지한다. 결제 시스템 완성을 뜻하지 않는다.

후속 [로컬 API 연결 준비](replay-coaching-api-setup.md)에서 기존 키를 재사용했고, [단일 호출·정산·결과 복구](replay-coaching-provider.md)에서 초기 표본 전체 입력 **1,450토큰** 측정과 내부 생성 어댑터·응답/usage 해석·결과 저장을 구현했다. 지시문 보완 후 같은 표본은 **1,642토큰**이며, 실제 소액 시험의 usage를 확인했다. 실제 청구서 대조·운영 권한 연결은 미실행이다.

## 구현 범위

| 모듈 | 역할 |
| --- | --- |
| `cloud-functions/replay-coaching-preflight.js` | 정규화된 근거와 고정 지시문·strict JSON Schema로 전체 요청 구성, 토큰 계산 어댑터, 예산 준비·전송 승인 |
| `cloud-functions/replay-coaching-cost.js` | 단가 버전·정수 마이크로달러 계산, 요청 정책·견적·usage·운영 제어 검증 |
| `cloud-functions/replay-coaching-quota.js` | 기존 예약·이용 기간·정산·복구를 재사용하고 통화 장부의 개인 비용·일별 제한·중단 검사를 추가 |

생성 어댑터와 결과 보관·재조회는 후속 내부 모듈로 구현했다. 문장의 의미 품질 판정, 개별 유료 권한 조회, PG는 미구현이다. 새 모듈을 작성했다고 현재 사이트에 실제 AI 비용 차단 기능이 활성화된 것으로 표현하지 않는다.

## 전체 입력과 출력 제한

요청은 `gpt-6-luna`, `reasoning: { effort: 'none', mode: 'standard' }`, `service_tier: 'default'`, `max_output_tokens: 2000`으로 고정한다. 대화 이력·도구·이미지·파일 입력은 없고, `store: false`, `stream: false`, `truncation: 'disabled'`다. 서버에서 정규화한 수치만 단일 사용자 메시지로 넣는다. 지원하지 않는 모델·상위 처리 티어·추론 모드·추가 필드는 정책 검사에서 거절한다.

현재 모델 출력은 카드 1~3개의 kind·factId·questionId·practiceId만 포함하는 strict JSON Schema다. ID의 존재와 장면별 허용 조합을 서버에서 확인하고 기존 화면용 제목 30자·관찰 100자·질문/연습 80자·한계 60자 응답으로 조립한다. 모델 선택의 유용성을 이 구조 검사가 보장하지는 않는다. 이전 자유 문장 출력의 형식 통과 뒤 수치 오류를 발견해 적용한 변경이다.

`createOpenAITokenCounter`는 명시적 `enabled: true`와 서버 키가 있어야 구성할 수 있다. 기본 키 자동 검색·SDK 의존성·자동 재시도는 없다. 고정된 `/v1/responses/input_tokens`에 모델·지시문·메시지·역할·출력 스키마·추론 설정·truncation을 전달한다. 생성 전용 출력 상한 등은 카운트 API 본문에서 제외한다. 5초 이내 실패·잘못된 응답·알 수 없는 토큰 수는 진행을 막는다. 표본 1회의 실제 카운트를 확인했으며 이 어댑터를 운영 경로에 연결하지 않았다.

입력 상한은 **전체 6,000토큰**이다. JSON의 문자·바이트 수를 토큰 수로 환산하지 않는다. 요청 본문 32KiB 제한은 별도 메모리·전송 제한이다. 표본의 전체 입력은 1,450토큰이며 다른 입력에는 별도 카운트가 필요하다. 토큰 API 1회 성공이 계정별 영구 지원·무료 제공을 뜻하지 않는다.

토큰 계산 뒤에는 전체 생성 요청의 SHA-256·모델·단가 버전·입력 토큰·출력 상한·최대 비용·측정 시각을 견적에 고정한다. 유효 기간은 30초이며, 프롬프트·스키마·모델 등을 바꾸면 기존 견적으로 전송할 수 없다. 견적과 요청을 확인하고 전송 시작 상태를 영속화한 뒤, **동일한 동결 요청**을 단일 호출 어댑터에 전달한다. 운영 경로에는 연결하지 않았다.

## 비용 단위와 상한

1달러 = 1,000,000 마이크로달러(`µUSD`)다. 부동소수점 원화 대신 정수와 `BigInt`로 계산하며 요청 비용은 합계에서 한 번 올림한다. 단가 레지스트리는 과거 견적·정산을 읽을 수 있도록 이전 버전을 보존한다. 버전을 새로 추가해도 이전 장부를 0으로 초기화하지 않는다.

| 항목 | 한도 또는 계산 | 적용 조건 |
| --- | --- | --- |
| 단가 버전 | `openai-standard-2026-10-25-luna-v1` | Standard 일반 텍스트 입력 $0.10·출력 $0.50 / 100만 토큰 |
| 요청당 최대 | 1,600µUSD = $0.0016 | 입력 6,000·출력 2,000토큰, 일반 입력 단가 |
| 개인 이용 기간 예산 | 최대 185,185µUSD | 서버가 이보다 작은 예산을 지정할 수 있음 |
| 전체 비용 월 예산 | 최대 4,629,629µUSD | 운영자가 명시적으로 배정한 금액과 비교해 작은 한도 적용 |
| 개인 일별 성공 / 시도 | 한국 시간 날짜별 5회 / 10회 | 실패·전송 전 취소도 개인 시도에는 포함 |
| 개인 이용 기간 | 성공 최대 50회 / 시도 최대 70회 | 기존 서버 지정 월간 기간과 동시 1개 예약 유지 |

개인·전체 상한은 기존 계획의 **400원·10,000원 ÷ (1,800원/달러 × 여유 1.2)**를 마이크로달러로 내림한 값이다. 실제 환율·세금·PG 수수료·호스팅 요금에 대한 보장이 아니다. 요청 최대액의 계획 원화 환산은 3.456원이며 예산 표에서는 4원으로 올렸다.

자동 캐시에는 쓰기 단가가 있으므로 `prompt_cache_options: { mode: 'explicit' }`에 **breakpoint를 하나도 넣지 않는** 요청으로 캐시를 사용하지 않는다. 할인이나 캐시 쓰기 비용을 가정하지 않는다. 지역별 엔드포인트·추가 서비스 비용·가격 변경을 이 고정 단가가 자동으로 포괄하지 않는다. 실제 공급자 연결 전 요청·청구 조건을 재확인한다.

## 장부와 중단 스위치

새 컬렉션은 만들지 않는다. 통화 장부는 기존 모의 단위와 혼합하지 않도록 별도 문서 키와 `accounting: 'usd_micro_v1'` 표식을 사용한다.

| 위치 | 문서 / 추가 메타데이터 |
| --- | --- |
| 사용자 | `_replay_coaching_users/usd_micro_v1_{sha256(uid)}`. 기존 64자리 해시 ID와 겹치지 않는 접두사. 이용 기간별 `spentUnits`, 일별 `days`, 견적·시작 날짜가 붙은 활성 예약과 종료 기록 |
| 전역 비용 월 | `_replay_coaching_months/usd_micro_v1_YYYYMM`. 확정 비용과 미확정 예약을 함께 한도에 반영 |
| 제어 | `_replay_coaching_months/usd_micro_v1_control`. `schemaVersion: 1`, `enabled`, `period`, `allocatedMicros`, `rateVersion` |

제어 문서가 없거나 비활성·배정액 0·다른 비용 월·알 수 없는 단가 버전이면 신규 준비를 중단한다. **월 최대 한도만 선언해 놓고 그 금액을 자동 배정하거나 충전하지 않는다.** 다음 월 활성화·예산 배정도 자동으로 수행하지 않는다. 운영 제어 문서를 만드는 HTTP API·클라이언트 권한·운영 변경 CLI는 추가하지 않았다. 테스트에서만 demo DB에 설정한다.

1. 완료·실패·미확정 요청을 먼저 조회한다. 완료 재확인은 토큰 API나 생성 재호출 없이 기존 상태만 반환한다.
2. 제어 상태를 확인한 뒤 토큰 수를 계산한다. 신규 생성 비용을 예약할 때 같은 트랜잭션에서 제어 문서·개인 장부·전역 장부를 읽는다.
3. 전송 직전에 제어 문서와 견적 만료·이용 기간 만료·비용 월을 다시 확인한다. 중단됐거나 예산이 줄었다면 미전송 예약을 비용 0으로 취소한다.
4. 전송 시작이 기록된 뒤에는 중단됐어도 정상 정산·명시적 복구를 허용한다. 이미 발생했을 수 있는 공급자 비용을 지우지 않는다. 중단 기능으로 이미 전송한 요청까지 취소된다고 보장하지 않는다.

확인된 usage는 입력 수·출력 수·합계·모델·Standard 티어·캐시 읽기/쓰기 0을 검사하고 고정 단가로 환산한다. 입력 수가 견적과 다르거나 비용을 확인할 수 없으면 예약을 유지한다. 종료 기록에는 실제 출력 토큰 수를 남겨 비용을 다시 계산할 수 있게 한다. 전송 전 취소·최대 비용 복구에서는 출력 수가 `null`이다. 후속 어댑터에서 응답 ID·종료 상태·본문을 해석하고 성공 시 검증 결과도 함께 보관한다.

복구에 통화 장부를 지정하려면 기존 서버용 `recoverCoachingQuota`에 `accounting: 'usd_micro_v1'`을 전달한다. 전송 후 미확정 종료는 개인·전역 양쪽에 최대 예약액을 비용으로 남긴다. 원래 비용 월에 정산하며 달력 월 변경으로 개인 지출을 초기화하지 않는다. 새 이용 기간의 예산은 새로 집계하되 이전 두 기간의 비용·중복 기록을 유지한다.

현재+이전 두 이용 기간에 종료 기록 최대 210개, 각 기간의 일별 버킷 최대 33개를 보관한다. 해설·요약·원본·인증 토큰을 저장하지 않는다. 예약 비용과 견적 메타데이터만 추가한다. 클라이언트는 제어 문서를 포함한 모든 장부에 접근할 수 없다.

통화 경로의 정상 흐름은 기본 트랜잭션 4회·문서 읽기 10회·쓰기 5회와 토큰 계산 요청 1회다. 트랜잭션 재시도로 읽기가 늘 수 있다. 기존 모의 HTTP 경로는 3회·6읽기·5쓰기로 유지한다. 무료 할당량과 별도의 호스팅 비용은 실제 운영 전에 확인한다. 새 스케줄·수집·분석·TTL·별도 결과 컬렉션은 없으며, 결과는 기존 종료 기록에 제한 보관한다.

## 검증과 다음 단계

단위 검증은 전체 요청 전달·토큰 계산 실패/상한/타임아웃·단가 고정·올림·개인/전체 예산·중복·동시 요청·일별 제한·중단 경합·견적 변경/만료·실패 비용·미확정 복구·달력 월 변경·이용 기간 갱신·모의 장부 혼합 거절을 확인한다. Firestore Emulator에서는 실제 트랜잭션으로 동시 예약과 중단, 정상 정산 대 복구 경합, 장부 접근 거절을 확인한다. 기존 모의 브라우저 흐름도 회귀 검사한다.

첫 Emulator 검사에서 복구 함수가 아직 모르는 전역 월을 빈 문서 ID로 만들던 문제를 발견해, 사용자 참조와 월 참조 생성을 분리했다. 테스트 DB도 빈 ID를 실제 SDK처럼 거절하도록 보완했다. 로컬 테스트 통과를 실제 결제·공급자 청구 보증으로 표현하지 않는다.

이전 소액 실제 시험에서 생성·usage·전체 경로 시간을 확인했고, 이후 사실 문장의 서버 확정과 상황별 선택 계약을 내부 구현했다. 다음은 새 계약의 실제 선택 유용성과 무료 해설 대비 추가 가치를 평가하는 단계다. 내부 생성·usage/오류 매핑·자동 재시도 0회·결과 유실 복구는 구현했지만, 의미 품질·운영 연결·고객별 유료 권한·개인정보 보관 안내가 완료되기 전에는 유료 상품을 공개하지 않는다. 기존의 Luna/Sol 비교 계획은 제안이며 현재 가드는 **Luna만** 허용한다. Sol 비교가 필요하면 별도의 가격 버전·한도·시험 예산을 먼저 검토해야 한다.
