# 리플레이 인쇄·PDF 보고서

개발: 2026-10-28, 배포 준비: 2026-10-29. 한 경기 기본 분석 결과를 보고서로 정리하는 기능의 구현·검증 기록이다. 실제 공개 버전은 [현재 상태](current-status.md)의 배포 확인 방법으로 대조한다. [문서 목차](README.md).

## 사용 흐름

1. JSON 한 개 또는 가상 샘플을 분석하고 선수를 선택한다.
2. 결과 상단의 **보고서 / PDF**를 누른다. 재생을 일시정지하고 별도 미리보기를 연다.
3. 닉네임·경기 정보·검증 범위를 확인한 뒤 **인쇄 / PDF 저장**을 누른다.
4. 브라우저 인쇄 창에서 프린터 또는 **PDF로 저장**을 선택한다. 브라우저 머리글·바닥글을 끄면 URL 등 자동 표시를 제외할 수 있다.
5. 닫기 또는 Escape로 미리보기를 닫는다. 기존 결과·필터·재생 위치는 유지하고 초점은 보고서 버튼으로 돌린다. 재생은 자동 재개하지 않는다.

PDF 저장 메뉴와 지원 범위는 브라우저·기기에 따라 다르다. 직접 PDF 파일을 생성하는 유료 서비스나 별도 PDF 라이브러리를 웹에 추가하지 않는다. 현재 여러 경기 비교 표와 유료 AI 응답을 보고서에 합치는 기능은 포함하지 않는다.

## 내용과 집계 범위

| 항목 | 기준 |
| --- | --- |
| 경기 정보 | 선택 선수 닉네임·맵·경기 시각·점수·결과. 가상 샘플은 표시 유지 |
| 경기 총계 | 공식 JSON의 선수 요약 K/D/A·피해량. 라운드별 사건 집계와 범위가 다를 수 있음 |
| 검증 지표 | `context.status === 'complete'`인 라운드 수·처치/사망·평균 생존·라운드 생존율 |
| 주요 장면 | 기존 `getKeyMoments` 규칙에 검증 라운드만 전달. 검증 가능한 라운드가 없으면 선정하지 않음 |
| 라운드 표 | 화면의 접힘·필터와 무관하게 제공된 모든 라운드 표시. 상황 검증 보류값은 대시로 표시하고 추정하지 않음 |
| 한계 | JSON 기록의 재구성이며 실제 시야·음성·의도·인과관계·실측 승리 확률을 입증하지 않음 |

이탈·재입장의 [재생 복원](replay-playback.md)과 통계의 엄격한 상황 검증은 범위가 다르다. 그래프가 복원되었다는 이유로 보고서의 검증 보류 라운드를 완료로 바꾸지 않는다. 검증 지표의 평균 생존은 검증 라운드 생존 시간 합계/검증 라운드 수이며 생존율은 그중 사망 없이 마친 비율이다. 검증 라운드가 없으면 0% 대신 집계 불가로 표시한다.

## 처리·접근성·수명

- 보고서 모듈은 버튼을 처음 누를 때 동적으로 읽는다. 기본 분석 진입 시 미리 가져오지 않는다.
- 보고서 작성은 현재 분석 결과의 허용 필드만 복사한다. 추가 API·AI 호출, DB 쓰기, 파일/결과 전송, 자동 폴링, 영구 저장을 추가하지 않는다. 기존 한 경기 전력 조회와 페이지 공통 SDK 동작까지 없앴다는 뜻은 아니다.
- 경기/선수 ID·좌표·원본 파일명·현재 URL·전력 응답·유료 해설 장부는 보고서 본문에 넣지 않는다. 닉네임·경기 시각은 포함되므로 이용자가 공유 전에 확인한다. 브라우저 자체 인쇄 헤더의 URL 표시는 별도 설정이다.
- native dialog의 모달 초점과 Escape를 사용한다. 닫기·초기화·선수 변경·새 분석·페이지 종료 때 임시 DOM과 인쇄 이벤트를 정리한다. 인쇄 중 임시 문서 제목은 완료/취소 또는 미리보기 종료 때 복구한다.
- 모듈 대기 중 파일·선수가 바뀌면 이전 보고서를 열지 않는다. 불러오기 실패 시 기존 분석을 유지하고 새로고침 안내를 표시한다.
- 인쇄에는 사이트 메뉴·업로드·조작부를 제외하고 흰색 A4 보고서를 출력한다. 긴 표는 페이지를 나누고 열 제목을 반복한다. 화면 테마는 바꾸지 않는다.

## 검증 근거

단위 검사는 샘플 수치·검증 보류 제외·빈 집계·입력 불변/스냅샷·개인 식별자 제외·HTML 이스케이프를 확인한다. 로컬 브라우저 검사는 390/1280px×밝은/어두운 테마, 전체 라운드·인쇄 스타일·초점 복구·지연된 모듈/실패·긴 표와 보류 표시를 확인한다. 관련 검사를 기본 CI에 포함한다.

실제 Chromium PDF 출력을 생성해 페이지를 이미지로 렌더링했다. 가상 6라운드는 1페이지, 보류 1개를 포함한 합성 40라운드는 2페이지에서 마지막 라운드와 안내까지 확인했다. 브라우저 버전·인쇄 설정에 따라 페이지 수는 달라질 수 있다. 운영 API·DB·유료 AI·프린터 장치와 실기기 PDF 메뉴를 검증한 것은 아니다.

이전에 제공받은 실제 JSON 두 개도 외부 호출 없이 확인했다. 각각 전체 6/8라운드 중 엄격한 상황 검증 5/5라운드만 집계하고, 보류 1/3라운드를 표에 유지했다. 두 파일 모두 보고서 주요 장면이 검증 라운드에만 연결되는 것을 확인했다.
