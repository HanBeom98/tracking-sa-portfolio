# 회원별 이용권 구매 내역·잔여 횟수 조회

2026-10-27. **판매가 꺼진 내부 구매 경로와 로컬 미리보기의 구현·검증 기록**이다. 실제 판매·운영 경로 배포·가맹 재접수는 이번 작업에 포함하지 않는다. 공개 심사용 TEST가 운영 잔액을 지급하는 구조로 바뀌지 않는다.

## 이용자가 확인하는 내용

로그인한 계정으로 ‘내역 조회 / 처음부터 새로고침’을 누르면 최근 주문 10건을 확인한다. 주문번호를 브라우저에 보관하지 않은 다른 기기에서도 같은 계정의 내역을 조회하는 구조다. 페이지 밖의 이용권도 포함한 전체 잔여 횟수를 별도로 표시하며 다음 페이지는 ‘다음 10건’을 눌러 읽는다.

| 표시 | 기준 |
|---|---|
| 기간 내 미사용 | 아직 만료되지 않았고 분석·환불에 잡히지 않은 횟수 |
| 분석 처리 중 | 진행 중 요청이 예약한 횟수. 새 분석에 중복 사용하지 않음 |
| 환불 대기 | 기존 환불 예약에 잡힌 횟수. 환불 완료로 표시하지 않음 |
| 만료된 미사용 | 기간이 끝난 미사용 횟수. 기록을 삭제하거나 자동 환불하지 않음 |
| 사용 완료·환불 완료 | 원장에 확정된 각각의 횟수 |
| 주문별 내역 | 구매 당시 횟수·금액·주문일·결제 완료일·만료일·상태 및 각 횟수 |

계정 이용 제한 상태는 별도 안내한다. ‘기간 내 미사용’ 횟수가 있어도 제한된 계정이 새 분석을 쓸 수 있다는 의미는 아니다. 로그인 계정을 바꾸거나 로그아웃하면 이전 내역을 지우고, 이전 계정에서 시작한 늦은 응답도 버린다.

## 서버·조회 비용 범위

- 인증 토큰의 UID로 비공개 계정 경로를 정한다. 요청자가 UID·경로·가격·조회 개수를 지정할 수 없다. 브라우저가 DB를 직접 조회하도록 규칙을 개방하지 않는다.
- 기존 주문 컬렉션을 생성 시각 내림차순, 같은 시각은 문서 ID 내림차순으로 조회한다. 값 커서를 사용하여 offset/전체 스캔을 하지 않는다. 기본 단일 필드 색인의 문서명 정렬 방향과 맞췄으며 새 색인 정의를 추가하지 않았다.
- 다음 페이지 유무를 판단할 주문 최대 11건과 지갑 문서 1개를 한 읽기 전용 트랜잭션으로 읽는다. 이것은 읽는 문서 범위를 제한한 것이며 실제 요금 전체를 문서 수만으로 보장하는 수치는 아니다.
- 주문과 지갑의 횟수·만료일이 불일치하거나 소유자가 손상돼 있으면 부분 결과를 반환하지 않는다. 결제사 토큰·원본 응답·결제 해시·AI 요청/비용·다른 계정 정보는 반환하지 않는다.
- 자동 조회·실시간 리스너·추가 저장·조회 로그 컬렉션·예약 작업·결제/AI 호출을 추가하지 않았다. 일반 구매 응답의 4KiB 제한은 유지하고, 최대 10건인 내역 응답만 16KiB로 제한한다.
- 내역은 조회 시점의 스냅샷이다. 페이지를 이동하는 사이에 생긴 새 주문은 처음부터 새로고침하면 확인한다. 조회 화면 자체에서 결제 승인·환불·횟수 지급을 실행하지 않는다.

## 검증

| 검증 | 결과 |
|---|---|
| 전체 단위 테스트 | 1,019개 통과 |
| 구매/내역 브라우저 | 10개 통과, 모바일390px·PC1280px 포함 |
| Firestore Emulator | 8개 통과: 신규 내역4건 + 기존 결제/복구4건 |
| 빌드·구조 | build, source-of-truth, public-edit-policy, build-artifacts, source-graph 통과 |

본인/타인/미로그인 접근, 페이지 경계의 같은 생성 시각, 원장 손상, 만료 정각, 실제 분석 예약·환불 예약의 분리, 사용 처리와 조회의 동시 실행, 중복 클릭·실패 후 수동 재조회·계정 전환 중 늦은 응답을 확인했다. 실서비스 DB·결제·유료 AI 대신 합성 원장과 로컬 demo Emulator를 사용했다. Admin SDK는 이미 설치된 운영 의존성을 재사용했으며 새 패키지를 추가하지 않았다.

서버 SDK를 쓰는 Emulator 테스트에는 `cloud-functions/package.json`의 기존 의존성이 설치되어 있어야 한다(`npm.cmd --prefix cloud-functions ci`). 이 작업에서는 중복 설치 대신 기존 배포 작업 폴더의 설치본을 `NODE_PATH`로 연결했다. 테스트는 `FIRESTORE_EMULATOR_HOST=127.0.0.1:8085`와 demo 프로젝트를 검사하고, 로컬 Emulator가 없으면 운영 DB로 대체 접속하지 않는다.

## 남은 단계

현재 화면은 명시적인 로컬 구매 미리보기에서만 열린다. 후속으로 [개발 미리보기 조건 확인 문구·버전·서버 시각 기록](replay-coaching-purchase-acknowledgement.md)을 구현했다. 실제 판매 약관 동의를 완료한 것은 아니다. 운영 인증 HTTP 경로·실제 계정 AI·LIVE 제공자·가맹 승인·확정 제공/환불 정책은 판매 전 별도로 연결해야 한다. 현재 구매 조건은 3,300원·50회·365일이며 기존 구매 조건을 소급 축소하지 않는다.
