# AI 리플레이 해설 비용·이용 한도 설계안

2026-10-26 현재는 [사실·질문·연습 ID 선택 계약](replay-coaching-facts.md)을 내부 구현·오프라인 검증했다. 아래 가격·예산 정책은 유지하되 이전 프롬프트의 측정값을 새 계약에 재사용하지 않는다. 새 선택 품질·실제 입력 토큰·생성 비용은 미검증이다.

2026-10-25 최초 설계. 판매 조건이나 운영 설정에는 적용하지 않았다. 이후 소액 실제 시험을 수행했고 그 결과를 바탕으로 선택 계약을 내부 구현했다. 기존 모의 API·무료 분석 기능은 그대로 유지한다.

## 1. 모델 선택과 건당 계산

먼저 `gpt-6-luna`의 짧은 한국어 해설을 평가한다. 이미 코드가 계산한 전체 집계와 최대 6개 장면을 해석하는 작업이므로 비용이 낮은 모델부터 확인했다. 후속 [소액 실제 시험](replay-coaching-pilot.md)에서 API 연결·응답 시간은 확인했지만 사실·맥락 품질은 부족했다. 개발에 사용하는 Codex 모델 설정과 사이트가 호출할 API 모델은 별도다.

공식 Standard 텍스트 요금은 다음과 같다. Batch/Flex·캐시 할인·도구 호출을 전제로 하지 않는다. [OpenAI 요금표](https://developers.openai.com/api/docs/pricing), [Luna 모델 사양](https://developers.openai.com/api/docs/models/gpt-6-luna).

| 후보 | 입력 / 100만 토큰 | 출력 / 100만 토큰 | 입력 6,000 + 출력 2,000의 달러 비용 | 계획 원화 비용 | 요청 전 예약액 | 용도 제안 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| GPT-6 Luna | $0.10 | $0.50 | $0.0016 | 3.456원 | 4원 | 우선 평가 후보, `reasoning.effort: none` |
| GPT-6.1 Sol | $2.00 | $10.00 | $0.032 | 69.12원 | 70원 | 품질 비교 후보, 낮은 추론 설정부터 |
| GPT-6 Astra | $10.00 | $50.00 | $0.16 | 345.6원 | 346원 | 초기 상품의 상시 호출 후보에서 제외 |

계산식: `(입력 토큰 × 입력 단가 + 출력 토큰 × 출력 단가) / 1,000,000`.

원화 계획값은 **1달러 = 1,800원, 추가 여유 20%**로 계산했다. 현재 환율을 조회한 값이나 실제 부가세·카드 수수료율이 아니다. 요청별 예약액은 그 값을 원 단위로 올림했다. 청구 단가·환율·부가 비용이 가정을 벗어나면 설정을 다시 검토한다. 이 표는 토큰 제한을 구현했을 때의 비용 시나리오이며 현재 코드가 실제 과금을 이 금액으로 차단한다는 뜻이 아니다.

## 2. 입력·출력·호출 제한

| 항목 | 제안 | 현재 상태 |
| --- | --- | --- |
| 입력 | 지시문·요약·응답 스키마·메시지 구조를 모두 포함해 최대 6,000토큰 | 전체 요청·카운트·상한 검사 구현. 실제 표본 1명의 전체 입력 1,450토큰 측정 |
| 출력 | `max_output_tokens: 2000` | 단일 호출 내부 어댑터에 고정. 실제 소액 생성 시험 완료, 의미 품질 기준 미달로 운영 연결 보류 |
| 해설 분량 | 근거가 있는 카드 최대 3개. 제목 30자·관찰 100자·연습 80자·한계 60자 이하를 우선 평가 | 기존 검증기의 상한보다 짧은 생성 목표. 품질·완성률 측정 필요 |
| 형식 | Structured Outputs의 strict JSON Schema와 기존 근거 참조 검증을 모두 적용 | 실제 소액 시험의 형식 검사는 통과했지만 문장의 사실성까지 보장하지는 않음 |
| 호출 | 하나의 요약에 모델 생성 1회. SDK·서버의 자동 재시도 0회 | 현재는 로컬 모의 생성만 실행 |
| 부가 기능 | 웹 검색·파일 검색·이미지·도구·대화 이력 없음. 캐시 쓰기 정책 추가 없음 | 유료 기능 없음 |
| 모델 전환 | 실패해도 Sol/Astra로 자동 전환하지 않음 | 실제 모델 모드 자체가 비활성 |

출력 상한에는 보이는 문장뿐 아니라 추론·보이지 않는 형식 토큰도 포함된다. 제한에 걸려 불완전 응답이 되면 문장이 없더라도 비용이 발생할 수 있다. 따라서 Sol의 작은 출력 예산은 품질 비교에서 실패할 수 있으며 자동으로 상한을 늘리지 않는다. [OpenAI 추론 비용과 불완전 응답 설명](https://developers.openai.com/api/docs/guides/reasoning#controlling-costs).

입력 6,000토큰은 JSON 바이트 수로 환산해 보장하지 않는다. 공식 input token count 기능은 메시지 구조까지 계산한다. 후속 모듈은 동일한 입력·스키마를 카운트에 전달하고 확인 실패 시 예약을 거절한다. 호출 비용·지연과 계정 지원 여부는 실제 활성화 전에 확인한다. 상세를 줄일 때는 전체 집계와 생략 수를 일관되게 재구성하고 다시 검사해야 한다. 이번에는 해당 API도 호출하지 않았다. [OpenAI 토큰 계산 안내](https://developers.openai.com/api/docs/guides/token-counting).

## 3. 월 3,300원 상품의 조건부 제안

**Luna가 품질 평가를 통과하면 결제 기간당 유효 해설 50회**를 우선안으로 삼는다. 기존 무료 리플레이 분석은 계속 사용할 수 있게 한다. 한도 이월·초과 자동 결제는 넣지 않는다. Sol이 필요하다면 판매를 시작하기 전에 20회 안으로 원가·상품성을 다시 검토한다. 이미 판매한 50회를 모델 변경을 이유로 줄이는 방식은 사용하지 않는다.

| 모델 | 20회 전부 상한 사용 | 30회 전부 상한 사용 | 50회 전부 상한 사용 |
| --- | ---: | ---: | ---: |
| Luna | 80원 | 120원 | 200원 |
| Sol | 1,400원 | 2,100원 | 3,500원 |
| Astra | 6,920원 | 10,380원 | 17,300원 |

이는 정상 생성 비용 예약액만 합산한 표다. 실패·환불·PG·세금·서버 운영비를 포함한 순이익 표가 아니다. 특히 Sol 50회는 정상 AI 비용만으로 상품 가격을 넘는다.

페이앱은 공개 비용 안내에서 사업자 일반 카드 3.4%, 비사업자 카드 4.0%를 VAT 별도로 안내한다. 수수료 VAT까지 단순 반영하면 3.74%·4.4%다. **실물 기준이며 비실물은 인상 가능**하다고 명시하므로 TrackingSA의 실제 정기결제 요율로 확정하지 않는다. 등록비 면제도 현재 무료 이벤트다. 기존 문의 답변·서비스 허용·최종 계약·보험 조건 확인이 별도로 남아 있다. [페이앱 공식 비용 안내](https://www.payapp.kr/homepage/guide/guide1.html).

| 1인 결제 3,300원 기준 | 공개 사업자 일반 예시 | 공개 비사업자 예시 | 요율 인상 가정 | 추가 스트레스 가정 |
| --- | ---: | ---: | ---: | ---: |
| PG 요율 가정(VAT 포함) | 3.74% | 4.4% | 10% | 15% |
| PG 수수료(원 단위 올림) | 124원 | 146원 | 330원 | 495원 |
| Luna 정상 50회 예산 | 200원 | 200원 | 200원 | 200원 |
| 실패·미확정 비용 여유 | 200원 | 200원 | 200원 | 200원 |
| 세금·환불·운영 대응 예비비 | 1,000원 | 1,000원 | 1,000원 | 1,000원 |
| 차감 후 미배정 금액 | 1,776원 | 1,754원 | 1,570원 | 1,405원 |

1,000원은 세법에 따른 납세액 산출이 아닌 임의의 사업 계획 예비비다. 미배정 금액은 순이익이 아니며 실제 세금·정산·보험·호스팅·고객 대응 비용과 환불에 따라 줄어든다. 10%·15%는 페이앱 실제 요율이 아닌 민감도 가정이다.

| 제한 | Luna 초기안 | 이유 |
| --- | --- | --- |
| 사용자 권한 | 서버에서 확인한 결제 기간당 유효 해설 50회 | 결제 화면 성공 표시만으로 권한 부여하지 않음 |
| 일별 제한 | 한국 시간 기준 유효 해설 5회·모델 시도 10회 | 하루 집중 사용과 실패 반복 제한 |
| 기간 시도 상한 | 정상·실패·미확정을 합해 최대 70회 | 50회와 실패 여유를 분리. 한도 도달 시 오류 안내/운영 확인 |
| 개인 비용 상한 | 결제 기간당 400원 상당의 달러 예산 | 정상 200원 + 실패 여유 200원. 외부 호출 전 최대 비용 예약 |
| 전체 비용 상한 | 미사용 유료 배정 예산 안에서, 초기 달력 월 10,000원 상당 이하 | 10,000원을 자동으로 지출하는 것이 아님. 미판매 상태의 운영 배정액은 0 |
| 동시 요청 | 계정당 1개, 예약액을 전역 합계에 포함 | 동시에 들어와도 비용 상한 우회 방지 |

금액 장부는 부동소수점 원화가 아니라 **정수 마이크로달러(1달러=1,000,000단위)**로 설계한다. Luna 상한 요청의 기본 생성 예약은 1,600단위다. 원화 예산은 계획 환율·여유를 적용해 달러 단위로 내림 변환한다. 단가/모델/제한 버전을 예약에 고정하고, 예상 초과나 알 수 없는 요금은 요청을 막는다. 가격·지원 여부가 바뀌면 자동으로 다른 모델을 쓰지 않는다.

전체 달력 월 한도와 사용자의 결제 기간 한도는 별개다. 결제일이 월말이라는 이유로 달력 월이 바뀔 때 이용권을 한 번 더 지급하지 않는다. 환불·해지 시 기존 지출·미확정 예약을 지우지 않는다. 별도의 소액 품질 시험 예산은 운영 구독 예산과 분리한다.

## 4. 실패·중복·미확정 정산

**사용자 이용 횟수와 공급자 비용을 분리**한다. 해설이 쓸 수 없어 사용자에게 무료 처리해도 이미 생성한 토큰 비용은 운영자 비용으로 남는다.

| 상황 | 사용자 횟수 | 공급자 비용 장부 | 후속 동작 |
| --- | --- | --- | --- |
| 인증/권한/입력/토큰 검사에서 거절 | 차감 없음 | 생성 비용 없음 | 공급자 생성 미호출 |
| 예약 후 외부 전송 전 중단이 확정 | 예약 해제 | 비용 예약 해제 | 동일 작업의 안전한 상태 전환만 허용 |
| 완전한 응답 + 형식/근거 검증 통과 | 1회 확정 | usage 기반 비용 확정 | 결과 확인과 함께 확정, 추가 생성 없음 |
| 토큰 부족·거부·형식/근거 검증 실패 | 성공 횟수 차감 없음 | usage가 있으면 실제 비용, 없으면 최대 예약액 보수적 확정 | 실패 시도는 기록. 자동 재생성/상위 모델 호출 없음 |
| 네트워크 단절·타임아웃·5xx·저장 결과 불명 | 확정 차감하지 않고 보류 | 사용됐을 수 있는 최대액을 유지 | 같은 요청 ID로 상태만 확인. 새 생성 호출로 우회하지 않음 |
| 같은 ID 재확인·중복 클릭 | 추가 차감 없음 | 외부 생성 추가 호출 없음 | 저장 상태/보관 중인 결과만 반환 |
| 운영 확인 후에도 실제 비용을 모름 | 이용 횟수 예약 복구 | 최대 예약액을 지출로 확정 | 해당 작업은 재실행 불가 상태로 종료. 이전 실행의 늦은 쓰기를 차단 |

외부 전송 직전에 영속적인 `dispatching` 상태를 기록한다. 그 이후 프로세스가 죽으면 전송/청구 여부를 임의로 미사용 처리하지 않는다. 운영자가 요청 ID·응답 ID·토큰 사용량·상태·가격 버전을 확인해 복구하며, 본문/토큰 키/개인정보는 로그에 남기지 않는다. 아직 전송하지 않았다는 증거 없이 예산을 되돌리는 타이머는 만들지 않는다.

설계 당시의 `finishCoachingQuota(..., false)`는 모의 생성 실패에 비용이 들지 않는다는 전제였다. 현재는 [정산·복구 단계](replay-coaching-settlement.md)에서 사용자 성공과 비용 단위를 분리하고, [통화 준비 모듈](replay-coaching-budget.md)에서 숫자 usage·단가 버전 검증을 추가했다. [단일 호출·결과 복구](replay-coaching-provider.md)에서 응답/오류 해석도 내부 구현했다. 실제 생성 시험에서는 usage 환산과 로컬 정산을 확인했고 청구서 대조는 미실행이다. 로컬 모의 단위를 실제 유료 정산으로 취급하면 안 된다.

OpenAI의 지출 알림과 강제 상한은 별도 기능이며, 공식 강제 상한도 반영 지연으로 소폭 초과할 수 있다고 설명한다. 공급자 설정은 보조 수단으로 두고 사이트 자체의 사전 예약 장부를 먼저 적용한다. 이번에는 계정의 지출 한도·결제·자동 충전 설정을 변경하지 않았다. [OpenAI 지출 한도](https://developers.openai.com/api/docs/guides/spend-limits).

| 4 | 토큰 계산·생성 JSON 스키마·단가 버전 검사 준비 | 내부 구현·실제 소액 시험 완료. 초기 표본 입력 1,450토큰, 필드 설명 보완 후 1,642토큰. 운영 미연결 |

초기 제안은 최신 결과 1개·16KiB·24시간 조회였다. 후속 [결과 복구 구현](replay-coaching-provider.md)은 다른 작업 뒤에도 기존 요청을 복구하도록 종료 기록과 함께 결과당 3,072바이트·현재/이전 2개 이용 기간에 제한 보관한다. 결과 최대 150개·종료 기록 최대 210개이며 별도 문서 쓰기·TTL·예약 작업은 없다. 24시간 후 자동 삭제하지 않으며 운영 도입 전 개인정보 처리방침·보관/삭제 안내를 최종 동작에 맞춰야 한다. 이번 저장 검증은 로컬 데모에만 실행했다.
