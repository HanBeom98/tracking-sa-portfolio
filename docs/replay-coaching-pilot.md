# Luna 실제 해설 품질 시험과 출시 보류

후속 2026-10-26 [사실 확정·상황별 선택 계약](replay-coaching-facts.md)을 내부 구현·오프라인 검증했다. 아래는 이전 자유 문장 계약의 실제 시험 기록이며 새 선택 계약의 실제 AI 품질은 아직 시험하지 않았다.

2026-10-25. **실제 API 연결과 비용 정산은 동작했지만, 사실성과 조언 품질 기준은 통과하지 못했다.** 기존 무료 분석·모의 화면을 유지하고 실제 유료 기능과 구독 판매를 활성화하지 않았다. 시험은 익명 수치 요약과 로컬 파일 장부만 사용했으며 운영 DB·배포·결제 설정을 바꾸지 않았다.

## 표본과 확인 방법

제공받은 실제 한 경기의 선택 선수 1명과 합성 경계 사례 11개를 사용했다. 실제 사례의 교환킬 설명 오류를 발견해 지시문을 보완한 뒤, 보완 버전으로 12개 사례를 각 1회 시험했다. 데이터가 불충분한 사례는 외부 호출 전 로컬에서 거절되는 것도 확인했다.

모델은 `gpt-6-luna`, 추론 `none`, Standard, 출력 상한 2,000토큰, 캐시 읽기/쓰기 없음이다. 다른 모델이나 상위 처리 티어로 자동 전환하지 않았다. 시험용 사용자·예산 장부는 로컬 파일에만 존재하며 기존 운영 구독 권한이나 Firestore에 쓰지 않았다. 계정의 비공개 비용·usage 상세와 개별 응답은 저장소 밖 점검 기록에 보관한다.

| 검사 | 보완 후 표본의 결과 |
| --- | --- |
| 응답 완료·JSON 형식·분량·허용 근거 ID | **12/12 통과** |
| 생성 카드 수 | **19개** |
| 수동 대조에서 확인한 명확한 수치 오류 | **1개 카드** |
| 실제 응답의 모델·티어·토큰/캐시 usage와 정산 | 계약과 일치, 미확정 예약 없음 |
| 전체 요청 경로 시간 | 2.1~5.4초, 중앙값 약 2.8초 |
| 유료 제공 판단 | **보류** |

시간은 토큰 계산 API·생성·로컬 장부 저장을 합한 단일 실행 경로다. 모델 생성 시간만의 측정이나 운영 화면 성능 보증이 아니다. 내용 대조는 코딩 보조 에이전트의 수동 검토이며 전문가/사용자 만족도 평가가 아니다. 실제 한 경기와 소수 합성 사례로 일반 정확도나 안정성을 추정하지 않는다.

## 발견한 문제와 대응

| 사례 | 모델 설명 또는 조언 | 근거와 판단 | 대응 |
| --- | --- | --- | --- |
| 실제 리플레이의 교환킬 수혜 후보 | 본인 사망 3.5초 뒤 아군이 사망했다고 설명 | 실제로는 본인을 죽인 상대를 **팀원이 처치**한 기록 | `tradesMade`/`tradesReceived`, 후속 처치 시각·간격·직전 아군 사망 수의 뜻을 고정 지시문에 추가. 같은 실제 표본 재시험에서는 올바르게 구분 |
| 아군의 연속 사망 뒤 단독 상황 | 2초에 아군 3명·적 3명이 살아 있다고 설명 | 3명은 라운드 **시작 인원**. 2초에는 본인만 남아 **1대3** | 지시문만으로 숫자의 시점을 보장할 수 없음을 확인. 사실 문장을 서버에서 확정하는 다음 작업 필요 |
| 이미 혼자 남은 상황 | 팀과 합류하는 루틴을 권함 | 해당 시점에는 합류할 생존 팀원이 없음 | 생존 인원과 단독 여부에 맞는 조언 조건 필요 |
| 본인이 생존한 교환킬 성공 후보 | 본인의 사망과 후속 처치를 구분하라고 권함 | 기록에 없는 본인 사망을 연습 주제로 사용 | 교환킬 수행/수혜와 본인 사망 여부를 조언 조건으로 분리할 필요 |
| 서로 다른 시각의 사건 | 사건 순서를 알 수 없다고 과도하게 유보 | 기록상 다른 시각과 간격은 확인됨 | 확인 가능한 시간 순서와 알 수 없는 의도·시야를 구분해야 함 |

보완 후 실제 표본에서는 다음 사실을 올바르게 기술했다.

- 검증된 9라운드의 8킬·5사망, 첫 처치 2회·첫 사망 0회.
- 8라운드 15.3초 사망과 3.5초 뒤 팀원의 후속 처치 후보를 구분.
- 6·7라운드의 첫 처치 이후 사망 기록을 함께 선택.

그러나 연습 제안은 대부분 기록을 다시 확인하라는 수준이었다. 기존 무료 규칙 해설보다 유료 이용자가 체감할 추가 가치가 충분하다고 판단하지 않았다. 근거 ID가 실제로 존재하고 JSON 형식이 맞아도 그 문장의 사실성이 검증되는 것은 아니다. 현재 내부 경로의 `customerSuccess`는 형식 검증 뒤의 정산 결과이며, 전문가 수준의 의미 품질 보증을 뜻하지 않는다.
