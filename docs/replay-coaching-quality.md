# 리플레이 해설 품질 검증

2026-10-25. 유료 AI를 연결하기 전, **현재 규칙 기반 근거와 모의 해설 문장이 원본 기록에 맞는지** 로컬에서 확인했다. 실제 AI 답변 품질, 연습 효과, 결제 안전성을 검증한 결과가 아니다. 운영 코드·화면·결제·호스팅 설정은 변경하지 않았다.

## 검사 방식

`scripts/replay-coaching-quality.mjs`는 원본 사건에서 매 시점의 이전 사망자와 최근 처치를 직접 조회한다. 기존 분석기의 순차 상태 갱신 함수를 재사용하지 않고, 생존 인원·첫 사건·교환킬 후보·혼자 남은 상황·공수·결과·사망 후 처치를 다시 계산한다. 라운드 요약 K/D, 전체 집계, 최대 6개 상세 근거, 서버 입력 정규화, 현재 모의 문장의 사실을 대조한다.

라운드가 검증 가능한지에 대한 선택 자체는 기존 분석기의 판정을 사용한다. 이 부분까지 독립적으로 입증한 것으로 보지 않는다. 재접속으로 제외되는 라운드와 검증 표본이 없는 경우는 별도로 정답을 지정한 합성 사례로 확인한다.

## 실제 파일 결과

사용자가 제공한 공식 JSON 한 편을 읽었으며, 원본·닉네임·계정 ID는 저장소에 추가하지 않았다. 로컬 결과에는 선수 순번과 수치·식별자 없는 관찰 문장만 남긴다. 다른 실제 파일에도 같은 명령을 적용할 수 있다.

| 항목 | 결과 | 해석 |
| --- | --- | --- |
| 실제 경기 파일 | 1편 | 여러 경기의 대표 표본이 아님 |
| 선수 / 라운드 | 10명 / 9라운드 | 동일 경기의 다른 관점 |
| 검증한 선수별 라운드 | 90개 | 90경기를 검사한 뜻이 아님 |
| 제외한 선수별 라운드 | 0개 | 이 파일에서만 모두 검증 가능 |
| 대조한 모의 관찰 문장 | 30개 | 수치·시각·생존 인원·근거 일치 |
| 발견한 원본과의 불일치 | 0건 | 현재 표본·지원하는 규칙 범위의 결과 |

## 합성 품질 사례

| 사례 | 기대하는 동작 |
| --- | --- |
| 사건 없는 검증 라운드 | 실제 0킬·0사망으로 표시 |
| 동시 첫 처치·사망 | 사건 순서를 임의로 정하지 않고 0초 교환킬 제외 |
| 사망 후 처치 | 킬에는 포함하고 생존 시간과 구분 |
| 교환킬 5초 / 5.1초 | 경계 안만 후보로 포함 |
| 사망 후 팀원 대응 | 사망 시 인원과 대응까지의 시간을 대조 |
| 같은 상대가 연속 처치 | 가장 최근 피해자 기준 유지 |
| 같은 시각에 여러 팀원 사망 | 피해자 수를 유지하고 후보를 중복 집계하지 않음 |
| 여러 팀원 동시 사망 후 혼자 남음 | 그룹 반영 후 인원으로 판정 |
| 라운드별 공수 전환 | 경기 전체 고정 팀으로 판정하지 않음 |
| 재접속 라운드 제외 | 제외 표본을 실제 0으로 바꾸지 않음 |
| 상세 6개보다 많은 라운드 | 전체 집계의 분모를 축소하지 않음 |
| 검증 가능한 라운드 없음 | 집계 null, 관찰 문장 없음 |
| 사망한 선수가 나중에 처치 | 살아 있는 아군의 교환킬로 계산하지 않음 |
| 사건 배열 순서 변경 | 동시 사건을 포함해 같은 결과 |
| 0초 사건 / 초기 1대다수 | 초기 상태와 사건 반영 후 상태를 구분 |
| 틀린 수치·근거 없는 패배 원인 주입 | 형식 검사를 통과해도 별도 품질 검사에서 실패 |

새 품질 테스트 17개와 기존 근거·미리보기·상황 테스트를 실행했다. 이 검사는 **현재 고정된 한국어 관찰 문장**만 지원한다. 연습 제안의 유용성이나 미래 모델의 임의 문장을 판별하는 범용 의미 검증기가 아니다.

## 실행

```sh
node --test tests/unit/replay-coaching-quality.test.js tests/unit/replay-coaching-preview.test.js tests/unit/replay-coaching-evidence.test.js tests/unit/replay-context.test.js
npm run test:unit
node scripts/replay-coaching-quality.mjs --replay /absolute/path/replay.json --report /absolute/path/new-report.json
```

보고서는 기존 파일을 덮어쓰지 않는다. 검증 실패나 미지원 입력은 종료 코드 1로 처리하며, 원본 식별자가 오류 차이에 노출되지 않도록 CLI는 일반 오류만 출력한다. 입력은 서버 모의 API가 지원하는 범위(최대 64라운드, 라운드별 시간·인원 제한)에 맞아야 한다. 자동 수집·외부 호출·유료 토큰·추가 서버 저장은 없다.

## 유료 AI 연결 전 남은 기준

- 다른 맵·경기 길이·공수 전환·재접속 등을 포함한 **추가 실제 경기**로 같은 대조를 반복한다. 현재 한 경기로 전체 품질 검증을 완료했다고 판단하지 않는다.
- 현재 응답 검증기는 형식·길이·참조만 검사한다. 올바른 참조에 잘못된 수치를 붙인 문장을 런타임에서 차단하는 기능은 없다. 이번 오답 주입 테스트가 이 차이를 명시적으로 보여 준다.
- 실제 모델을 붙이면 관찰의 사실 일치, 근거 없는 원인·의도 단정, 연습 과제의 구체성·반복성 등을 따로 평가한다. 출력 형식 통과와 품질 합격은 구분한다.
- 실제 호출 전 전체 입력 토큰·출력 상한·개인/전체 비용 상한·중단 기능을 구현하고, 승인한 소액 범위에서 품질과 실제 비용을 측정한다.
