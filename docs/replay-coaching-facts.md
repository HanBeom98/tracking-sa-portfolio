# 사실 확정과 상황별 AI 선택 계약

후속 구현은 [구독자용 복기 흐름·다음 경기 목표](replay-coaching-depth.md)를 참고한다. 아래 슬롯 v3 실제 시험·요청 크기는 심화 후보 추가 전의 검증 기록이다. 심화 후보는 추가 실제 AI 호출 없이 오프라인 검증했다. 이전 ID/문장에 의한 결과 복구는 유지한다.

2026-10-26. **사실 목록·상황별 질문/연습 선택·카드 조립·저장 결과 재검증을 내부 경로로 구현했다.** 선택 v2 실제 시험에서 같은 종류의 복기 카드 두 개를 반환해 전체 결과가 거절되는 사례를 확인했다. 이를 막기 위해 모델 출력만 고정 슬롯 v3으로 변경했다. 슬롯 v3의 제한된 실제 시험 1회에서 카드 3개 생성·검증·로컬 저장·재조회가 통과했다. 운영 DB 쓰기·배포는 하지 않았다. 이전 [실제 해설 시험](replay-coaching-pilot.md)의 수치 오류와 부적절한 조언을 막기 위한 구조 변경이며 유료 가치는 아직 검증 전이다.

## 역할

| 단계 | 처리 |
| --- | --- |
| 사실 목록 | 시작 인원·사망 직전 인원·단독 상황·첫 교전·교환킬 수행/수혜·사망 이후 처치를 별도 사실로 생성 |
| AI 선택 | 중요한 사실과 그 사실에서 허용되는 질문/연습 ID를 선택. 숫자·사건·자유 문장을 작성하지 않음 |
| 서버 검사 | 실제 제공한 사실인지, 해당 사실에서 허용한 kind·질문·연습인지, 중복이 없는지 검사 |
| 카드 조립 | 서버의 제목·관찰·질문/연습·한계·근거 ID로 기존 `schemaVersion: 1` 화면 응답 생성 |
| 정산·재조회 | 선택과 완성 카드를 비용과 함께 저장. 재조회 때 같은 선택으로 다시 조립해 저장 문장과 일치하는지 확인 |

AI 요청 형식 이름은 `replay_coaching_selection_v3`이며 응답은 ID만 포함한다. strength·review·practice 슬롯을 각각 한 개씩 두고 선택하지 않는 슬롯은 null로 반환한다. 강점으로 제공할 사실이 없는 경우 strength 스키마는 null만 허용한다.

```json
{
  "schemaVersion": 3,
  "slots": {
    "strength": null,
    "review": {
      "factId": "r1_solo",
      "questionId": "q_solo_before",
      "practiceId": "p_solo_before"
    },
    "practice": null
  }
}
```

위 선택을 이전에 실패했던 **합성 1라운드 사례**에 적용하면 관찰은 서버가 고정한다.

v2에서는 배열 항목마다 종류를 고를 수 있어 서로 다른 장면을 review로 두 번 선택할 수 있었다. v3에서는 종류가 슬롯 이름으로 고정되므로 같은 종류를 두 번 나열할 수 없다. 나머지 사실에 맞지 않는 종류·질문·연습, 슬롯 사이 동일 사실 재사용, 모두 null인 응답은 계속 거절한다. 전역/종류별 enum만으로 사실별 연관 조건까지 보장하지 않으므로 서버 검사를 유지한다.

서버는 v3 슬롯을 기존 `schemaVersion: 2` 선택 배열로 정규화하고 기존 `schemaVersion: 1` 화면 카드로 조립한다. 저장된 v2 선택의 재조회·정산 형식은 유지한다. 카드 종류를 임의로 바꾸거나 잘못된 항목을 조용히 삭제해서 통과시키지 않는다.

> 1라운드 시작 후 2.0초부터 본인만 남은 1대3 상황입니다.

질문과 연습도 서버가 관리하는 항목이다. AI는 ‘혼자 남기 직전의 인원 변화’ 질문과 ‘혼자 남기 전후 기록을 구분하는 복기’를 선택할 수 있지만, 같은 사실에 생존 팀원 합류 항목을 붙일 수 없다. 이 예시는 수동 ID 선택으로 재현했으며 새 모델 응답이 아니다.

현재 AI의 역할은 **장면의 우선순위와 허용된 질문/연습 조합 선택**이다. 재학습이나 자유 문장 생성과 구분한다. 항목을 제한해 사실 오류를 줄였지만 반복되는 문장이나 약한 선택 가치가 남을 수 있어 실제 유용성은 별도로 평가한다.

## 사실·조언의 경계

- 시작 인원과 사망 직전 인원을 시점 이름과 함께 표현한다. 단독 상황의 아군 수는 본인 1명이며 시작 인원을 재사용하지 않는다.
- 교환킬 수행은 아군 사망 → 본인 후속 처치, 수혜는 본인 사망 → 팀원 후속 처치로 주체를 구분한다. 직전 사망·후속 처치·간격을 명시한다. 시각은 소수 첫째 자리로 표시한다.
- 같은 시각의 첫 사건은 동시 사건으로 표시하고 내부 선후를 정하지 않는다. 사망 이후 처치는 별도 사실이다.
- 시작 시점의 생존 팀원 합류 항목은 시작 인원에 본인 외 팀원이 있을 때만 제공한다. 사망 장면의 팀원 질문은 사망 직전에도 본인 외 팀원이 생존한 경우에만 제공한다.
- 단독 상황은 전후 인원 변화·이후 기록을 복기한다. 처음부터 혼자였으면 이전 팀원 사망을 전제하는 질문도 제외한다.
- 수행/수혜 질문을 바꾸거나 사망 없는 수행 후보에 본인 사망 항목을 붙이면 거절한다. 전역 enum에 존재해도 해당 사실에 맞지 않는 ID는 거절한다.
- 클라이언트 지시·닉네임·계정 ID·원본 JSON은 모델에 보내지 않는다. 기존 정규화는 요약의 구조·수치 일관성을 검사하며 공식 원본이라는 진위를 인증하지는 않는다.

## 보관·비용·호환성

전체 검증 집계와 최대 6개 상세 라운드에서 라운드별 우선순위를 번갈아 적용해 최대 **24개 사실**을 제공하고 생략 수를 명시한다. 질문/연습 본문은 공통 목록으로 한 번씩 보내며 원래 수치 요약을 중복 전송하지 않는다.

요청 32KiB·전체 입력 6,000토큰·출력 2,000토큰·개인/전체 비용 예약·일별 제한·중단 검사·재시도 0회는 유지한다. 전체 지시문·사실/선택 목록·출력 스키마를 카운트와 요청 해시에 포함한다. 슬롯 v3의 한 표본에서 실제 입력 토큰·비용·시간을 측정했으며, 비공개 시험 기록은 저장소 밖에 보관한다. 새 요청마다 카운트하며 v2나 이전 자유 문장 계약의 측정값을 재사용하지 않는다.

결과는 `{providerResponseId, response, selection}`으로 기존 종료 기록에 함께 저장한다. 결과당 3,072바이트·사용자 문서 JSON 700,000바이트·현재/이전 2개 이용 기간의 최대 150개 성공 결과/210개 기록을 유지한다. 별도 문서·쓰기·컬렉션·TTL·예약 작업은 없다.

선택 정보가 없는 구형 자유 문장 결과나 조립 문장이 달라진 결과는 반환을 거절한다. 기존 비용·성공 기록을 초기화하거나 같은 요청을 다시 유료 생성하지 않는다. HTTP 모의 경로·무료 분석은 유지하며 새 내부 경로의 결과만 이 계약을 쓴다.

## 검증

| 검사 | 결과 |
| --- | --- |
| 사실 회귀 검사 | 14개: 시점별 인원·교환킬 주체/시각·동시 사건·사후 처치·생존 조건·구형/변조 결과·잘못된 조합 비용 보존 |
| 슬롯 회귀 검사 | 6개: 종류별 고정 키·null·중복 복기 실패 재현·잘못된 조합/빈 결과·기존 저장 선택 호환성 |
| 전체 단위 / Emulator | **827/827**, **61/61** |
| 실제 JSON 오프라인 대조 | 한 경기 10명·9라운드, 사실 **221개**의 수치/사건을 독립 원본 사건 쿼리와 대조 |
| 조합·크기 경계 | 질문/연습 **1,312개**, 서로 다른 사실의 카드 3개 **6,984개** 조합 검사 |
| 해당 실제 표본의 최대 크기 | 슬롯 v3 요청 13,064바이트, 최대 길이 공급자 응답 ID를 포함한 저장 결과 2,034바이트 |
| 실제 AI API | 슬롯 v3 제한된 실제 시험 1회에서 **카드 3개 생성·검증 통과**. 선택 v2의 중복 종류 실패와 구분 |

실제 시험의 세 카드는 6라운드 첫 교전, 8라운드 본인 사망 후 팀원의 후속 처치 후보, 2라운드 사망 직전 인원을 선택했다. 각 시각·주체·인원은 원본 사건 쿼리와 대조했다. 완료 결과는 같은 요청으로 다시 조회해 카운트·생성 없이 복구됨을 로컬에서 확인했다.

무료 해설과 강점·복기 카드의 근거 라운드 두 개가 같고 연습 카드만 다른 장면을 선택했다. 이 관측은 정확도나 유료 가치의 비율이 아니다. 한 경기·한 플레이어·한 응답만으로 추가 가치를 입증하지 못했으며, 조언의 구체성과 여러 독립 경기에서의 반복 검증이 남아 있다.

```text
node scripts/replay-coaching-facts-audit.mjs --replay <local.json> --report <new-report.json>
```

검증은 기존 분석기가 완전하다고 선택한 라운드의 사실을 독립 사건 쿼리와 대조한다. 한 표본으로 원본의 완전성·모델의 선택 유용성·유료 품질을 보장하지 않는다. 다음은 다른 독립 경기에서의 검증과 무료 해설 대비 추가 가치 확인이다. 운영 HTTP·구독 권한·PG·환불·개인정보 보관 안내는 별도다.

공식 OpenAI 문서: [Structured Outputs와 enum·strict JSON Schema](https://developers.openai.com/api/docs/guides/structured-outputs).
