# 테스트 전용 모의 해설 API 기반

## 현재 상태

기존 Firebase Cloud Functions의 `replayCoachingPreview` 핸들러를 추가했다. **운영 미배포·기본 비활성**이며 기존 수동 Functions 배포 대상에도 포함하지 않았다. 브라우저의 해설 미리보기는 계속 로컬에서 생성한다. 새로운 서비스·패키지·모델 키·유료 AI 호출·자동 작업을 추가하지 않았다.

이 단계는 인증·입력 검사·동시 요청/한도 처리의 로컬 검증이다. 실제 구독 권한, 모델 호출, 실제 원화/토큰 비용 산정, 운영 활성화까지 완료한 서비스가 아니다.

후속 [전체 입력·비용 상한 준비 모듈](replay-coaching-budget.md)을 별도 서버 내부 경로로 로컬 구현했다. 아래 모의 HTTP 핸들러가 실제 토큰 API나 통화 장부를 호출하도록 바꾸지는 않았다. 운영 모델 모드는 계속 거절한다.

## 요청과 처리

- JSON POST: `{ "requestId": "202610-고유한_16~64자_ID", "evidence": { ...근거_요약_v1 } }`.
- `Authorization: Bearer <Firebase ID token>`을 Firebase Admin SDK로 검증한다. 본문의 UID·구독 여부·비용 값은 받지 않는다.
- Origin이 있으면 `https://trackingsa.com`만 허용한다. CORS는 인증을 대체하지 않는다.
- 전체 본문은 UTF-8 **12,288바이트 이하**다. 입력 형식·범위 검사를 통과해야 DB에 접근한다.
- 신규 요청은 한국 시간 월(`YYYYMM`)에 맞는 ID를 사용한다. 보관 중인 알려진 요청은 지난달 번호도 중복 상태만 확인한다. 같은 ID의 다른 입력은 409로 거절한다. 사용자 한도는 달력 월과 분리된 [서버 지정 이용 기간](replay-coaching-access.md)을 따른다.
- 처리 순서: 활성화/설정 → 인증/테스트 UID → 입력 검사 → 한도 예약 → 전송 시작 상태 기록 → 로컬 모의 문장 → 응답 검증 → 사용자 횟수와 비용 분리 정산.
- 응답에는 `mode: "mock"`을 포함한다. 최초 성공은 `outcome: "completed"`와 검증된 `response`, 중복 완료는 `outcome: "already_completed"`와 사용 횟수만 반환한다. 결과 본문을 서버에 캐시하지 않으므로 중복 응답에 해설을 다시 싣지 않는다.
- 응답은 `Cache-Control: no-store`. 리플레이·요약·해설 본문·인증 토큰은 로그/DB에 저장하지 않는다.

## 입력 검사 범위

`cloud-functions/replay-coaching-input.js`가 허용한 키·고정 enum·수치만 재구성한다. 현재 지원 범위는 전체 64라운드 이하, 상세 최대 6개, 각 팀 초기 인원 1~16명, 라운드 시간 1시간 이하, 방향별 교환킬 예시 최대 2건이다. 지원 범위를 벗어나면 축약하거나 0으로 대체하지 않고 거절한다.

표본 수·제외 사유 합계·생존/사망 수·킬/교환킬 상한·시각과 5초 창·장면 ID·상세 생략 수를 검사한다. 전체 상세가 있는 경우 집계 수치와 평균 생존 시간도 대조한다. 상세가 일부라면 전체 집계가 상세 합계보다 작지 않은지 검사한다. 클라이언트의 `limitations` 문장은 버리고 서버 고정 안내로 대체한다.

이는 **요약 내부의 형식/범위/일관성 검사**다. 원본을 받지 않으므로 원본 경기와 같은 기록인지 또는 공식 파일인지 증명하지 않는다. 응답의 형식/참조 검사도 문장 진실성이나 연습 효과를 보증하지 않는다.

## 한도와 장애 처리

| 항목 | 현재 구현 |
| --- | --- |
| 권한 | 서버 환경의 테스트 UID 최대 5개만 허용. 실제 구독 연동 없음 |
| 개인 이용 한도 | 명시적 서버 테스트 기간 기준 성공 1~50회. 달력 월이 바뀌어도 초기화하지 않음 |
| 실패 시도 제한 | 계정당 이용 기간 전체 최대 70회 시도. 성공 한도 이상으로 명시해야 함 |
| 동시 요청 | 계정당 1개. 사용자 이용권 1회, 전역 생성 시도와 비용 단위를 처리 전에 함께 예약 |
| 중복 | 기간별 최대 70개, 현재와 이전 두 기간만 제한 보관. 같은 기간 기록을 버려 새 시도를 허용하지 않음 |
| 모의 비용 단위 | 서버가 정한 요청당 단위와 전체 월 단위 한도. **원화나 실제 모델 요금이 아님** |
| 확정된 모의 생성 실패 | 개인 성공 횟수는 늘리지 않음. 로컬 생성 예외는 비용 0, 반환된 문장의 검증 실패는 모의 비용 유지. 실패도 전역 시도 수에 포함 |
| 확정 저장 결과 불명 | 예약 또는 이미 확정된 차감을 유지. 자동 복구/재생성하지 않음 |
| 오래된 미확정 작업 | 60초 이후 `REQUEST_UNRESOLVED`로 보류. 월이 바뀌어도 자동 해제하지 않음. 서버 전용 함수로 명시적 취소/최대 비용 종료 가능 |

자동 복구는 하지 않는다. 사용자 횟수/비용 분리와 신뢰할 수 있는 서버용 복구 함수는 [정산·복구 문서](replay-coaching-settlement.md)에 정리했다. 복구용 HTTP API/운영 CLI와 실제 공급자 비용 판정은 미구현이며, 이번에는 운영 DB에 복구를 실행하지 않았다. `mock` 이외 모드는 무조건 비활성 처리한다.

사용량 문서는 `_replay_coaching_users/{sha256(uid)}`와 `_replay_coaching_months/{YYYYMM}`이다. 사용자 문서는 현재 이용 기간·활성 예약·이전 두 기간의 제한된 시도 기록만 보관하며 기간별 문서를 계속 쌓지 않는다. 익명·회원·사이트 관리자 모두 Firestore 클라이언트에서 이 두 컬렉션을 읽거나 쓸 수 없다. Admin SDK 서버 트랜잭션만 사용한다.

신규 성공 요청은 기본적으로 트랜잭션 3회, 문서 읽기 6회·쓰기 5회다. 충돌 시 재시도 읽기가 늘 수 있고, 한도 거절/중복도 인증과 DB 읽기를 사용할 수 있다. 운영에서 활성화하면 모의 응답에도 기존 Firebase의 호출·DB 사용량이 생긴다. 모의 모드가 보편적인 무과금 보증은 아니다. 이번 검증은 demo Emulator에서만 실행했다.

## 설정 및 배포 경계

다음 환경 값이 전부 명시되어야 모의 요청을 허용한다. 이번 작업에서 운영 환경에는 설정하지 않았다.

| 변수 | 의미 |
| --- | --- |
| `REPLAY_COACHING_MODE` | `mock`만 허용. 미설정/기타 값은 비활성 |
| `REPLAY_COACHING_TEST_UIDS` | 실제 테스트할 UID 목록. 최대 5개 |
| `REPLAY_COACHING_USER_LIMIT` | 계정별 테스트 이용 기간 성공 한도(최대 50) |
| `REPLAY_COACHING_ATTEMPT_LIMIT` | 계정별 테스트 이용 기간 시도 한도(최대 70) |
| `REPLAY_COACHING_TEST_PERIOD_ID` | 명시적 테스트 이용 기간 ID |
| `REPLAY_COACHING_TEST_PERIOD_START` | UTC ISO 시작 시각(포함) |
| `REPLAY_COACHING_TEST_PERIOD_END` | UTC ISO 종료 시각(제외). 기간 길이 28~32일 |
| `REPLAY_COACHING_GLOBAL_MONTHLY` | 전역 월 생성 시도 한도. 전송 후 종료한 실패도 포함 |
| `REPLAY_COACHING_GLOBAL_UNITS` | 전역 월 모의 비용 단위 한도 |
| `REPLAY_COACHING_UNITS_PER_REQUEST` | 요청당 예약 단위 |

테스트에서는 개인 2회·전체 3회·전체 15단위·회당 5단위를 예로 사용했다. 판매 구독 상품의 허용 횟수나 요금 정책을 확정한 값이 아니다.

브라우저와 서버의 모의 문장/응답 검증은 같은 소스를 사용한다. 빌드가 `scripts/sync-replay-coaching-modules.mjs`로 소스 두 파일을 `cloud-functions/replay-coaching-shared/*.mjs`에 복사한다. 이 두 파일은 생성물이며 직접 수정하지 않는다. Firebase predeploy는 동기화 여부를 검사하며, unit 테스트도 소스와 비교한다. `.mjs` 파일은 Firebase가 업로드하는 디렉터리 안에 있어 부모 `src/`를 런타임에 참조하지 않는다.

새 함수는 기존 `.github/workflows/functions-deploy.yml`의 명시적 배포 대상에 넣지 않았다. 이후 활성화 시에는 배포 대상·런타임 검증·설정·UID·사용량과 브라우저의 요약 전송 안내를 함께 검토해야 한다.

## 검증과 후속 단계

- 단위: 비활성/미설정, 인증·권한·본문·입력 오류의 DB 미접근, 중복·다른 입력 충돌, 동시 계정·전역 예약, 실패 복구, 저장 결과 불명, 한국 월 경계, 미확정 예약 보존, 실패 시도 상한, 생성 모듈 동기화.
- Firestore/Storage Emulator: 클라이언트 사용량 접근 금지와 실제 트랜잭션의 동시 요청/중복 처리를 기존 보안 테스트와 함께 확인.
- 실제 제공 파일의 요약 9라운드·8킬·5사망도 입력 정규화를 통과했다. 실제 운영 요청은 보내지 않았다.

화면과 모의 API의 로컬 연결은 [연결 검증 문서](replay-coaching-local.md)를 따른다. 실제 모델 연결 전에는 구독 권한·공급자 요금에 따른 최악 요청 비용·출력 토큰 상한·실패/미확정 청구와 복구 절차를 확정해야 한다.
