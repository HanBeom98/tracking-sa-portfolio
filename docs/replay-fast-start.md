# 리플레이 빠른 시작과 샘플 체험

## 기본 분석과 전력 조회

JSON 구조를 확인하면 선수 선택과 기본 분석을 바로 사용할 수 있다. 기본 분석·이벤트 재생·상세 라운드는 전력 조회 완료를 기다리지 않는다. 경기 유형 자동 확인이 실패해도 기본 분석은 유지되며, 사용자가 전력 비교 기준을 선택할 수 있다.

경기 유형과 전력 조회는 기존 넥슨 경로·동시성 3·메모리 캐시를 재사용한다. 결과가 준비되면 `#replayForecast`만 갱신하므로 재생 위치·필터·상세 보기·포커스를 다시 만들지 않는다. 경기 후 7일 초과 등 기존 전력 조회 제외 기준도 유지한다.

파일·전력 기준·초기화 변경은 전력 작업 버전을 무효화한다. 이전 작업의 진행 표시·성공·실패는 현재 화면에 적용되지 않는다. 선수 변경 시 이전 분석을 숨기고 현재 선수로 다시 분석할 수 있다. 같은 파일·전력 기준의 전력 결과는 다른 선수를 분석할 때 재사용한다.

취소된 작업은 남은 선수 조회를 새로 시작하지 않는다. 이미 시작된 HTTP 요청은 완료될 수 있으나 이후 작업이나 화면 갱신을 이어 가지 않는다. 유료 AI 호출이나 DB 쓰기는 이 흐름에 추가하지 않는다.

## 파일 없이 체험

리플레이 첫 화면의 두 버튼은 가상의 경기 데이터를 브라우저 안에서 생성한다.

- **샘플로 한 경기 체험**: 가상의 5대5·6라운드 경기에서 체험 선수를 선택한 상태로 분석 결과를 연다.
- **샘플로 여러 경기 비교**: 같은 가상 선수 ID가 있는 두 경기·12라운드를 비교한다. 전후 훈련 비교는 기존처럼 사용자가 직접 그룹을 지정한다.

샘플은 실제 경기나 사용자 기록이 아니며, 화면 안내와 결과 제목·맵 이름에서 구분한다. 실제 경기의 닉네임·파일을 배포물에 넣지 않는다. 샘플 데이터 모듈은 버튼을 누를 때만 불러오고, 넥슨 전력 조회·유료 AI·서버 저장을 실행하지 않는다. 파일 입력으로 실제 JSON을 선택하면 해당 분석의 샘플 표시가 해제된다. 한 경기와 비교 탭은 각자의 파일·결과 상태를 유지한다.

## 검증

### 초기 로딩과 지연 로딩

일반 한 경기 분석 진입에서는 비교·훈련 비교 모듈과 개발용 모의 API UI를 불러오지 않는다. 비교 탭을 마우스나 키보드로 처음 열거나 비교 샘플을 사용할 때 비교 코드를 불러온다. 비교 세션은 한 번만 만들고, 탭을 다시 열어도 파일·선수 선택·결과를 유지한다.

비교 코드 로딩 중에는 파일 선택을 잠시 비활성화하고 진행 상태를 표시한다. 복원되거나 프로그램으로 먼저 설정된 FileList도 최신 선택만 적용한다. 로딩 실패 시 새로고침 안내를 표시하며 한 경기 분석은 계속 사용할 수 있다. 페이지를 떠난 뒤 도착한 모듈은 UI를 새로 연결하지 않는다.

개발용 모의 UI의 접근 조건은 `http://127.0.0.1:4173`과 `?coaching=mock`으로 동일하다. 모의 코드가 늦게 준비되면 현재 선택·분석 결과에만 연결한다. 초기화·페이지 이탈 뒤 이전 결과를 복구하지 않는다. 무료 분석과 운영 유료 AI 활성화 설정은 바꾸지 않는다.

동일한 로컬 첫 진입에서 자체 JS 응답은 47개·321,536바이트에서 40개·286,467바이트로 줄었다. 외부 SDK/API를 차단한 압축 전 본문 측정이며 실제 전송량·PageSpeed·실사용자 속도 측정은 아니다. 새 지연 로딩 검증은 기본 CI에 포함한다.

### 기본 분석·샘플 회귀 검증

- 지연된 유형/전력 응답에서 선수 변경·초기화·파일 교체·수동 기준 변경을 브라우저로 검증.
- 늦은 전력 결과가 재생 DOM과 현재 위치를 유지한 채 해당 패널만 갱신하는지 검증.
- 샘플 두 경기의 참가자·라운드·이벤트·비교 집계와 재생 모델의 검증 라운드를 단위 테스트로 확인.
- 모바일·데스크톱에서 샘플 분석/비교와 실제 파일 전환, API 요청 0건을 확인.
- 지연 응답·샘플 브라우저 검증은 기본 `test:e2e:ci`에도 포함한다. 테스트의 외부 서비스는 차단하고 합성 응답만 사용한다.

결제 설정·실제 판매·운영 AI 활성화는 이 변경의 범위에 포함하지 않는다.
