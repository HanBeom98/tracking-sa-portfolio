# 배포 전 코드 점검과 리팩토링 체크리스트

점검일: 2026-10-25. 리플레이 상황 분석 1단계가 반영된 작업 파일을 점검한 뒤, 사용자 승인에 따라 R01~R06을 수정했다. 커밋·푸시·배포는 하지 않았다. 아래 상세 근거와 줄 번호는 최초 점검 당시의 코드 기준이며 현재 진행 상태는 체크리스트와 마지막 검증 기록을 따른다.

## 결론

현재 기능을 유지하면서 정리할 부분이 있다. 우선순위는 **문자열 출력 보강 → 확실한 미사용 코드·의존성 정리 → 작은 중복 제거 → 큰 모듈 분리**다. 파일이 길거나 export의 외부 호출이 없다는 이유만으로 삭제하면 안 된다.

기존 검사는 모두 통과하지만, 현재 검사에 포함되지 않은 HTML 출력 문제를 로컬 브라우저에서 재현했다. 미사용 코드 정리보다 이 부분을 먼저 처리하는 것을 권장한다. 공개 페이지에 등록되는 리그 컴포넌트와 큰 모듈의 분리는 기능을 유지하면서 진행할 후속 개선이다.

## 확인 근거와 수정 시 주의점

### R01: 닉네임을 HTML로 해석하는 출력

- `src/domains/stats/sudden-attack/ui/utils/ui-helpers.js:157`: 최근 검색의 `data-name`과 버튼 내용에 이름을 직접 삽입한다.
- 같은 파일 `179`행 이후: 즐겨찾기의 이름·속성·접근성 레이블에 직접 삽입한다.
- `src/domains/stats/sudden-attack/ui/components/player-card.js:258`: 닉네임을 카드 HTML에 직접 삽입한다. 주변 클랜 등 외부 문자열도 함께 검토해야 한다.
- 리그 랭킹·MVP·매치 목록·관리 화면에도 비슷한 문자열 조합 패턴이 있다. 동일한 출력 경계 점검 대상으로 다루되, 모든 값이 공격 가능한 것은 아니다.

실제 생성된 로컬 사이트에서 최근 검색·즐겨찾기 저장값과 카드 모델에 무해한 `<b data-audit-...>검증용</b>` 문자열을 넣었다. 세 위치 모두 문자열 대신 실제 `<b>` 요소를 만들었다. 스크립트 실행·정보 전송은 사용하지 않았다. 이 결과는 **HTML 삽입 가능성**을 입증하며, 공식 닉네임 제한을 우회하거나 다른 사용자에게 전달하는 원격 공격 경로를 입증한 것은 아니다.

수정은 원본 이름·검색어·OUID 매칭을 바꾸지 않고 **출력 시점**에 적용한다. `textContent`/`dataset` 또는 텍스트·속성용 escaping을 사용한다. 특수문자·따옴표·한글 이름의 표시, 클릭 후 전달 값, 최근 검색·즐겨찾기 보존을 검증한다. 게시판의 `domain/html.js`에는 escaping이 이미 있으나, 전적 도메인이 게시판에 역으로 의존하도록 만들기보다 공통 도구의 위치를 정해야 한다.

### R04: 사용하지 않는 암호화 패키지

`tweetnacl`은 루트·`functions`의 의존성 선언과 잠금 파일에만 있고 현재 코드·스크립트·테스트에서 import/require하지 않는다. Discord 서명 검증은 `functions/api/discord-interaction.js`의 Web Crypto Ed25519를 사용한다.

패키지 제거 시 서명 검증 구현이나 권한 검사를 바꾸지 않는다. 의존성을 갱신하고 Discord 서명·변조·요청 본문 검사 및 API 브리지 검사를 다시 실행한다. `functions/package.json`은 ESM 설정 역할도 하므로 파일 전체를 지우지 않는다.

### R05: 중복되는 Firestore 준비 대기

`board/edit/main.js:110`과 `board/post/main.js:129`의 `waitForFirestoreReady()`는 동일한 함수다. DB 준비를 최대 5초 기다리고 50ms 간격으로 확인한다. 두 페이지의 기다림을 공통 infra/runtime helper로 옮길 수 있다. 준비 전·정상 준비·타임아웃을 검증하고 로그인 대기와 DB 대기를 혼동하지 않는다.

랭킹·하이라이트·MVP의 닉네임 클릭 이벤트도 유사하지만 짧은 UI 코드이므로 이 중복만을 위해 큰 추상화를 만들 우선순위는 낮다.

### R06: 배포 지식의 중복

- `scripts/deployment-artifacts.js`와 `src/shared/infra/builder.py` 양쪽에 루트 자산·복사 정책이 있다.
- 통합된 가이드 목록은 JS manifest와 `src/shared/infra/config.py`에 반복된다.
- sync map은 전체 복사 검사와 일부 역할이 겹치지만 명시적인 경로 호환 검사의 의도도 있다.

현재 값의 불일치나 빌드 실패가 발견된 것은 아니다. 향후 한쪽만 수정할 위험을 줄이기 위한 개선이다. Node와 Python이 함께 읽을 작은 manifest를 원본으로 두고, 기존 build/mirror/통합 가이드 검사로 검증하는 방식이 적절하다. 기존 301 경로는 삭제하지 않는다.

### R11: 검사 범위와 자동 점검의 한계

아래 항목은 최초 점검 기준이다. 이후 보강한 범위와 남은 한계는 맨 아래 R11 수정 후 검증에 기록했다.

- 미사용 구형 광고 로더에 대한 테스트는 통과해도 실제 페이지에서 그 로더를 쓰는지는 보장하지 않는다. 제거 시 현재 광고 초기화 경로의 검사만 유지한다.

## R11 수정 후 검증

기존 `check:ddd-boundary`는 같은 동작을 호출하는 호환 명령으로 유지하고, CI에서는 실제 범위를 드러내는 `check:application-browser-boundary`를 사용한다. AST로 application 파일의 지정된 window/document·대화상자·innerHTML 구문을 확인해 주석·문자열·정규식 예시를 코드와 구분하고 optional/computed member도 확인한다. 기존 계정 번역의 `globalThis["window"]` 표현 한 개는 파일·표현·이유가 일치할 때만 허용한다. 중복·추가 접근·사용하지 않는 예외는 실패한다.

새 `check:source-graph`는 배포 명세에 포함되는 브라우저 JS 원본을 HTML/공용 조각/Python 주입 script 태그와 문자로 확인되는 import·재내보내기·로더 URL에 연결한다. 누락 로컬 JS·연결 없는 파일 후보·매핑 없는 bare import·domain/application의 일부 역방향 참조·문자열 모듈 그래프의 순환을 CI에서 실패시킨다. 계산된 dynamic import는 별도 검토 경고를 표시한다. 테스트나 검사용 스크립트의 참조로 브라우저의 미연결 파일을 숨기지 않는다. 검사는 파일을 삭제하지 않는다.

이 검사로 드러난 순수 helper의 역방향 참조도 정리했다. `makeError` 구현은 board/domain/errors.js로, 경기 유형 설정/분류 구현은 stats/sudden-attack/domain/public-match-categories.js로 옮겼다. 기존 application 경로는 재내보내기를 유지한다. 오류 코드·객체 타입과 경기 분류 값·동결 설정, 기존 import의 함수/설정 identity가 유지되는 회귀 검사를 추가했다. 기존 stats 조립 파일의 infra 생성자 import 3개와 게시판 인증 호환 facade의 재내보내기 1개만 정확한 파일 쌍으로 허용한다. 포괄적인 파일/폴더 예외는 추가하지 않았다.

## 최종 푸시 범위 확인

최신 원격 main(f2321f57) 위에 리플레이 1단계와 R01~R11 변경을 통합했다. 원격과 로컬의 과거 변경은 내용이 같고 커밋 ID가 다른 복사 이력이므로 원격 이력을 보존했다. 별도로 보류한 포스타입 후원 커밋은 포함하지 않는다. 따라서 최종 배포 명세에는 support/index.html이 없으며 기본 브라우저의 후원 검사 2개도 포함하지 않는다.

통합한 소스에서 새 빌드 후 단위 659/659, Python 41/41, 로컬 Chromium 53/53, 실제 SDK·Firestore/Storage 규칙 54/54, 인증·게시판 브라우저 11/11을 통과했다. 인증 브라우저 첫 실행은 새 작업본에 로컬 Firebase SDK 설치본이 없어 ENOENT로 실패했으며 기존 SDK를 연결한 뒤 재실행해 통과했다. 제품 코드 수정은 필요하지 않았다.

원본/산출물 검사 159개, 필수 파일 256개, application 28개와 기존 예외 1개, 소스 그래프 JS 151개/연결 222개를 확인했다. 이전 단계 표의 55개 브라우저/257개 산출물과 차이는 보류된 후원 범위 제외에 따른 것이며 테스트 실패를 제거한 결과가 아니다. 이 기록은 로컬 검증이며 운영 배포나 배포 후 성능 측정을 뜻하지 않는다.


후속 변경: 위 R01~R11 기록은 당시 구성을 설명한다. 이후 Vercel 상업적 이용 경로를 정리하면서 루트 api/·vercel.json·@vercel/functions와 해당 어댑터 전용 검사를 제거/전환했다. 현재 구성과 외부 서비스 상태는 [Vercel 의존성 정리](vercel-retirement.md)를 따른다.
